# Random_Remove — technical

## The remover

`algorithms/randomness/RemoveRandom.gd` (scene `algorithms/randomness/remove_random.tscn`, a `Node3D` with the script and nothing else). Exports: `selection_mode` (`Range` · `Column` · `Row` · `All`, the registry's `selection_mode` axis), `target_column` 3, `target_row` 3, `x_min` 2 … `x_max` 5, `y_min` −1 … `y_max` 1, `z_min` 2 … `z_max` 5, `removal_speed` 1.0 (the timer's period is 0.5 / speed), `highlight_duration` 0.3 s, `local_grid` false, `multimesh_path` `LocalGrid/GridMultiMesh`; since R1b, `replay_on_reset` false.

The bound grid: `_bind_owned_grid` (at `_ready` and after `apply_grid_config`) builds the bench when `local_grid` is on and there is none, then takes the MultiMesh at `multimesh_path` — a descendant only; a missing or external target fails closed with an empty set — and owns a private copy of its resource before touching a transform or a colour. `_original` keeps every cube's transform.

The three steps. The filter, `_should_include_instance(pos)`, is one `match` over the cube's own grid coordinates (the board's, not the hall's): `All` → true; `Column` → `pos.x == target_column`; `Row` → `pos.z == target_row`; `Range` → x, y and z inside the six bounds. `find_all_instances` runs it over every cube not already removed, collects the candidates into `active_instances`, colours each cube `ELIGIBLE` (amber, 1.0 0.68 0.18) or `EXCLUDED` (grey, 0.28 0.35 0.42), and sets `initial_count` (the candidates plus the already removed — an empty set stays empty and never widens to All); at a run's start it keeps `initial_eligible`. The draw, `remove_one`: refuses while a removal is in progress, unbound, or the set is empty (and stops the timer then); draws `_rng.randi_range(0, active_instances.size() − 1)` from the private generator, highlights that cube (`HIGHLIGHT`, red), waits `highlight_duration`, and — unless a reset or a new mode has moved the generation on — scales its original transform's basis to zero, marks it removed, drops it from the candidates, counts it, logs it (`removal_log`, R1b) and emits `instance_removed`. `reset_and_find_instances` stops the timer, bumps the generation (a pending draw is cancelled), clears the removed set, the counts and the log, re-seeds the generator with `run_seed` when `replay_on_reset` is on, restores every transform and filters again. `choose_mode` parses a mode word and resets. `start_removal` / `stop_removal` run the timer (not on the bench's panel). `set_random_seed(value)` seeds and names; `new_seed()` randomizes, names and resets. `get_state()`: bound, mode, total, eligible_at_start, remaining, removed, last_selected, last_removed, busy, generation, seed, replay_on_reset, removal_log, initial_eligible. `apply_grid_config` accepts `local_grid`, `selection_mode` / `mode`, the column, row and six bounds, `removal_speed`, `highlight_duration`, and rebinds when ready.

## The bench (`#local_grid:true`)

`algorithms/randomness/remove_random_fixture.gd`, `build(remover)`: a pedestal 0.8 × 0.96 × 0.8 with a collider, a board 1.4 × 0.06 at 0.99 m with a collider, the `GridMultiMesh` — 64 cubes of 0.82 at a 0.14 m pitch, scaled onto the board at 1.086 m, coloured per instance — a permanent slot plate under each cube, column and row numerals along two edges, the status label (`<set> · seed N` / `Eligible: a   Remaining: b   Removed: c`) and the last-removed label above the board's far edge, and a RackTemplates panel scaled ×3, tilted 35° toward the visitor at 0.87 m: RANGE · ROW · COLUMN · ALL / REMOVE ONE · RESET · NEW SEED (R1b). The buttons connect the push button's `pressed` (relayed from its area's `button_pressed`) to `choose_mode`, `remove_one`, `reset_and_find_instances` and, for NEW SEED, a five-digit `set_random_seed` plus a reset. `build` turns `replay_on_reset` on and names a five-digit seed; the labels are redrawn on `state_changed`. The set is named on the status; when no eligible cube remains the second label says so and names the last removed.
