# Source, reviews and recovery

The October 20, 2026 cleanup preserves the accumulated museum work and book
writing while moving generated review copies out of version control.

## What belongs in Git

- Game code, scenes, shaders, registries, maps and sequence definitions.
- Canonical book texts, course sources, lesson implementations and authored notes.
- Reusable build tools, probes, assertions and tests.
- Authored code and prose in iteration folders, except duplicated before/after,
  test-output and snapshot trees.

Rendered review pages, receipts, copied source snapshots, ZIP bundles and export
copies belong in the sibling encyclopedia's ignored `captures/` directory.
Previously committed historical reviews remain tracked in this cleanup.

The initial verified snapshot records 24,324 pending paths. The migration
manifest selects 13,994 generated files and retains 10,330 source/authoring paths.
Some retained paths are modifications to tracked files, not new files.

## Where the files went

Archive root:
`../ada_encyclopedia/captures/repository-reviews/`

Original repository-relative paths are preserved under that root. NTFS hard
links remain at the original locations so existing review URLs, book generators
and local file references continue to work. These names share the same file
content; editing through either name changes both. They are compatibility
paths, not independent backups. No directory junctions or broader web access
were introduced.

New writers should use `tools/evidence_root.py` and `evidence_dir()` to put
generated evidence in the encyclopedia from the outset. Keep canonical sources
in their existing repository locations. The ignore section generated by
`tools/repository_cleanup.py ignore` documents the boundary for future reviews.
Inspect that policy before force-adding a file from an excluded review subtree.

## Recovery

Verified recovery snapshot:
`../ada_encyclopedia/captures/repository-cleanup/2026-10-20/`

- `working-tree.zip`: pending file contents before cleanup, read back and
  SHA-256 checked against the snapshot.
- `snapshot.json`: initial HEAD, branch, Git statuses, file sizes and hashes.
- `tracked.patch`, `staged.patch`, `git-index`: initial Git changes and index.
- `plan.json`: each archive candidate and every retained path.
- `moves.jsonl`: append-only migration records written before replacing an
  original path with its hard link.

These files are local and ignored by both repositories. They are **not an
off-device backup**. Preserve this recovery directory when moving the project
to another computer.

Run from the AdaResearch repository:

```text
python tools/repository_cleanup.py verify
python tools/test_repository_cleanup.py
```

Verification checks archive hashes, compatibility links, retained source
existence and agreement between the manifest and Git's ignore rules. It reports
retained files edited after the original backup rather than overwriting them.

To restore a missing original path from the archive:

```text
python tools/repository_cleanup.py restore
```

Restore refuses to overwrite a different current file and leaves the archive
intact. For a later edit that also changed the hard-linked archive, recover the
specific earlier file from `working-tree.zip` into a separate recovery folder,
compare it with current work, and choose the version deliberately. Do not
extract the whole ZIP over the working tree or replace the live Git index.

Migration can be resumed with `python tools/repository_cleanup.py migrate
--apply`. Every candidate must still match its recorded hash. Windows extended
paths support deeply nested review snapshots. No recursive delete, Git reset,
Git clean or stash is part of this procedure.

## Scope of validation

The cleanup verifies preservation and organization; it does not establish that
every accumulated feature or tutorial passes its runtime tests. Feature-specific
test results remain with their original reports and probes. Commit messages
must distinguish this preservation check from fresh engine or headset testing.
