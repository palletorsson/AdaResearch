# Sieve pass — math density in the curriculum spine

_Recorded 2026-05-13T09:15:00_

**Target:** the mathematical vocabulary the curriculum makes explicit vs. the mathematical vocabulary it actually uses. The question driving the pass is *is Ada teaching math, or teaching computation-via-math?* — and where that answer creates gaps.

**Background:** Palle's question at the end of yesterday's "[Play before play](/blog/2026-05-13-play-before-play)" framing: where do binary, factorials, calculus, exponents, logarithms, floor division, mean/median, modular arithmetic, etc. live in the spine? Some are present and named; some are present and unnamed; some are absent. This pass walks the spine to see which is which.

---

## 1. The claim

The published spine (`commons/maps/curriculum_spine.json`) declares an arc from F_order through synthesis. It does not declare a math curriculum *per se*. The arc claims to teach **computation as world-making**, where math is the substrate. Mathematical concepts surface when the world needs them; they are not first-class subjects.

That is a coherent framing — and the right one. Under it:
- A missing concept is **not a gap** unless the world somewhere needs it and the curriculum doesn't show it.
- *Implicit-but-downstream-of-something-explicit* is OK.
- *Implicit-and-undischarged* is a gap.

So the pass walks each F_order sequence (and the four immediately following) asking: **what math atoms does this sequence use, and which of them does it name?**

## 2. The trace

Reading each sequence's `truth` + `qfep_role` + `learning_objectives` + the artifacts placed in its `artifact_groups`:

### seq 1 · primitives

- *Truth*: "A point is position without extension. Everything is built from nothing."
- *Objectives*: Vector3 as position; point as existence-without-extension; line topology; triangle as GPU atomic unit.
- *Artifacts*: 67 unique — origin, static_point, line, triangle, righttriangle, pythagorean_triangle_angles, draw_dot, draw_triangle_faces, pyramid, cube_scene, sphere/sphere_low/mid/high, capsule_radials_rings, …
- *Math atoms used, explicit*: Vector3 (named), basic counting (in array-sized variants like `sphere_low/mid/high`), Pythagoras (`pythagorean_triangle_angles`).
- *Math atoms used, implicit*: counting and natural numbers (radial_segments, rings on capsule/torus), integer scaling (`sphere_high` vs `sphere_low` parameter choice), bilinear interpolation (every mesh shader), 3D coordinates (Vector3).

### seq 2 · transformation

- *Truth*: "Identity preserved under transformation. What stays the same when everything changes? Invariants define structure."
- *Objectives*: Translation (T_x, T_y, T_z); Rotation; Scale; **Matrix representation as 4×4 matrices**; Composition (order matters!); Invariants.
- *Artifacts*: 20 — `x/y/z_translation_cube`, `rotate_grid_cubes`, `scale_me`, `translation_cube_demo`, `spin`, `pickup_gate`, `chair_assembly_puzzle`, `clipboard`, `prism_block`, `righttriangle`, …
- *Math atoms used, explicit*: translation, rotation, scale, 4×4 matrices, composition, invariants — all in objectives.
- *Math atoms used, implicit*: **vectors as first-class atoms** — translation IS vector addition, but the sequence teaches the operation without naming the underlying object. Vectors get named only at seq 5 (forces).

### seq 3 · array_tutorial

- *Truth*: (empty)
- *Objectives*: Basic VR navigation; Single element interaction; Linear array traversal; 2D grid understanding; Pattern recognition.
- *Artifacts*: 19 — `grid_2d_4x4`, `grid_3d_4x4x4`, `column_3_z`, `xyz_coordinates`, `pattern_tile_4x4`, `pattern_tile_brick`, `pattern_tile_herringbone`, `pattern_tile_mirror`, `pulsar_compact`, `gridagent`, `tiling_demo`, …
- *Math atoms used, explicit*: arrays, 2D grids, patterns — but the *mechanism* is hidden.
- *Math atoms used, implicit and undischarged*:
  - **Binary**: a 4×4 grid uses 2-bit row+col addressing. Nothing names this.
  - **Floor division**: `index // width = row, index % width = col` is what makes arrays usable. Implicit in every pattern artifact.
  - **Modular arithmetic**: every tile pattern (brick offset, herringbone, mirror) is modular. The wallpaper groups at fractals depend on this. Never named here.
  - **Indexing as function** (`a[i]` is a function from integer to value).

### seq 4 · color

- *Truth*: "Color is perception, not physics. RGB is a lie we agree on."
- *Objectives*: RGB space; HSV space; mixing (additive vs subtractive); perception theory; digital materiality; gradients (interpolation).
- *Artifacts*: 23 — `colorballs`, `rainbow`, `rainbow_hallway`, `SpectrumVisualizer`, `gridcolorizer`, `visual_color_mixing`, `albers_wall_gallery`, …
- *Math atoms used, explicit*: RGB tuples, HSV decomposition, gradients (linear interpolation between two colours).
- *Math atoms used, implicit and undischarged*:
  - **Functions from continuous input to continuous output** — RGB(t), gradient(t), hue(λ). This is the curriculum's first encounter with functions-as-mappings and *it is not named as such*. Color is structurally where "function" first lives, and naming it would set up wavefunctions, forces, and randomness as already-familiar.
  - **Mean / median**: any colour mix is a weighted average. The Albers gallery (`albers_wall_gallery`) IS a meditation on perceptual midpoints. Never named.
  - **Inverse / non-linear mappings**: gamma correction, HSV ↔ RGB, etc.

### seq 5 · forces

- *Objectives*: Coordinate systems; Vector components; Magnitude (√(x²+y²+z²)); Unit vectors; **Addition and subtraction**; **Dot product (a·b = |a||b|cos θ)**; etc. (16 objectives total — by far the densest.)
- *Math atoms used, explicit*: vectors (finally named), dot product, magnitude, F = ma.
- *Math atoms used, implicit*:
  - **Derivative**: F = m·a where a = dv/dt = d²x/dt². The whole sequence is the implicit introduction to calculus, but the word "derivative" doesn't appear.
  - **Acceleration as instantaneous rate of change**: the truth field says *"Acceleration is the only thing you feel"* — beautiful and load-bearing, but the *concept of an instantaneous rate of change* is not named.

### seq 6 · wavefunctions

- *Objectives*: Rotation creates oscillation (unit circle → sine); amplitude/frequency/phase; **Fourier synthesis**; interference, resonance; beat frequencies; periodic-to-chaotic.
- *Math atoms used, explicit*: sine, Fourier (named), interference.
- *Math atoms used, implicit and undischarged*:
  - **Exponents**: any rotation in the complex plane is `e^{iθ}`. Sine and cosine are `Re(e^{iθ})` and `Im(e^{iθ})`. The unit circle → sine framing *begs* for the exponential framing and doesn't get it.
  - **Integral**: Fourier synthesis IS integration. "Any signal is a sum of sines" is a Riemann sum that becomes an integral in the limit. Unnamed.
  - **Calculus (continued)**: derivative again (sin' = cos), and the ODE that sine solves (`y'' = -y`).

### seq 7 · randomness

- *Objectives*: Entropy as possibility space; PRNG vs TRNG; distributions; random walk; emergence.
- *Math atoms used, explicit*: entropy (named), distributions (named), PRNG/TRNG.
- *Math atoms used, implicit and undischarged*:
  - **Logarithms**: Shannon entropy is `H = -Σ p log p`. The objectives say "entropy as possibility space" but never write the formula.
  - **Expected value / integral over a distribution**: the natural close of the calculus arc started at forces.
  - **Combinatorics & factorials**: random permutations, "shuffling", `n!`. Unnamed.

### seq 10 · fractals

- *Objectives*: self-similarity; fractal dimension `D = log(N)/log(S)`; recursion; edge of chaos; natural fractals.
- *Math atoms used, explicit*: logarithms (finally — in the dimension formula); recursion; self-similarity.
- *Math atoms used, implicit*: exponents (`s = base · ratio^n` for every recursive step). Logarithm appears in the *formula* but its conceptual introduction lives here rather than at randomness (where Shannon would have introduced it first).

## 3. Per-sequence reading — does what's named carry what's used?

| seq | named math | used-and-unnamed | verdict |
|---|---|---|---|
| 1 primitives | Vector3, Pythagoras | counting, integer scaling | ✓ adequate |
| 2 transformation | translation/rotation/scale ops, 4×4 matrices | **vectors as atoms** | ⚠ vectors not named |
| 3 array_tutorial | "arrays", "patterns" | **binary, floor division, modular arithmetic** | ✗ three core atoms unnamed |
| 4 color | RGB, HSV, gradients (linear interp) | **functions, mean/median, inverse mappings** | ⚠ functions unnamed — biggest miss |
| 5 forces | vectors, dot product, magnitude, F=ma | **derivative, instantaneous rate of change** | ⚠ calculus implicit |
| 6 wavefunctions | sine, Fourier | **exponents, integrals** | ⚠ analytic backbone unnamed |
| 7 randomness | entropy, distributions, PRNG | **logarithms, factorials, expected value** | ⚠ closing analytic atoms unnamed |
| 10 fractals | logarithms (in formula), recursion | exponents (still) | ✓ but late |

The pattern: the spine has **a calculus shadow** running from `forces` through `randomness` (4 sequences in a row) that uses derivative, integral, exponent, and logarithm without ever naming them as such. And it has **an arithmetic shadow** at `array_tutorial` that uses binary, floor division, and modular arithmetic without naming them either.

## 4. Cross-sequence transitions

- **transformation → array_tutorial**: the player has just learned vector-like operations (translation = vector addition, rotation = matrix multiplication) but the words *vector* and *matrix multiplication* haven't landed. Then array_tutorial moves to indexed structures without bridging to "an array is a function from index to value." A small naming pass here would set up everything later.
- **color → forces**: this is the cleanest transition with the deepest missed move. Color introduces *interpolation*, which is the first time the curriculum encounters a function. If color named "functions" out loud, forces would feel like "vector-valued functions of position" — a continuation, not an introduction.
- **forces → wavefunctions → randomness**: these three sequences share a calculus substrate. None acknowledge it. A small surfacing — even one sentence each — would let the player notice that the same idea (change accumulated over time) is doing the work everywhere.
- **randomness → noise → CA → fractals**: by fractals, logarithms are needed for the dimension formula. They've already been used (silently) in entropy. Naming them at randomness would carry forward; naming them at fractals first is too late.

## 5. The three-question sieve at the curriculum level

### Does naming the math atoms thicken the cognitive water?

Yes — three handles it adds:

- *Relational thinking across sequences*: "the same idea is doing the work here that did the work there." Without names, every sequence reads as its own island. With names, the curriculum starts to read as a connected language.
- *Bidirectionality*: the player can ask the math out loud (*"why does Fourier work?"*) instead of receiving it as black-box magic. The atoms become *quotable*.
- *Ada's project named*: the curriculum's claim is that *computation is mathematics made world*. If the mathematics is never named, the claim is hard to verify. Naming the atoms makes the claim falsifiable — and therefore real.

### What does naming foreclose?

- **The naive-engagement track.** A player who would have absorbed the math through use is now confronted with a word they could have done without. For some learners this is a wall.
- **The unified "computation" framing.** Once you name derivatives and integrals, the curriculum starts to sound like a math course with computational examples. The frame the spine declares (*computation as world-making*) wobbles.
- **Sequences becoming hostage to their math atoms.** If `array_tutorial` opens with "today: binary," then any redesign of array_tutorial has to keep binary at its head.

These foreclosures are real but small if the naming is *light* — one sentence in `truth`, one bullet in `learning_objectives`. The curriculum doesn't have to *teach* logarithms at randomness; it has to **name** them so the player can see the same thing return at fractals.

### What lives in the dark spot?

What naming can't reach:

- *The felt quality of an integral happening.* The sound of a Fourier synthesis, the weight of acceleration in your arm during the orb burst — those live in the body during VR. Naming surfaces the concept but not the felt thing.
- *The aesthetic that math acquires by being placed.* The way `albers_wall_gallery` argues that color-midpoints are perceptual not arithmetic — naming "mean" loses what Albers added.
- *The history.* When Newton names `dx/dt` he's also naming the move from Aristotle's *substance* to *function*. The pedagogical work of carrying that history is hard to compress into one bullet.

**Generative — fragile.** The dark spot stays habitat if naming is *minimal and stays subordinate to the world-making frame*. The moment a sequence's primary `truth` becomes a math definition, the curriculum becomes a textbook. The moment the math atom is a footnote to the truth, the dark spot is preserved.

## 6. Recommendations

### 6a. Light naming passes (small, immediate)

Add one bullet each to the indicated sequences' `learning_objectives`:

| seq | add to objectives |
|---|---|
| 1 primitives | (already adequate) |
| 2 transformation | "Vectors as atoms: every translation is a vector addition; every rotation is a vector-to-vector map." |
| 3 array_tutorial | "Binary indexing: 2 bits address a 4×4 grid. Floor division splits index into row+col. Modular arithmetic wraps." |
| 4 color | "Color as function: every gradient is a function from `t ∈ [0,1]` to a color. Color is your first continuous mapping." |
| 5 forces | "Derivative as instantaneous rate of change: velocity is the rate of position; acceleration is the rate of velocity. F = ma is calculus made physical." |
| 6 wavefunctions | "Exponential form: rotation in the complex plane is `e^{iθ}`; sine is its imaginary part. **Fourier synthesis is integration in the limit.**" |
| 7 randomness | "Shannon entropy: `H = -Σ p log p`. Logarithm measures disorder. Factorials count arrangements." |

These are one-sentence additions. Each names a math atom the sequence already uses. No new artifacts, no new maps, no curriculum reorder.

### 6b. Proposed new sequence — `change` (order 4.5, between color and forces)

The single biggest gap is the unintroduced calculus running across forces, wavefunctions, randomness. The natural fix is a new sequence at **order 4.5** with three sub-units:

1. **Change** (the derivative): velocity from position, slope of a curve, "what's changing per unit input?"
2. **Accumulation** (the integral): area under a curve, Riemann sum, "what totals up from rate?"
3. **Flow** (the vector field): direction-and-magnitude at every point, "what's happening at every place at once?"

QFEP phase: still `F_order` (it's foundational), but transitions cleanly into `oscillation` because oscillation is the closed-form solution to a differential equation. Truth-statement candidate: *"Things change. Change accumulates. Accumulation flows."*

Output of this sequence: the player has the conceptual vocabulary to *receive* forces, wavefunctions, randomness, and noise as expressions of the same underlying calculus. Each of those four sequences gets to *say* what it's doing instead of *just doing it*.

### 6c. Re-frame seq 4 (color) as "color as functions"

Already in the recommendations above as a one-bullet add, but worth flagging separately: this might be the *highest-leverage single change in the spine*. The current truth statement ("Color is perception, not physics. RGB is a lie we agree on.") is good and should stay. Add a second sentence: *"Color is also your first encounter with functions — every gradient is a mapping from input to output."* That single sentence sets up the next ten sequences.

### 6d. Defer

These are not gaps — implicit-but-downstream-of-something-explicit:

- *Counting / natural numbers* (used at primitives in sphere_low/mid/high but downstream of "primitives are atoms").
- *Pythagoras* (already named at primitives via the `pythagorean_triangle_angles` artifact).
- *Linear interpolation* (used at color, named via "gradients" — adequate).
- *Set membership / equivalence* (implicit everywhere but doesn't need a sequence; it's part of any computational vocabulary).

## 7. Load-bearing rules out of this pass

1. **Naming is light, not heavy.** One bullet in objectives per sequence; never make a math atom the primary `truth`. The curriculum remains *computation as world-making* in framing; the math is named in service of that.

2. **Every implicit math atom either gets named in its sequence or is downstream of one that was.** If it isn't, that's the gap definition for future passes.

3. **The calculus shadow gets its own sequence** — `change`, at order 4.5. Without it, four consecutive sequences (forces, wavefunctions, randomness, noise) run on an unintroduced backbone.

4. **Color as functions is the keystone.** That single re-framing aligns sequences 4–10 around a single mathematical object.

## 8. Pass result

The spine passes the sieve **under correction**. Its claim — *computation as world-making, math as substrate* — holds. But the substrate has *named exposure* in some sequences and *invisible exposure* in others, and the invisible parts create cross-sequence opacity. The fix is small (one-sentence additions to seven sequences plus one new sequence) and conservative (the framing the spine declares is preserved).
