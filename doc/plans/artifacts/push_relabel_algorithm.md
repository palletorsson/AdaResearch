# Artifact: Push-Relabel Algorithm

> preflow-push with height labels — initialize by saturating source edges, then repeatedly: push excess flow along admissible edges (height[u] > height[v]), or relabel (raise height) if no push is possible

## Context

**Category:** unknown | **Complexity:** intermediate
**Tags:** graph_theory, max_flow, push_relabel, preflow, height_labels, optimization, algorithm | **Themes:** algorithms, misc

Treat max flow as local pressure rather than global routes. The source saturates its outgoing edges, nodes accumulate excess, and relabel operations raise heights until flow can keep moving downhill. Watching active nodes flare and heights change makes the algorithm's logic bodily: congestion is stored, redirected, and discharged. It complements Edmonds-Karp by proving that local bookkeeping can solve the same global problem.

*push-relabel proves that maximum flow can be found without ever finding a complete path — local excess management is sufficient if you get the heights right*

## Design

- **Visual:** material: standard, animation: static
- **Scale:** [5.0, 1.0, 4.0] (xlarge)
- **Interaction:** to see water pile up at nodes and overflow downhill — excess flow accumulates, height labels rise, and the algorithm finds max flow by managing local floods rather than finding global paths
- **Critical Parameter:** height[source] = |V| — the source starts at maximum height, creating initial pressure; excess flow at the sink accumulates into max_flow
- **What Emerges:** the relabel operations create a "waterfall" effect where height labels propagate backward from sink to source, establishing the pressure gradient that drives flow forward
- **Triggers:** step-by-step animation with delay between operations; push operations highlighted in orange; active nodes (with excess) glow yellow; height and excess labels update per node
