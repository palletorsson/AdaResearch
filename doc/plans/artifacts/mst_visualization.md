# Artifact: mst_visualization

> Kruskal's (sort edges by weight, Union-Find to reject cycles) or Prim's (grow tree from starting vertex, always add cheapest crossing edge) — both find the minimum-weight spanning tree

## Context

**Category:** unknown | **Complexity:** beginner
**Tags:** graph_theory, minimum_spanning_tree, kruskal, prim, union_find, optimization, algorithm | **Themes:** algorithms, misc

Assemble the cheapest skeleton that still keeps the whole graph connected. Kruskal and Prim expose two greedy viewpoints on the same optimization problem: one ranks edges globally, the other grows a tree locally from a root. Accepted edges glow green, rejected cycle-forming edges glow red, and the redundant structure of the full graph becomes legible through what must be left out. The artifact makes efficiency feel like subtraction.

*the minimum spanning tree is the cheapest way to keep everyone connected — every edge in it is necessary, and removing any one disconnects the network*

## Design

- **Visual:** material: standard, animation: static
- **Scale:** [30.0, 20.0, 35.0] (xlarge)
- **Interaction:** to watch the cheapest skeleton of a network assemble edge by edge — green edges accepted, red edges rejected for creating cycles, the MST growing like a nervous system
- **Critical Parameter:** algorithm_type ("kruskal" vs "prim") — Kruskal processes edges globally by weight (greedy on edges), Prim grows locally from a root (greedy on vertices) — same result, different experience
- **What Emerges:** watching Kruskal reject edges reveals the cycle structure of the graph — every rejected edge would have closed a loop, and the set of rejected edges defines the graph's cycle space
- **Triggers:** step-by-step timer advances one edge decision per tick; Union-Find path compression tracks connected components; edge_density controls how many redundant edges exist to reject
