# Artifact: Karger's Algorithm

> randomized edge contraction — repeatedly merge endpoints of a random edge (Union-Find) until 2 super-vertices remain; the crossing edges are a cut; P(finding min-cut) >= 2/(n*(n-1))

## Context

**Category:** unknown | **Complexity:** intermediate
**Tags:** algorithm | **Themes:** algorithms, misc

Randomized algorithm for finding minimum cut in undirected graphs

*Karger's algorithm is a bet that randomness repeated enough times becomes certainty — the min-cut is always there, you just need enough attempts to stumble onto it*

## Design

- **Visual:** material: vertex_color, animation: vertex
- **Scale:** [4.0, 1.0, 4.0] (room_scale)
- **Interaction:** to watch four parallel contractions race side by side, each making different random choices, and see probability amplification turn a terrible single-run chance into near-certainty
- **Critical Parameter:** initial_vertex_count (n) — P(success per run) = 2/(n*(n-1)); for n=8 that is ~3.6% per run, but parallel repetition amplifies it exponentially
- **What Emerges:** the probability amplification chart shows observed success rate converging toward theoretical P(at least one success) = 1 - (1-p)^k as rounds accumulate
- **Triggers:** auto-demo starts new parallel rounds every _auto_interval seconds; ParameterController3D sliders for vertices, density, speed, and panel count; ImmediateMesh redrawn every frame
