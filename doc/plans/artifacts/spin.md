# Artifact: spin

> MultiMesh phases: translate → translate+rotate → translate — rotation mid-sequence changes everything

## Context

**Category:** unknown | **Complexity:** beginner
**Tags:** transformation, rotation, composition, translation, noncommutative, multimesh, transform | **Themes:** geometry, math, transforms

A MultiMesh sequence that translates, then rotates, then translates again. Because the rotation is inserted into the middle of the process, the final arrangement makes the order of operations visible instead of merely stating it. The artifact is less about spinning in place than about how composition bends a path. It teaches non-commutativity through form.

*translation then rotation is not the same as rotation then translation — order is not commutative*

## Design

- **Visual:** material: standard, animation: static
- **Scale:** [6, 1, 1] (large)
- **Interaction:** learner reads the full MultiMesh array as a story: straight, then spinning, then straight again
- **Critical Parameter:** z_rotation_degrees — the per-step rotation angle during phase 2; controls how tight the spiral
- **What Emerges:** the non-commutativity of transformation composition — the order of translate and rotate matters
- **Triggers:** nothing at runtime — baked into MultiMesh transforms at ready(); regenerate flag rebuilds
