## Where to save a response

For the current packages, use `2026-09-18/<sequence>/01-review.md`. The date identifies the package batch, not necessarily the review date. Each sequence has a README and package.json linking the frozen inputs.

Paste the complete response without rewriting it. For another review, save `02-review.md`, `03-review.md`, and so on. Never replace an earlier review, even if the reviewer changes its mind. Plain `.txt` is fine too. You can also paste or attach the response in our conversation and name the sequence; it can be filed here for you.

If convenient, add the date received, reviewer/model if known, and whether you supplied the review text, the ZIP, or both. Do not guess missing metadata. Keep your own comments under a clearly marked Author notes section, or in a separate file.

Use a new dated batch when the source packages change. Do not treat an old package review as a review of newer manuscripts or maps.

## How we use it

Calibrate effort to each sequence's and hall's maturity. Use the current repository, artifact collection, history and appropriate runtime checks to assess the review's findings. Preserve mature work, make targeted repairs where sufficient, and concentrate development where important encounters are still missing. Recommendation counts do not set revision quotas; no change is a valid outcome. Record the evidence actually checked, the intended intervention scope and when the pass is complete.

1. Preserve the original review and identify its inputs.
2. Check located claims against that snapshot, then compare with current files.
3. Record findings in a separate DECISIONS.md: passage and purpose, evidence and limits, missing layer, recovery candidates, decision, next action, verification.
4. Check relevant secondary/decorative work and previous placements before classifying a mismatch as unnecessary prose. Classify work as restoration/promotion, artifact development/repair, placement/reveal, text revision, justified cut, metadata, or further inspection/runtime test. A source observation is not automatically a defect; an editorial preference is not automatically a correction.
5. Make a small, reviewable pass and record what changed. Keep declined suggestions and reasons visible.

Follow this order: **restore or strengthen the encounter → reconsider placement and reveal timing → revise the relation between text and artifact → only then consider cutting the text**. A strong passage may need an artifact-development task. A strong artifact may need the manuscript to notice more of what it makes possible. Cut only when the claim no longer matters to the sequence or neither the existing collection nor the intended future project supports it, and record why.

For deliberate returns, identify the changed scale, body, receiver, context, timing or question before calling them redundant. In Primitives, the author has explicitly asked to preserve the rabbit, folding past and unresolved questions. An encounter missing from the review bundle may still exist elsewhere in the project; record incomplete evidence rather than claiming absence.
