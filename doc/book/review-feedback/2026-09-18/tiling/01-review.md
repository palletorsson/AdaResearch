# Tiling — 01 Review

Source-aware editorial and reader-experience review of the **Tiling** sequence.

Basis: `tiling-book.md`, `tiling-review.md`, and the supplied ZIP snapshot on branch `palm-scanner-door-entry`, captured 2026-09-18. No repository code was executed.

This review uses two linked lenses:

1. **Structural / technical:** what the implemented encounter actually supports, what each return does in the sequence, and where source, metadata, map, and manuscript disagree.
2. **Reader experience:** where curiosity builds, where the visitor can discover something before it is named, where explanation arrives too early, and whether the better intervention belongs to the artifact rather than the prose.

Before proposing any cut, the review asks what technical, poetic, critical, or structural work the passage performs. Recurrence is not treated as redundancy when an earlier idea returns through a changed source, rule, carrier, scale, surface, body, or use.

The sequence currently reads as:

> **pattern / palette / clock → source and copies → relation between copies → environmental carrier → classification → volume → appearance conditions → wearable recipe**

A second formulation is:

> **A pattern is not one thing. It can be a stored source, a rule for returning to that source, a scale and offset, a receiver that accepts or refuses updates, a surface that gives the addresses geometry, and finally a recipe that can travel to another body.**

This is a much more precise sequence than the declared objective “A tile is a rule, not a picture.” The manuscript repeatedly shows that **source, rule and carrier are separable**, rather than collapsing all three into “the tile.”

# 2. Reader-experience lens

## Pattern Disco

### Curiosity

The opening depends on recognition:

> “Do you recognise the floor in its new colours?”

That works because this is not a new disco tutorial. It asks the visitor to notice what survives a palette change after the monochrome floor from Array Tutorial.

The instruction to hold both clocks first is useful. It makes the first comparison quiet enough to inspect.

### Discovery

The visitor can discover:

- palette changes while the binary pattern remains;
- pattern changes while palette remains;
- speed changes how quickly the rule is read;
- floor animation does not physically move the supporting body;
- sequencer and visual floor retain independent clocks;
- equal tempo does not imply equal phase.

The last point is particularly useful preparation for Change.

### Timing

The code appears after one direct palette comparison, which is reasonable.

The chapter is concise enough that no major explanation outruns the encounter.

The larger reader problem is visual: in the dated entrance and interior captures, the magenta museum grid is itself a strong repeated field surrounding the coloured floor. It competes with the intended comparison between floor arrangement and floor palette.

That should be solved spatially/materially rather than with prose such as “ignore the walls.”

### Return

This return is necessary. Array Tutorial established stored binary state and independent clocks. Color made relational appearance explicit. Pattern Disco combines them without claiming colour changed the underlying rule.

Do not cut it as recap.

## Pattern Foundry

### Curiosity

The opening is strong:

> “How many places can one small decision change?”

The first local edit answers that question immediately and bodily. A small source cell reappears many times.

The early mirror experiment also works well because an asymmetric pair makes reversal visible before the implementation is explained.

### Discovery

There are several genuinely different discoveries here:

1. **One source / many copies.**
2. **Source motif / transformation of copies are separate.**
3. **A flat and curved carrier can hold the same ordered image while presenting it differently.**
4. **A receiver can decline the next update without freezing the source.**
5. **Saving source state is different from holding receiver state.**
6. **Changing repeat size does not add cells or enlarge the receiving sheet.**
7. **Offset can change appearance and later return to the same appearance without returning to the same stored offset.**
8. **A receiver selection is a membership decision.**
9. **A surface can change which source it follows.**
10. **A room can contain two accepted moments from one evolving source.**

None of these is merely the previous point restated.

### Timing

The problem is accumulation.

After `LINK / HOLD`, the manuscript proceeds through:

- SAVE / RESTORE;
- wall receiver;
- TARGET;
- repeat size;
- SAVE with held receiver;
- UNDO LINK;
- offset;
- full-period return;
- NORTH/EAST;
- ARCHITECTURE;
- ALL FIVE;
- EAST mixed state;
- annex;
- studio ownership;
- wall hold;
- room live;
- room floor hold;
- exception granularity.

The writing is technically disciplined, but a first-time visitor has to remember too many control-state distinctions simultaneously.

This is a **dramaturgy problem**, not evidence that the ideas should be cut.

### Return

Foundry repeatedly revisits the same source because the receiver relation keeps changing. That recurrence is the content.

The critical ending about exceptions is earned because the visitor has discovered that the instrument can separate **whole receivers**, but not one repeated copy within a receiver.

## Symmetry Seventeen

### Curiosity

The interactive comparison starts well.

P1 → PM → PG creates an incremental puzzle:

- translation;
- reversal;
- reversal plus half-source slip.

The instruction:

> “Try to describe the difference before pressing HOLD.”

keeps the encounter ahead of the technical explanation.

### Discovery

The strongest critical experiment is making the source **less distinctive**.

A symmetry operation can still execute while the chosen motif makes its effect hard or impossible to see.

That teaches an important distinction:

> the selected rule names a construction; the visible image may possess more symmetry than that construction minimally imposes.

This is more sophisticated than simply memorising wallpaper-group labels.

### Timing

The transition to the cage is the risky part.

The manuscript is careful:

- cage = diagram of crystallographic restriction;
- not an empirical trial of every order;
- 17 groups = classification under stated Euclidean periodic assumptions;
- three console rules do not prove completeness.

The cage itself is much less careful. Its plate says:

> “exactly 17 wallpaper groups fall out — reach for 5 and it won't close”

which visually suggests that excluding 5-fold rotational order somehow produces the complete list of seventeen groups.

The manuscript then has to repair a claim made by the artifact.

### Return

The finite carpet versus ideal classification is an important return of the whole book’s representation method:

> the classification can be correct under its assumptions without exhausting pixel sampling, finite edges, lighting or bodily view.

Protect that paragraph.

## Ribbon Patterns 01

### Curiosity

> “The mark has acquired an inside. Can you find it?”

is a good shift from plane to volume.

The low 2D array beside the 3D volume lets the visitor see that physical thickness and data dimension are not the same thing.

### Discovery

The visitor can discover:

- a 2D source made of 3D cube bodies still has only two indices;
- a 3D volume adds a layer index;
- repeating layers use the new dimension without yet varying through it;
- SLICE removes bodies from view but not storage;
- SHIFT makes layer height enter the source lookup;
- the full volume contains a relation a single slice cannot show.

The paired turquoise frames—volume address and source address—are a good materialisation of the mapping.

### Timing

The technical storage order is dense:

`SOURCE [z][x]`  
`VOLUME [y][z][x]`  
world placement `Vector3(x,y,z)`

but this is exactly the distinction the room is built to teach. It should not be simplified merely because it requires concentration.

If learners lose it, first improve the frames/readout rather than paraphrasing it repeatedly.

### Return

The zero-value discussion is excellent:

> zero is pale body here; another interpretation could make it absence.

That returns directly to Array’s “zero means absence under this rule” and makes the ontological choice explicit.

# 3. Five high-value changes

## 3.1 Pattern Foundry — give the first visit three passes instead of one continuous state-machine tour

**Hall / instances**

`Pattern_Foundry`

Primary:
- A1 `(10,5)` `pattern_architecture`
- A2 `(7,7)` `pattern_tile_4x4`
- A3 `(7,10)` `pattern_tile_mirror`
- A8 `(6,17)` `pattern_machine_a:90:0#lesson:shared_recipe`

The later annex/studio material also depends on secondary placed systems and receiver adapters.

### Work the current passage performs

The chapter is long because the system genuinely has several independent dimensions:

- source edit;
- symmetry relation;
- receiver shape;
- receiver linkage;
- source save/restore;
- repeat scale;
- offset;
- selected receiver membership;
- source ownership;
- held state;
- architectural scale;
- whole-room differentiation.

These distinctions are worth keeping.

### Reader problem

The manuscript currently presents almost all of them as one continuous imperative path. After the first `LINK / HOLD`, the visitor must keep an increasingly complex mental state of:

- which source is current;
- which receiver is selected;
- whether it is linked or held;
- which repeat size it accepted;
- which offset it accepted;
- what SAVE contains;
- what UNDO LINK contains;
- which receiver group a target label denotes;
- and later which source owns the surface.

The room is teaching the difference between these states, but the first-visit dramaturgy can make them collapse together.

### Proposal — editorial staging, not cutting

Organise the chapter explicitly into **three passes**:

#### Pass 1 — One source, many appearances
Keep as the mandatory first path:

- DRESS THE ARCHITECTURE;
- one edit in `pattern_tile_4x4`;
- asymmetric mirror comparison;
- loom MARK;
- flat versus curve.

End that pass with the already strong idea:

> The rule returns a colour index. The palette supplies its colour. The receiving sheet supplies its shape.

#### Pass 2 — Let one receiver refuse
Begin again with a fresh question:

> **Can one surface keep an earlier answer while the source continues?**

Then introduce:

- LINK / HOLD;
- WALL;
- REPEAT SIZE;
- OFFSET;
- full-period return.

SAVE / RESTORE can sit here as a distinct comparison between **source memory** and **receiver memory**.

#### Pass 3 — Who is listening?
Use the architectural target groups and curved-room studio as the last pass:

- ARCHITECTURE / EAST / ALL FIVE;
- MIXED state;
- APPLY LIVE / HOLD / LOOM;
- ROOM / ROOM FLOOR;
- ownership and different moments.

Then the exception/granularity conclusion lands naturally.

### Artifact option

Before adding controls, test learners. If the eight loom-study buttons are visually overwhelming at first encounter, consider spatially or visually grouping them into the same three concepts:

- **SOURCE MEMORY:** MARK / SAVE / RESTORE
- **RECEIVER:** LINK / HOLD / TARGET / UNDO LINK
- **MAPPING:** REPEAT SIZE / OFFSET

No capability needs to disappear.

### Reason

This preserves the technical richness while letting curiosity rebuild three times. The problem is not “too many words”; it is that too many logically distinct state variables currently arrive under one continuous task voice.

## 3.4 Symmetry Seventeen — make the cage as careful as the manuscript

**Hall / instance**

`Symmetry_Seventeen`  
A1 `(7,5)` `wallpaper_cage:0:0`  
A8 `(20,10)` `vr_tile_editor:0:0#lesson:symmetry_compare`

### Work performed

The hall makes two separate claims:

1. the editor compares translation, reflection and glide reflection on one source;
2. the cage situates rotational orders within the crystallographic restriction and points toward the larger wallpaper-group classification.

The manuscript carefully refuses to let the cage prove more than it does.

### SOURCE discrepancy

`algorithms/symmetry/wallpaper_cage/wallpaper_cage.gd` places this text on the cage:

> “rotation is a continuous dial — every angle a symmetry  
> a periodic tiling admits only 1, 2, 3, 4, 6-fold  
> exactly 17 wallpaper groups fall out — reach for 5 and it won't close”

The source header also says:

> “From this cage falls a finite catalogue — exactly 17 wallpaper groups, the complete list...”

This compresses several mathematical results into one visual causal story.

The current manuscript is much more precise:

> “Its subject is rotation compatible with a periodic planar lattice. It is a diagram of that restriction, not an experiment that tries every arrangement until one fails.”

and:

> “The three comparisons at the console are an entrance into that subject, not a demonstration of the completeness of the list.”

### Artifact/source proposal

Change the cage text to something like:

> **PERIODIC PLANAR LATTICE**  
> compatible rotational orders: 1 · 2 · 3 · 4 · 6  
> five- and seven-fold rotations are excluded by the crystallographic restriction  
> wallpaper classification also considers translations, reflections and glide reflections

Then, separately:

> **Under the Euclidean two-direction periodic assumptions used here: 17 plane groups.**

### Curriculum proposal

Replace the declared objective:

> “The seventeen wallpaper groups, and why there are exactly seventeen”

with something closer to:

> **Situate translation, reflection and glide reflection within the seventeen wallpaper groups, and identify the assumptions under which that classification applies.**

### Reason

The manuscript has already solved this conceptual problem. The artifact and objective should catch up rather than pulling the prose back toward a false demonstration.

Without that return, Foundry has to introduce source authorship before the visitor has learned to hold those variables apart.

> source

> → receiver state  
> → receiver membership  
> → source ownership.

The solution is to give that hierarchy **reader passes**, not delete the distinctions.

## Do not cut SAVE / RESTORE and LINK / HOLD as duplicate memory systems

They deliberately preserve different things.

SAVE / RESTORE addresses shared **source recipe**.

LINK / HOLD addresses a receiver's **accepted image / relation to future updates**.

The visitor needs both to discover that “memory” is not one operation.

This is an excellent return of the book's recurrent distinction between:

It prepares Change directly.

Its best move is not defining translation and reflection. It is letting the visitor see that the source can stay fixed while the lookup changes, and then contrasting that with FLIP X genuinely rewriting the source.

# 9. Overall conclusion

Tiling is structurally stronger than its old objective list suggests.

It does **not** mainly teach that “a tile is a rule.” It progressively separates at least six things that ordinary language often collapses into “the pattern”:

1. **source values** — the finite editable motif;
2. **copy rule** — translation, reflection, glide, shifted lookup;
3. **mapping parameters** — repeat size, offset, phase;
4. **receiver relation** — live, held, saved, source ownership;
5. **carrier** — floor, wall, curve, tunnel, volume, skirt;
6. **appearance / affordance** — shading, viewpoint, cut-out, collision, body.

That separation is the sequence's main intellectual achievement.

The reader experience is strongest when the artifact gives a consequence first and the technical vocabulary arrives second:

- the asymmetric mark turns before “reflection” is named;
- the source address wraps before modulo is explained;
- equal greys are compared before numerical sameness is asserted;
- the fabric visibly opens before `discard` is shown.

The places that need work are largely where the **artifact violates that same discovery method** by printing its conclusion too early, or where a complex system asks the reader to manipulate too many state dimensions without a renewed question.

The highest-value work is therefore:

1. **stage Pattern Foundry into conceptual passes rather than cutting its capabilities;**
2. **delay semantic labels in Tutorial Pattern;**
3. **delay the “each face starts its own grid” answer in Array Patterns;**
4. **bring the Symmetry cage/objective up to the manuscript's mathematical caution;**
5. **quiet competing architectural regularity around Pattern Disco;**
6. **repair stale primary-role metadata in Ribbon 03;**
7. **include dynamically/secondarily loaded sources when the manuscript has promoted them into the main encounter.**

The reader-experience principle I would carry forward from Tiling is:

> **Let the copy surprise the source before naming the rule that related them.**

And the structural principle is:

> **When many things appear to share a pattern, keep asking which relation is actually shared: the values, the rule, the mapping, the receiver, the carrier, or only the appearance.**
