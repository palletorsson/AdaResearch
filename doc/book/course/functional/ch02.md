## 2.1 A little every frame

*[the cube in three stills a second apart, each half a metre higher than the last]*

**Delete a node**: select it, then press Delete.
If you added supplied nodes, delete those from the editor.
Keep the base room, camera and lighting.

Replace the root node's script with this example.
Code creates the cube each time you run.

**Example 2.1: a rising cube**

<!-- code: claim="cube.position.y > 0" -->
```gdscript
extends Node3D

var cube = MeshInstance3D.new()

var speed := 0.5

func _ready():
	cube.mesh = BoxMesh.new()
	cube.position = Vector3(0, 0.5, 0)
	add_child(cube)

func _process(delta):
	cube.position.y += speed * delta
```

Run the project: the cube rises.

- `cube` is declared outside the functions.
  - `_ready` creates its mesh and adds it to the scene.
  - `_process` uses the same node every frame.
- `delta` is the seconds since the last frame.
  - It has no underscore here: the code uses it.
- `*` multiplies.
- `speed * delta` is the frame's share of `speed`.
  - After one second, the cube stands 0.5 higher.
- The frame rate: how many frames Godot draws a second.
  - A fast machine draws more frames, each a shorter `delta`.
- Change `speed * delta` to `speed`: the cube shoots away.
  - It adds 0.5 every frame, not every second.
  - Restore: `speed * delta`.

Times `delta`: per second, at any frame rate.

## 2.2 Turn and grow

*[the cube in three stills, an eighth turn apart, at 0.7, 1 and 1.3 times its size]*

**Example 2.2: a cube that turns and pulses**

<!-- code: claim="clock > 0 and cube.scale.x >= 0.7 and cube.scale.x <= 1.3" claim="is_equal_approx(cube.scale.x, cube.scale.z)" claim="is_equal_approx(1.57 * 4, 6.28) and lerp(0.7, 1.3, 0) == 0.7 and lerp(0.7, 1.3, 1) == 1.3" -->
```gdscript
var cube = MeshInstance3D.new()

var clock := 0.0

func _ready():
	cube.mesh = BoxMesh.new()
	cube.position = Vector3(0, 0.5, 0)
	add_child(cube)

func _process(delta):
	clock += delta
	cube.rotate_y(1.57 * delta)
	cube.scale = Vector3(1, 1, 1) * lerp(0.7, 1.3, pingpong(clock, 1))
```

Run the project: the cube turns and pulses.

- `rotate_y()` turns a body around y, through its centre.
  - A rotation is a turn around an axis.
  - 1.57 is a quarter turn: a full turn is 6.28.
  - Times `delta`, a quarter turn each second.
- `scale`: how many times its size a body is drawn.
  - `Vector3(1, 1, 1)` is its own size.
  - A `Vector3` times a number multiplies all three.
- Make it `Vector3(2, 1, 1)`: twice as long, still turning.
  - Restore: `Vector3(1, 1, 1)`.
- `clock` adds up the seconds.
  - `0.0`, not `0`: so `clock` keeps the parts of a second.
- `lerp()` and `pingpong()` are Godot's own calls, typed bare.
  - They are supplied: you use them before they are taught.
  - `pingpong(clock, 1)` rises with `clock` to 1, then falls to 0.
  - `lerp()` turns 0 into 0.7, and 1 into 1.3.
  - So the cube swells to 1.3, then shrinks to 0.7.
- A transform is a move, a turn or a growth.

A turn and a growth are timed by `delta`, like a move.

## 2.3 If it passes the line

*[the cube in three stills under a white line: rising, touching the line, falling toward 0.5]*

**Example 2.3: a bouncing cube**

<!-- code: until="speed < 0" claim="cube.position.y > 2 and cube.position.y < 2.1" -->
```gdscript
var cube = MeshInstance3D.new()

var speed := 1.0
var top := 2.0
var low := 0.5

func _ready():
	cube.mesh = BoxMesh.new()
	cube.position = Vector3(0, 0.5, 0)
	add_child(cube)
	$Supplied.line(Vector3(-1, 2.5, 0), Vector3(1, 2.5, 0))

func _process(delta):
	cube.position.y += speed * delta
	if cube.position.y > top:
		speed = -1.0
	if cube.position.y < low:
		speed = 1.0
```

Run the project: up to 2, down to 0.5.
At y 2, the cube's upper side is at 2.5.

- `if` runs its block only when the test is true.
  - Its block is the indented lines under it.
  - Past `top`, the speed flips to -1: down.
  - Past `low`, it flips back to 1.
- A conditional is code run only on a true test.
- `cube.position.y > top` is a test: is y more than `top`?
  - A test is `true` or `false`.
- A comparison is a test of two values.
  - `>` is more than, `<` less than.
  - `==` is equal to, `!=` not equal to.
  - `=` sets a value, and `==` asks about one.
- `pingpong()` bounces a number this same way.

Every frame it moves, and two tests send it back.

## 2.4 Wait, then go back

*[the carrier in three stills: crossing, resting at x 2, crossing back toward x -2]*

Build a cube, then give it a waiting time.

**Example 2.4: the carrier that waits at each end**

<!-- code: until="waiting" claim="carrier.position.x == far and speed > 0" -->
```gdscript
var carrier = MeshInstance3D.new()

var speed := 1.0
var far := 2.0
var waiting := false
var waited := 0.0

func _ready():
	carrier.mesh = BoxMesh.new()
	carrier.position = Vector3(0, 0.5, 1.5)
	add_child(carrier)

func _process(delta):
	if waiting:
		waited += delta
		if waited > 1.5:
			waiting = false
			waited = 0.0
			speed = -speed
	else:
		carrier.position.x += speed * delta
		if carrier.position.x > far:
			carrier.position.x = far
			waiting = true
		elif carrier.position.x < -far:
			carrier.position.x = -far
			waiting = true
```

Run the project: the carrier crosses, rests, and crosses back.

- A bool is a value that is `true` or `false`.
  - `waiting` is a bool: is the carrier resting?
  - `if waiting:` asks the bool itself.
- `else` runs when the `if` at its indent failed.
- `elif` asks again when the test at its indent failed.
- Two tabs in: a block inside a block.
- Resting, it adds the seconds to `waited`.
  - After 1.5 seconds, `waited` goes back to 0.
  - Then the carrier reverses: `-speed`.
- Moving, it watches both ends.
  - At an end, it is set on the end itself.
  - So its first step back lands between the ends.

A bool, kept across frames, says moving or waiting.

## 2.5 Close enough

*[top view: the cyan walker a step from the cube; a frame later, the cube gone]*

1. Add `walker.tscn` to the root node.
   - It is the walker, a node named `Walker`.
   - W, A, S and D steer it.

**Example 2.5: collect the cube**

<!-- code: nodes=Walker:Node3D claim="taken == false" claim="$Walker.call('set', 'position', Vector3(2.5, 0, 0)) == null and call('_process', 0.0) == null and taken and cube.is_queued_for_deletion()" -->
```gdscript
var cube = MeshInstance3D.new()

var reach := 1.0
var gap := 0.0
var taken := false

func _ready():
	cube.mesh = BoxMesh.new()
	add_child(cube)
	cube.position = Vector3(3, 0.5, 0)

func _process(_delta):
	if taken == false:
		gap = (cube.position - $Walker.position).length()
		if gap < reach:
			cube.queue_free()
			taken = true
```

Run the project and walk into the cube.
The cube is gone.

- Two `Vector3`s subtract number by number: x, y, z.
  - The brackets subtract first: the cube's place, seen from the walker.
- `length()` is a `Vector3`'s distance from the origin.
  - So `gap` is the distance from walker to cube.
  - Closer than `reach`, one metre, is close enough.
- `queue_free()` takes a node out of the scene.
  - Once freed, the node can no longer be used.
  - `taken == false` keeps the code from using it again.

One position minus another, then `length()`: the distance between them.

## 2.6 Keys decide

*[the cube stopped at x 2, the right end of its run; the cyan walker at the start]*

**Example 2.6: keys push the cube**

<!-- code: claim="left == false and right == false and cube.position.x == 0" claim="Input.call('action_press', 'ui_right') == null and call('_process', 0.5) == null and right and is_equal_approx(cube.position.x, 0.75) and Input.call('action_release', 'ui_right') == null" -->
```gdscript
var cube = MeshInstance3D.new()

var push := 1.5
var left := false
var right := false

func _ready():
	cube.mesh = BoxMesh.new()
	cube.position = Vector3(0, 0.5, 0)
	add_child(cube)

func _process(delta):
	left = Input.is_action_pressed("ui_left")
	right = Input.is_action_pressed("ui_right")
	if left and cube.position.x > -2:
		cube.position.x += -push * delta
	if right and cube.position.x < 2:
		cube.position.x += push * delta
	if not (left or right):
		cube.rotate_y(push * delta)
```

Run the project, hold the Right arrow: the cube slides.

- `Input` is Godot's keyboard, mouse and controller.
- `Input.is_action_pressed()` asks: is this action's key held at this moment?
  - An action is a name for one or more keys.
  - Quotes: text kept as written, never run as code.
  - `ui_left` is the action that the Left arrow sets off.
  - `ui_right` is the action that the Right arrow sets off.
- `left` and `right` are bools, asked again every frame.
- `and` is true when both tests are true.
  - Right held, and room to the right: the cube moves.
  - At 2 it stops, key or no key.
- `or` is true when either test is true.
- `not` turns true into false, and false into true.
  - `not (left or right)` is true when neither arrow is held.
  - When it is true, the cube turns where it stands.

A held key is a test: `and`, `or`, `not` join tests.

## 2.7 Children follow

*[the room four times its size: a table two metres high, a ball on it, the small cyan walker]*

Build a room node, with a table and ball under it.

**Example 2.7: a room scaled by four**

<!-- code: claim="ball.position == Vector3(0.3, 0.75, 0)" claim="ball.global_position.is_equal_approx(Vector3(1.2, 3, -3))" -->
```gdscript
var room = Node3D.new()
var table = MeshInstance3D.new()
var ball = MeshInstance3D.new()

func _ready():
	add_child(room)
	table.mesh = BoxMesh.new()
	room.add_child(table)
	ball.mesh = SphereMesh.new()
	room.add_child(ball)
	table.position = Vector3(0, 0.25, 0)
	table.scale = Vector3(1, 0.5, 1)
	ball.position = Vector3(0.3, 0.75, 0)
	ball.scale = Vector3(0.5, 0.5, 0.5)
	room.position = Vector3(0, 0, -3)
	room.scale = Vector3(4, 4, 4)
```

Run the project: the room stands four times its size.

- `table` and `ball` are under `room` in the scene tree.
  - Parent: the node holding another in the scene tree.
  - A child is a node held by another.
  - `room` is the parent, `table` and `ball` its children.
- `room.add_child(table)` makes the table a child of the room.
- `ball` still stands at (0.3, 0.75, 0).
  - Its position counts from `room`, in `room`'s metres.
  - `room`'s metres are four times as long.
  - So the ball is four times as high, and as far right.
- Not under `room`, the walker keeps its size.
- End `_ready` with `room.rotate_y(0.78)`: table and ball turn too.
  - Restore: delete that line of code.

A child moves, turns and grows with its parent.

## 2.8 Order matters

*[top view: two prisms from one start, both turned a quarter: one at z -2, one at x 2]*

Make two prisms.
Give each the same move and turn, in different orders.

**Example 2.8: turn then move, move then turn**

<!-- code: claim="turn_first.position.distance_to(Vector3(0, 0.5, -2)) < 0.01" claim="move_first.position.distance_to(Vector3(2, 0.5, 0)) < 0.01" -->
```gdscript
var turn_first = MeshInstance3D.new()
var move_first = MeshInstance3D.new()

func _ready():
	turn_first.mesh = PrismMesh.new()
	add_child(turn_first)
	move_first.mesh = PrismMesh.new()
	add_child(move_first)
	turn_first.position = Vector3(0, 0.5, 0)
	turn_first.rotate_y(1.57)
	turn_first.translate(Vector3(2, 0, 0))
	move_first.position = Vector3(0, 0.5, 0)
	move_first.translate(Vector3(2, 0, 0))
	move_first.rotate_y(1.57)
```

Run the project: two prisms, turned alike, in two places.

- `translate()` moves a body along its own axes.
  - A body's own axes turn with it.
- `turn_first` turns first: its own x runs away from you.
  - Seen from above, a positive turn goes anticlockwise.
  - Its move of 2 along x lands at z -2.
- `move_first` moves 2 right, then turns where it stands.
- Same two transforms, two orders, two places.
- Swap the last two lines of code: `move_first` joins `turn_first`.
  - Restore: swap them back.

A turn before a move changes where the move goes.
