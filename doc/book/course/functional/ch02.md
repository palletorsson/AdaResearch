## 2.1 A little every frame

*[the cube in three stills a second apart, each half a metre higher than the last]*

Add a `MeshInstance3D` named `Cube` with a `BoxMesh`.
Set its `position` to (0, 0.5, 0) in the Inspector.

**Example 2.1: a rising cube**

<!-- code: nodes=Cube:MeshInstance3D:BoxMesh claim="$Cube.position.y > 0" -->
```gdscript
extends Node3D

var speed := 0.5

func _process(delta):
	$Cube.position.y += speed * delta
```

Each example after this one replaces all but `extends Node3D`.
Run the project: the cube rises.
`delta` is the seconds since the last frame.
It has no underscore here: the code uses it.
`*` multiplies.
Each frame adds `speed * delta`, its share of a second.
After one second, the cube stands 0.5 higher.
The frame rate: how many frames Godot draws a second.
A fast machine draws more frames, each a shorter `delta`.
Change `speed * delta` to `0.01`.
Run the project: on a faster machine, it rises faster.
Restore: `speed * delta`.

Times `delta`: per second, at any frame rate.

## 2.2 Turn and grow

*[the cube in three stills: each a quarter turn further round, at 0.7, 1 and 1.3 times its size]*

**Example 2.2: the pickup cube**

<!-- code: nodes=Cube:MeshInstance3D:BoxMesh claim="clock > 0 and $Cube.scale.x >= 0.7 and $Cube.scale.x <= 1.3" claim="is_equal_approx($Cube.scale.x, $Cube.scale.z)" -->
```gdscript
var clock := 0.0

func _process(delta):
	clock += delta
	$Cube.rotate_y(1.57 * delta)
	$Cube.scale = Vector3(1, 1, 1) * lerp(0.7, 1.3, pingpong(clock, 1))
```

Run the project: the cube turns and pulses.
`rotate_y()` turns a body around its own y axis.
A rotation is a turn around an axis.
Its number is an angle: 1.57 is a quarter turn.
Times `delta`, a quarter turn each second.
`scale`: how many times its size a body is drawn.
`Vector3(1, 1, 1)` is its own size.
A `Vector3` times a number multiplies all three.
`lerp()` and `pingpong()` are supplied, made by Godot.
`clock` adds up the seconds.
`pingpong(clock, 1)` runs 0 to 1 in a second, then back.
`lerp()` turns it into a value between 0.7 and 1.3.
So the cube swells to 1.3, then shrinks to 0.7.
A transform is a move, a turn or a growth.
Change `Vector3(1, 1, 1)` to `Vector3(2, 1, 1)`: it stretches along x.
Restore: `Vector3(1, 1, 1)`.

One scale on all three keeps a cube a cube.

## 2.3 If it passes the line

*[the cube in three stills under a white line: rising, touching the line, falling toward 0.5]*

**Example 2.3: a bouncing cube**

<!-- code: nodes=Cube:MeshInstance3D:BoxMesh until="speed < 0" claim="$Cube.position.y > 2 and $Cube.position.y < 2.1" -->
```gdscript
var speed := 1.0
var top := 2.0
var low := 0.5

func _ready():
	$Supplied.line(Vector3(-1, 2.5, 0), Vector3(1, 2.5, 0))

func _process(delta):
	$Cube.position.y += speed * delta
	if $Cube.position.y > top:
		speed = -1.0
	if $Cube.position.y < low:
		speed = 1.0
```

Run the project: up to 2, down to 0.5.
The line at 2.5 marks where the cube's top turns.
`if` runs its block only when the test is true.
Its block is the indented lines under it.
`$Cube.position.y > top` is a test: is y more than `top`?
A test is `true` or `false`.
A comparison is a test of two values.
`>` is more than, `<` less than.
`==` is equal to, `!=` not equal to.
`=` sets a value, and `==` asks about one.
A conditional is code run only on a true test.
Past `top`, the speed turns down: -1.
Past `low`, it turns up again.
`pingpong()` makes this same back-and-forth for you.

Every frame it moves, and two tests turn it back.

## 2.4 Wait, then go back

*[the carrier in three stills: crossing, resting at x 2, crossing back toward x -2]*

Add a `MeshInstance3D` named `Carrier` with a `BoxMesh`.
Set its `position` to (0, 0.5, 1.5) in the Inspector.

**Example 2.4: the carrier that waits at each end**

<!-- code: nodes=Carrier:MeshInstance3D:BoxMesh until="waiting" claim="$Carrier.position.x == far and speed > 0" -->
```gdscript
var speed := 1.0
var far := 2.0
var waiting := false
var waited := 0.0

func _process(delta):
	if waiting:
		waited += delta
		if waited > 1.5:
			waiting = false
			waited = 0.0
			speed = -speed
	else:
		$Carrier.position.x += speed * delta
		if $Carrier.position.x > far:
			$Carrier.position.x = far
			waiting = true
		elif $Carrier.position.x < -far:
			$Carrier.position.x = -far
			waiting = true
```

Run the project: the carrier crosses, rests, and crosses back.
A bool is a value that is `true` or `false`.
`waiting` is a bool: is the carrier resting?
`if waiting:` asks the bool itself.
`else` runs its block when the test before it failed.
`elif` asks again when the test before it failed.
Resting, it adds the seconds to `waited`.
Past 1.5 seconds, it moves again and turns: `-speed`.
Moving, it watches both ends.
At an end, it is set on the end itself.
So its first move back is inside again.

A bool keeps a state across frames: moving or waiting.

## 2.5 Close enough

*[top view: the cyan walker a step from the cube; a frame later, the cube gone]*

Add `walker.tscn` to the top node.
It is the walker: you steer it with WASD.

**Example 2.5: collect the cube**

<!-- code: nodes=Cube:MeshInstance3D:BoxMesh,Walker:Node3D claim="taken == false" claim="$Walker.call('set', 'position', Vector3(2.5, 0, 0)) == null and call('_process', 0.0) == null and taken and $Cube.is_queued_for_deletion()" -->
```gdscript
var reach := 1.0
var gap := 0.0
var taken := false

func _ready():
	$Cube.position = Vector3(3, 0.5, 0)

func _process(_delta):
	if taken == false:
		gap = ($Cube.position - $Walker.position).length()
		if gap < reach:
			$Cube.queue_free()
			taken = true
```

Run the project and walk into the cube.
The cube is gone.
`$Cube.position - $Walker.position` is the way from walker to cube.
The brackets subtract first.
`length()` is how long a `Vector3` is: the distance it spans.
So `gap` is the distance from walker to cube.
Closer than `reach`, one metre, is close enough.
`queue_free()` takes a node out of the scene.
After that, `$Cube` reaches nothing.
`taken == false` stops the code asking for it again.

One position minus another, then `length()`: the distance between them.

## 2.6 Keys decide

*[the cube stopped at x 2, the right end of its run; the cyan walker at the start]*

**Example 2.6: keys push the cube**

<!-- code: nodes=Cube:MeshInstance3D:BoxMesh claim="left == false and right == false and $Cube.position.x == 0" claim="Input.call('action_press', 'ui_right') == null and call('_process', 0.5) == null and right and is_equal_approx($Cube.position.x, 0.75) and Input.call('action_release', 'ui_right') == null" -->
```gdscript
var push := 1.5
var left := false
var right := false

func _process(delta):
	left = Input.is_action_pressed("ui_left")
	right = Input.is_action_pressed("ui_right")
	if left and $Cube.position.x > -2:
		$Cube.position.x += -push * delta
	if right and $Cube.position.x < 2:
		$Cube.position.x += push * delta
	if not (left or right):
		$Cube.rotate_y(push * delta)
```

Run the project, hold the Right arrow: the cube slides.
`Input` is Godot's keyboard, mouse and controller.
`Input.is_action_pressed()` asks: is this key held at this moment?
Quotes: text kept as written, never run as code.
`ui_left` is the action that the Left arrow sets off.
`ui_right` is the action that the Right arrow sets off.
`ui_accept` is the action that Space and Enter set off.
`left` and `right` are bools, asked again every frame.
`and` is true when both tests are true.
Right held, and room to the right: the cube moves.
At 2 it stops, key or no key.
`-push` is `push` the other way, to the left.
`or` is true when either test is true.
`not` turns true into false, and false into true.
`not (left or right)` is true when neither arrow is held.
The brackets ask `left or right` first.
Then the cube turns where it stands.

`and`, `or` and `not` join several tests into one.

## 2.7 Children follow

*[the room four times its size: a table two metres high, a ball on it, the small cyan walker]*

Add a `Node3D` named `Room`.
Under `Room`, add a `MeshInstance3D` named `Table` with a `BoxMesh`.
Under `Room`, add a `MeshInstance3D` named `Ball` with a `SphereMesh`.

**Example 2.7: a room scaled by four**

<!-- code: nodes=Room:Node3D,Room/Table:MeshInstance3D:BoxMesh,Room/Ball:MeshInstance3D:SphereMesh claim="$Room/Ball.position == Vector3(0.3, 0.75, 0)" claim="$Room/Ball.global_position.is_equal_approx(Vector3(1.2, 3, -3))" -->
```gdscript
func _ready():
	$Room/Table.position = Vector3(0, 0.25, 0)
	$Room/Table.scale = Vector3(1, 0.5, 1)
	$Room/Ball.position = Vector3(0.3, 0.75, 0)
	$Room/Ball.scale = Vector3(0.5, 0.5, 0.5)
	$Room.position = Vector3(0, 0, -3)
	$Room.scale = Vector3(4, 4, 4)
```

Run the project: the room stands four times its size.
`Table` and `Ball` are under `Room` in the scene tree.
Parent: the node holding another in the scene tree.
A child is held by another node, and follows it.
`Room` is the parent, `Table` and `Ball` its children.
`$Room/Table` reaches a child by a path of names.
`Ball` still stands at (0.3, 0.75, 0).
Its position counts from `Room`, in `Room`'s metres.
`Room`'s metres are four times as long.
So the ball stands four times higher, and further out.
Not under `Room`, the walker keeps its size.
End `_ready` with `$Room.rotate_y(0.78)`: table and ball turn too.
Restore: delete that line of code.

A child moves, turns and grows with its parent.

## 2.8 Order matters

*[top view: two prisms from one start, both turned a quarter: one at z -2, one at x 2]*

Add two `MeshInstance3D` nodes, `TurnFirst` and `MoveFirst`.
Give each a `PrismMesh`.

**Example 2.8: turn then move, move then turn**

<!-- code: nodes=TurnFirst:MeshInstance3D:PrismMesh,MoveFirst:MeshInstance3D:PrismMesh claim="$TurnFirst.position.distance_to(Vector3(0, 0.5, -2)) < 0.01" claim="$MoveFirst.position.distance_to(Vector3(2, 0.5, 0)) < 0.01" -->
```gdscript
func _ready():
	$TurnFirst.position = Vector3(0, 0.5, 0)
	$TurnFirst.rotate_y(1.57)
	$TurnFirst.translate(Vector3(2, 0, 0))
	$MoveFirst.position = Vector3(0, 0.5, 0)
	$MoveFirst.translate(Vector3(2, 0, 0))
	$MoveFirst.rotate_y(1.57)
```

Run the project: two prisms, turned alike, in two places.
`translate()` moves a body along its own axes.
A body's own axes turn with it.
`TurnFirst` turns first: its own x runs away from you.
Its move of 2 along x lands at z -2.
`MoveFirst` moves 2 right, then turns where it stands.
Same two transforms, two orders, two places.
Swap the last two lines of code: `MoveFirst` joins `TurnFirst`.
Restore: swap them back.

A turn before a move changes where the move goes.
