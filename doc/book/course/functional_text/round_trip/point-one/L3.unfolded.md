# Chapter 1 · Point One: give the point a body

*Unfolded from the compressed lesson L3 by a blind reader. Passages that fill a gap the compressed text does not cover start with **[guess]**.*

You already know one thing about Godot: the function `_ready()` runs once, when a scene starts. This lesson uses that one fact to do three things in order:

1. place a point,
2. make the point visible,
3. make the point solid, so that something moving can bump into it.

The lesson's main claim is that these are **three separate things**. A position is not a body, and a body you can see is not yet a body you can touch.

What you need before starting: a scene, a node, a script, and `_ready()`.

---

## 1.1 The study and its three stations

The lesson comes with a ready-made study scene. Open the study folder (`studies/point-one`, which has its own README) and open `study.tscn`.

The scene's root node is called `PointStudy`. Under it are three child nodes, named in order:

- `Position`
- `Visible`
- `Solid`

Each of these is a **station**. A station is a node with a script attached and a label. [guess] The label is a piece of text in the 3D scene that names the station, so you can tell the three apart when the scene runs.

The study also gives you some things you do not build yourself: a floor, a light, a camera, and the **feelers**. A feeler is a moving probe, driven by a script called `contact_probe.gd`. [guess] Each feeler travels across one station and either passes through what is there or is stopped by it. It is your measuring instrument: it tells you whether a station holds something that can be touched.

Run the scene. Across the three stations you should see:

| station | what you see | what the feeler does |
|---|---|---|
| Position | nothing | crosses |
| Visible | a sphere | crosses |
| Solid | a sphere | stops |

Two keys control the feelers' run: **Space** pauses, **R** restarts.

You will not change the feelers in this lesson. You change **what a feeler crosses**: the contents of the stations.

## 1.2 A position is not a body

Open `position.gd`, the script of the `Position` station. The line that matters is:

```gdscript
var point_position := Vector3(0.0, 1.12, 0.0)
```

Read it piece by piece:

- `var` makes a **variable**: a name that holds a value. Here the name is `point_position`.
- `:=` gives the variable its first value. [guess] The colon also tells Godot to fix the variable's type from that first value, so `point_position` will always hold a `Vector3`.
- `Vector3(0.0, 1.12, 0.0)` is the value. A `Vector3` is how Godot writes a **position**: where something is. It is made of three numbers. [guess] The three numbers are the x, y and z coordinates, and the middle one, y, is height. (The lesson supports this much: raising the middle number makes a sphere rise, see 1.3.)

A **point** is the place a position marks. So this line names a point 1.12 above the station's origin.

[guess] The whole script probably looks like this, with the line inside `_ready()`:

```gdscript
extends Node3D

func _ready():
	var point_position := Vector3(0.0, 1.12, 0.0)
```

**Try it.** Change `1.12` to `1.7` and run the scene again.

Nothing changes. The Position station is still empty and its feeler still crosses. The editor shows a warning: **"unused variable"**.

That warning is the whole lesson of this station. You gave the point a name and a place, but nothing in the script *uses* that place. A position on its own makes nothing exist there: nothing to see, nothing to touch. This is why the first feeler crosses the station no matter what number you put in `point_position`.

## 1.3 Add a mesh, and the point is seen

Open `visible.gd`, the script of the `Visible` station. It keeps `point_position` and adds a **mesh**: something that can be seen. The lines that carry the idea are:

```gdscript
var sphere := SphereMesh.new()
sphere.height = radius * 2.0
var marker := MeshInstance3D.new()
marker.mesh = sphere
marker.position = point_position
add_child(marker)
```

Line by line:

- `SphereMesh.new()`: `.new()` makes a new object of a class. A `SphereMesh` is a sphere's surface, the thing that gets drawn. It is stored in the variable `sphere`.
- `sphere.height = radius * 2.0`: sets the sphere's height to twice the radius. `radius` is a variable of the script; its starting value is `0.14`. [guess] The script also sets `sphere.radius = radius` (that line is not shown in the compressed lesson). In Godot a `SphereMesh` keeps its height and radius as separate settings, so the height has to be set to the diameter (radius × 2) for the sphere to stay round instead of squashed or stretched.
- `MeshInstance3D.new()`: a `MeshInstance3D` is a node that shows a mesh in the scene. A mesh by itself is only a description of a surface. A node has to carry it before it appears. It is stored in `marker`.
- `marker.mesh = sphere`: gives the marker its **surface**.
- `marker.position = point_position`: gives the marker its **place**. Here, finally, the position from 1.2 gets used.
- `add_child(marker)`: gives the marker its **parent**. It attaches the marker under the station node, so it becomes part of the running scene. A node that is never added as a child does not appear.

So two parts are made with `.new()` (the `SphereMesh` and the `MeshInstance3D`), and three lines give the marker its surface, its place and its parent.

A **body**, in this lesson's words, is a node placed in the scene. The marker is a body you can see.

[guess] A whole `visible.gd` might look like this:

```gdscript
extends Node3D

var radius := 0.14

func _ready():
	var point_position := Vector3(0.0, 1.12, 0.0)
	var sphere := SphereMesh.new()
	sphere.radius = radius
	sphere.height = radius * 2.0
	var marker := MeshInstance3D.new()
	marker.mesh = sphere
	marker.position = point_position
	add_child(marker)
```

**Try it.**

- Change `1.12` to `1.7`: the sphere **rises**. Now the number does something, because something uses it.
- Change `radius` from `0.14` to `0.3`: the sphere **grows**, and its **centre stays where it was**. The centre is set by `marker.position = point_position`, which does not involve `radius`. Its height grows too, because of the line `sphere.height = radius * 2.0`: the height is calculated from the radius, so it follows any change you make.

Now watch the feeler. **It still crosses.** A bigger sphere does not help. A mesh is something to *see*, and seeing is all it gives. To the feeler the Visible station is as empty as the Position station.

## 1.4 Add a shape, and the point is touched

Open `solid.gd`, the script of the `Solid` station. It is `visible.gd` plus the following lines:

```gdscript
var solid := StaticBody3D.new()
solid.position = point_position
var sphere_shape := SphereShape3D.new()
sphere_shape.radius = radius
var collider := CollisionShape3D.new()
collider.shape = sphere_shape
solid.add_child(collider)
add_child(solid)
```

Three new classes appear:

- `StaticBody3D`: a body that physics knows about, so other things can collide with it. [guess] "Static" means it does not move on its own; it stays where it is put. Here it is put at `point_position`, the same place as the visible marker.
- `SphereShape3D`: a **shape**, meaning something that can be touched: a sphere-shaped boundary with a `radius`. It is given the same `radius` as the visible sphere.
- `CollisionShape3D`: a node that holds a shape and gives it to a body. `collider.shape = sphere_shape` puts the boundary into it.

The parenting, from the inside out:

- the `CollisionShape3D` (`collider`) is added as a child of the `StaticBody3D` (`solid.add_child(collider)`),
- the `StaticBody3D` is added as a child of the station node (`add_child(solid)`).

[guess] The shape on its own is only a description, like the mesh in 1.3. The `CollisionShape3D` carries it, and the `StaticBody3D` is what physics treats as solid.

Run the scene. **The feeler stops** at the Solid station.

As supplied, the white sphere you see and the boundary the feeler meets are in the same place and the same size. Both are placed at `point_position`, and both take their size from the same variable `radius`. That is why they look like one thing. They are still two things, and you can pull them apart.

**Try it: a boundary bigger than the surface.** Change only the shape's radius to `0.35`, leaving the visible sphere at `0.3` (the size you gave it in 1.3):

```gdscript
sphere_shape.radius = 0.35
```

Run. The feeler now stops *before* it reaches the visible sphere, so there is a gap. Empty space resists: the feeler is stopped by something you cannot see. To see the invisible boundary, turn on **Debug → Visible Collision Shapes** in the editor menu and run again. [guess] You do not need the overlay to know the gap is there. The feeler stopping in the air already shows it. The overlay only makes the boundary visible.

**Try it the other way: a surface bigger than the boundary.** Visible radius `0.3`, shape radius `0.07`. Run. The feeler sinks into the visible sphere, passing through its surface, and only then reports "stopped" when it reaches the small boundary hidden inside.

**Seen is not touched.** The mesh decides what is seen. The shape decides what is touched. Nothing forces them to agree. You choose whether they match. [guess] After the experiments you decide what you want the station to be: set them back to the same size so that what you see is what you touch, or keep the mismatch on purpose.

**In the museum, your movement is the feeler.** There is no feeler there. What meets the gap between surface and boundary is you, moving through the space: you are stopped by air, or you walk into something that looked solid. [guess] The study supplies a feeler because nobody walks through the study scene. The feeler stands in for your movement, so you can test a station without being there yourself. You do not change the feeler. You change what it crosses.

## 1.5 Light is not a body

The museum has a switch that runs:

```gdscript
sun.visible = false
```

`sun` is the museum's light, and setting its `.visible` to `false` turns it off. When you flip the switch the **shadows go, but the shapes stay**. Turning off a light changes what you see. It does not change what is solid. Bodies and their boundaries do not depend on light.

This line is for **reading, not pasting**. `visible.gd` has no `sun`: no variable or node of that name exists in your script. If you pasted the line there it would fail. [guess] It would fail with an error that `sun` is not declared. The `sun` belongs to the museum and is supplied, like the floor, light and camera in the study.

## Summary

**Words (types) this lesson fixes:**

- *station*: node + script + label
- *point*: the place a position marks
- *position*: where; written as a `Vector3`
- *variable*: a name that holds a value
- *mesh*: what is **seen**
- *body*: a node placed in the scene
- *shape*: what is **touched**

**Code introduced:** `var` · `:=` · `Vector3` · `.new()` · `SphereMesh` · `MeshInstance3D` · `add_child()` · `StaticBody3D` · `SphereShape3D` · `CollisionShape3D`

**Supplied, not built by you:** the feeler (`contact_probe.gd`), the floor, the light, the camera, and in the museum, `sun`.

**You needed before starting:** scene · node · script · `_ready()`

**The order of the lesson, and why:** nothing → surface → boundary. Each station adds one thing, and the feeler shows what that thing does and does not do. A position alone makes nothing exist. A mesh makes something you can see, but you can pass through it. A shape makes something you can touch. Because they come one at a time, you learn that *position*, *seen* and *touched* are three separate decisions, not one object.
