# Chapter 1 · Point One: give the point a body

*Unfolded by a blind reader from the compressed lesson `L2.md` alone. Passages marked
[guess] fill a gap the compressed text does not cover; everything else is stated in, or
follows directly from, the compressed text.*

You already know one thing about Godot: a function called `_ready()` runs once, at the
moment a scene starts. This lesson uses that single moment twice. First you place a
point, and find that a point on its own cannot be seen or touched. Then you give it a
body: something that can be seen, and then, separately, something that can be touched.

What you need from the previous lesson (Point Zero): what a scene is, what a node is,
what a script is, how `func` defines a function, and that `_ready()` runs once.

## 1.1 Three stations

*Picture: three labels that each read "Point one". Above the first is empty air. Above
the second and the third is a white sphere. Pink feelers sweep past all three.*

Open the Point One study (its README is in the `studies/point-one/` folder), then open
the scene `study.tscn`.

In the scene tree you will find a node called `PointStudy`. Under it stand three
**stations**, named `Position`, `Visible` and `Solid`. A station is simply a node that
carries a script and a label. Each label says "Point one".

[guess] `PointStudy` is the root node of `study.tscn`; the text only says the stations
stand under it.

[guess] Each station's script is named after it: `Position` runs `position.gd`,
`Visible` runs `visible.gd`, `Solid` runs `solid.gd`.

Run the scene. [guess] In Godot you can run the open scene with F6, or the Run Current
Scene button at the top right of the editor.

You will see:

- at the first station, nothing;
- at the second station, a white sphere;
- at the third station, a white sphere that looks exactly like the second.

Three pink **feelers** move across the stations, one per station. The first two pass
straight through. The third one stops.

While the scene runs, **Space** pauses the sweep and **R** restarts it.

Some parts of this study are supplied for you and you do not edit them: the feelers
(driven by a script called `contact_probe.gd`), the floor, the light and the camera.

What you do edit are the three station scripts. Everything you change in this lesson
changes one thing: what a feeler can pass through, and what stops it.

## 1.2 A position, then a mesh

*Picture: empty air above the first label, a white sphere above the second; the
feelers pass through both.*

### The first station: a position and nothing else

Here is the code of `position.gd`:

```gdscript
func _ready() -> void:
    var point_position := Vector3(0.0, 1.12, 0.0)
```

That is the whole of it. [guess] A script attached to a 3D node normally begins with a
line such as `extends Node3D`; the compressed text calls the two lines above "all of
`position.gd`", so either that line is there and not counted, or the study handles it.

Line by line:

- `func _ready()` is the function you already know: it runs once when the scene starts.
- `-> void` says the function returns nothing. [guess] "Returning" means handing a value
  back to whoever called the function; `_ready()` hands nothing back, it only does work.
- `var point_position` makes a **variable**: a name for a value. The name is
  `point_position`.
- `:=` gives the variable its value. [guess] The colon in `:=` tells Godot to work out
  the variable's type from the value on the right, so `point_position` becomes a
  `Vector3` and stays one.
- `Vector3(0.0, 1.12, 0.0)` is the value: a **Vector3**, which is three numbers held
  together. [guess] The three numbers are x, y and z, and the middle one (y) is height,
  in metres. The text supports the height part: when this value is used in the next
  script, raising 1.12 to 1.7 makes the sphere rise.

Two words to keep apart:

- a **position** is *where*: the three numbers;
- a **point** is the *place* those numbers mark.

**Try it.** Change `1.12` to `1.7` and run again. Nothing appears at the first station.
The editor shows a warning: "unused variable". You made a name and gave it a value, but
nothing ever used it.

That is the lesson of the first station: **a position gives the point no body.** There
is nothing at that place, so the first feeler crosses empty air, wherever you set the
position.

### The second station: a mesh, what is seen

`visible.gd` keeps the same start and adds a **mesh**: the thing that is seen.

[guess] The full `_ready()` is the position line followed by the new lines. The
compressed text shows only the new lines, indented as if they continue inside
`_ready()`, and they use `point_position`, so the position line must come first:

```gdscript
func _ready() -> void:
    var point_position := Vector3(0.0, 1.12, 0.0)

    var radius := 0.14
    var sphere := SphereMesh.new()
    sphere.radius = radius
    sphere.height = radius * 2.0

    var marker := MeshInstance3D.new()
    marker.mesh = sphere
    marker.position = point_position
    add_child(marker)
```

What each part does:

- `var radius := 0.14` is a variable holding the sphere's radius.
- `SphereMesh.new()` makes a new sphere mesh, the shape of the surface you will see.
  `.new()` makes a fresh object of the class named in front of it. [guess] A class is a
  kind of thing Godot knows how to build, and `.new()` builds one of it.
- `sphere.radius = radius` sets the mesh's radius from the variable.
- `sphere.height = radius * 2.0` sets the mesh's height to twice the radius, the
  sphere's full diameter. [guess] A `SphereMesh` stores its height separately from its
  radius, so if the two do not match you get a stretched or squashed sphere. Writing the
  height as `radius * 2.0` keeps the sphere round whatever radius you choose.
- `MeshInstance3D.new()` makes a new node that can show a mesh. It is called `marker`.
- `marker.mesh = sphere` gives the marker its surface.
- `marker.position = point_position` gives it its place.
- `add_child(marker)` gives it a parent: the marker becomes a child of this station.
  [guess] Until a node is added as a child, it exists only in memory and is not part of
  the running scene, so it would not be drawn.

`marker` is a **body**: a node you place. Notice that **a position and a body are two
different things.** The position is only three numbers; the body is a node that stands
at them. In this script the position is finally used, so the "unused variable" warning
is gone.

**Try it.**

- Set `1.12` to `1.7`: the sphere rises.
- Set `radius` to `0.3`: the sphere grows around one centre. The centre stays at
  `point_position` and the sphere swells outward in every direction. Its height grows
  too, because the height is calculated from the radius (`radius * 2.0`), so it follows
  automatically.

However large you make it, **the second feeler still passes through.** A mesh is only
seen; it is not touched.

## 1.3 A shape, set apart

*Picture: one feeler stopped short of a small sphere; another feeler sunk into a large
one.*

`solid.gd` builds the same `marker` as `visible.gd`, and then adds a **shape**: the
thing that is touched.

[guess] Here is the full `_ready()` as I understand it: the marker code from
`visible.gd`, followed by the new lines.

```gdscript
func _ready() -> void:
    var point_position := Vector3(0.0, 1.12, 0.0)

    var radius := 0.14
    var sphere := SphereMesh.new()
    sphere.radius = radius
    sphere.height = radius * 2.0

    var marker := MeshInstance3D.new()
    marker.mesh = sphere
    marker.position = point_position
    add_child(marker)

    var solid := StaticBody3D.new()
    solid.position = point_position

    var sphere_shape := SphereShape3D.new()
    sphere_shape.radius = radius
    var collider := CollisionShape3D.new()
    collider.shape = sphere_shape

    solid.add_child(collider)
    add_child(solid)
```

Three new classes do the work:

- **`StaticBody3D`**: a body that stops things. It is called `solid`, and it is placed at
  the same `point_position` as the marker. [guess] "Static" means it does not move by
  itself; things bump into it.
- **`SphereShape3D`**: the sphere-shaped boundary that can be touched. It is called
  `sphere_shape` and gets its radius from the same `radius` variable as the mesh. It is
  invisible.
- **`CollisionShape3D`**: a node that carries a shape. It is called `collider`, and
  `collider.shape = sphere_shape` hands it the sphere shape.

They are parented like this:

```
Solid (the station node, running solid.gd)
├── marker    MeshInstance3D    what is seen
└── solid     StaticBody3D      what stops things
    └── collider   CollisionShape3D   carries sphere_shape, what is touched
```

`solid.add_child(collider)` puts the collider under the body; `add_child(solid)` puts the
body under the station.

Run it: **the third feeler stops at the shape.**

Why do the white sphere and its boundary line up exactly? Because both are built from
the same two variables. The mesh and the shape share `radius` (0.14), and the marker and
the body share `point_position`. The surface you see and the boundary that is touched
happen to coincide only because the script makes them from the same numbers.

**Try it.**

- Change only the shape's radius: `sphere_shape.radius = 0.35`. The feeler now stops
  short, in front of the white sphere, in what looks like empty air. Empty space
  resists. [guess] You can see this without any extra tools, because the gap between the
  stopped feeler and the white surface is visible.
- Set the mesh radius to `0.3` and the shape radius to `0.07`. The feeler sinks into the
  white sphere before its label says "stopped". [guess] The feeler carries a label that
  changes to "stopped" when it meets a shape.
- To see the invisible boundary itself, turn on **Debug → Visible Collision Shapes**
  (in the Debug menu at the top of the editor) and run again. [guess] It takes effect on
  the next run, and draws the shape as an outline.

When you are done, restore `0.14`. [guess] Put both radii back to 0.14, so that the shape
again takes its radius from `radius` and the sphere and boundary agree.

The point of this section: **what is seen and what is touched are set apart, and you
choose whether they agree.** In the museum there is no feeler; your own movement is what
meets them. [guess] In the study you are not walking, so the feeler stands in for your
body. You never edit the feeler; you edit what it meets.

## 1.4 Light off, body kept

*Picture: the museum after the wall switch is pressed: shadows gone, spheres dim, shapes
still in place.*

In the museum there is a switch on the wall. What it does comes down to one line:

```gdscript
sun.visible = false
```

The shadows go, the spheres turn dim, but the shapes stay. Turning off the light changes
what is seen; it does not change what is touched. It is the same split as in 1.3.

`sun` is the museum's light. `visible.gd` has no `sun` in it, so this line is for
reading, not pasting. [guess] If you pasted it into `visible.gd`, Godot would report an
error, because no variable called `sun` exists there.

The corridor's last sphere still has a label saying "Point one". You now know how to
rebuild it: a position, a mesh for what is seen, and a body with a shape for what is
touched.

## Summary

**Words (types)**

- *station*: a node with a script and a label
- *point*: the place a position marks
- *position*: where; a `Vector3`
- *variable*: a name for a value
- *mesh*: what is seen
- *body*: a node you place
- *shape*: what is touched

`-> void` · `var` · `:=` · `Vector3` · `.new()` · `SphereMesh` · `MeshInstance3D` ·
`add_child()` · `StaticBody3D` · `SphereShape3D` · `CollisionShape3D`
