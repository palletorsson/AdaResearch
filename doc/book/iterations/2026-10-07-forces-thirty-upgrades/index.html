The point gains power: thirty upgrades for Vectors & Forces

You bring the familiar point into a wing where you first describe a movement, then influence a body, and finally work with the consequences left in the room. Each apparatus makes a promise you can test. The same point can arrive precisely, miss, or leave a situation worth using next.

These are ten scene groups using eleven existing idea IDs. The bridge remains optional; no learning prerequisite or hall has been added. Spring 20–21 supplies the clearest small example of the five beats.

Interaction and evidence rules
  1. Promise → prediction → release → reveal → residue. These are design beats, not compulsory screens, dialogue or timed steps.
  2. Keep the goal and decisive contact within a readable view; subtle cases may need optional arrows, a trace or a replay. Do not assume an uncaptioned viewer can understand every force.
  3. For a small physical trial, aim for a readable 5–20 second reveal where appropriate. Setup, reflection, continuous flight and orbit studies have no universal time limit.
  4. Release means an action has consequences that continue. It does not mean disabling locomotion, grabbing, counter-thrust or emergency recovery. Let natural travel time create the pause.
  5. In the opening geometry halls, release is committing a comparison or prescribed route. Do not manufacture a physics event to satisfy the five-beat template.
  6. Preserve aftermath by default when a trial ends in a miss or jam. Separate deliberate artifact reset from player respawn, lost-object recovery and finite simulation capacity; disclose recovery and retain evidence where feasible.
  7. Residue is first an actual arrangement, remaining motion, configuration or bounded recorded trace. Dents, abrasion, torn material, fused bodies and tangled rope require separately implemented receiver models.
  8. Mathematical predictions remain conditional. A collision outside a collision-free launch model changes the conditions; it does not refute the model.
  9. Spatial spectacle and tutorial role are separate. The optional hinged bridge can be a major encounter without becoming a prerequisite for the core course.
  10. Promise and precision stay credible: show a baseline success, not a machine rigged to collapse. Test mechanisms, records and recovery; do not assert an exact gag as the learning outcome.

What keeps the lineage exact

  1. Preserve the identity/look of PointBody and the inherited cube. Extend behavior where compatible; do not claim that current independent artifacts already share one runtime instance.
  2. Declare the state handed between halls: body configuration, learned tool modes and selected trace/experiment records. Implement the transport explicitly; do not assume live nodes survive a map unload.
  3. Every visible arrow names its quantity and frame: displacement in m, velocity in m/s, acceleration in m/s², force in N. Compatible quantities may be added; their types are not interchangeable.
  4. Opening mathematical models can be prescribed geometry. Label them; compare with physical receivers only after defining the different contracts.
  5. One owner integrates each body. Never add a custom velocity/position integration on top of a Godot rigid-body solver that already advances the same state.
  6. Keep player camera orientation level and separate tracked motion from software propulsion. Physical headset comfort remains a later test, not guaranteed by desktop assertions.
  7. Give each core tutorial one rebuildable focus and print its complete changed code plus an exact reference to inherited code. Core success includes an independent changed example.
  8. Reflection asks what a rule retains, excludes or makes possible. It need not explain every museum artifact; optional apparatus can remain outside both written tracks.
  9. Do not stage numerical failure as evidence of a force. Tunnelling, unstable joints and fake deformation are not substitutes for a tested mechanical relation.
  10. Leave aftermath inspectable, with an explicit reset. Bound active bodies and reveal that capacity; a test must not demand a specific collapse.
  11. Noise, flocking, fluid pressure, cloth, robot inverse kinematics and physical quadruped locomotion remain later topics or supplied systems.
  12. The thirteen core lessons depend on earlier core knowledge. Practice provides additional attempts; extension concepts are never prerequisites for the core route. Listed idea dependencies are knowledge/behavior dependencies, not a promise of shared runtime code today.
  13. Use the dramaturgy rules for release, observation and residue. They are proposed interaction contracts; historical traces and live bodies are not silently assumed to survive a hall unload.
