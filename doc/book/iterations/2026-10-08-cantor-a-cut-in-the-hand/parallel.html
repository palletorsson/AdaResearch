Tutorial · reconstruct the operation

Cantor Set — keep the two ends

Learning elements

  • An interval recorded as a start and a length
  • Replacing each entry with two entries
  • Separate current and next arrays
  • Retained length and generation history

Take the rose point above the small bar. Pull its middle towards you, past the rose mark, and release. The large bar becomes two. Repeat: every interval loses its own middle third. Your hand makes one gesture; the rule applies it across the current row.

The small bar is one interval enlarged, not the whole row in miniature. Its apparent size stays useful for your hand while the represented length falls. NEXT beside it performs the same cut. BACK and RESET return to earlier states. HISTORY shows the saved rows; GHOST marks removals without giving them collision.

A record for one span

Vector2(0, 6) stores start = 0, length = 6 metres along a local horizontal line. These two numbers are data, not an XY position. The interval ends at start + length.

For its first cut, kept is 2. The new records are (0, 2) and (4, 2). They cover 0–2 and 4–6. We never construct a solid for 2–4. On the next cut, use each record's own start and length.

The new function reads intervals and fills a separate next array. Only when that loop finishes does advance() replace current. Appending children to the array we are still reading would mix generations. original.duplicate() preserves the starting record; another copy records each completed row in history. Vector2 entries are values, so these array copies are sufficient here.

cantor.gd

Read replace_intervals() first. The rest connects that operation to the point you already hold and gives the numbers a visible form.

extends Node3D

const PointBody = preload("point_body.gd")
const HOME := Vector3(0, 1.27, 0.45)
const VIEW_SCALE := 0.2
@export var show_history := false
var original: Array[Vector2] = [Vector2(0, 6)]
var current: Array[Vector2] = []
var history: Array = []
var rows: Node3D
var point: XRToolsPickable
var readout: Label3D
var was_held := false

func _ready() -> void:
    current = original.duplicate()
    history.append(current.duplicate())
    rows = Node3D.new()
    add_child(rows)
    point = PointBody.new()
    point.tint = Color("e99db8")
    add_child(point)
    for x in [-0.4, 0.4]:
        bar(self, Vector3(x, 1.15, 0.45), 0.4, Color("28252c"))
    bar(point, Vector3(0, -0.12, 0), 0.4, Color("e99db8"))
    readout = Label3D.new()
    readout.position = Vector3(0, 1.98, 0)
    readout.font_size = 24
    readout.pixel_size = 0.001
    add_child(readout)
    park()
    redraw()

func replace_intervals(intervals: Array[Vector2], fraction: float = 1.0 / 3.0) -> Array[Vector2]:
    assert(fraction > 0.0 and fraction < 0.5)
    var next: Array[Vector2] = []
    for interval in intervals:
        var start := interval.x
        var length := interval.y
        var kept := length * fraction
        next.append(Vector2(start, kept))
        next.append(Vector2(start + length - kept, kept))
    return next

func advance() -> void:
    if point.held() or history.size() >= 6:
        return
    current = replace_intervals(current)
    history.append(current.duplicate())
    redraw()

func kept_length(intervals: Array[Vector2]) -> float:
    var total := 0.0
    for interval in intervals:
        total += interval.y
    return total

func _physics_process(_delta: float) -> void:
    var holding: bool = point.held()
    if was_held and not holding:
        var release := to_local(point.global_position)
        if release.z - HOME.z >= 0.30:
            advance()
    if not holding:
        park()
    was_held = holding

func park() -> void:
    point.global_transform = global_transform * Transform3D(Basis.IDENTITY, HOME)

func redraw() -> void:
    for child in rows.get_children():
        rows.remove_child(child)
        child.queue_free()
    var first := 0 if show_history else history.size() - 1
    for generation in range(first, history.size()):
        for interval: Vector2 in history[generation]:
            var centre := (interval.x + interval.y / 2.0 - 3.0) * VIEW_SCALE
            var at := Vector3(centre, 1.8 - generation * 0.16, 0)
            bar(rows, at, interval.y * VIEW_SCALE, Color("28252c"))
    readout.text = "cut %d / 5 | %d pieces | %.3f m kept\nPull the middle towards you 30 cm, then release" % [history.size() - 1, current.size(), kept_length(current)]

func bar(host: Node3D, at: Vector3, width: float, colour: Color) -> void:
    var surface := MeshInstance3D.new()
    var shape := BoxMesh.new()
    shape.size = Vector3(width, 0.05, 0.06)
    surface.mesh = shape
    var finish := StandardMaterial3D.new()
    finish.albedo_color = colour
    surface.material_override = finish
    surface.position = at
    host.add_child(surface)

The transition from held to released triggers one cut. Crossing the threshold while still holding changes nothing. Return the point before releasing to cancel. to_local() measures the withdrawal in the study's frame, even if you turn the whole station. park() returns the control after release. Five cuts is our deliberate limit.

bar() reuses the box mesh we already know. VIEW_SCALE fits six represented metres into a 1.2-metre drawing. The counts and lengths use the interval data, not that display scale. These small bars have no collision: they are a drawing of intervals. The point still has its pickup shape.

The two recursive child calls in Trees and the two appends here share a branching pattern. This script uses a loop to make one complete generation per gesture. It does not call itself; the hand decides when the next generation begins.

Predict, then cut

After two releases you should have four records, each 2/3 metre long, with 8/3 metres retained in total. After five: 32 pieces, each 6/243 metre, retaining 64/81 metre. More entries, less material.

Enable show_history in the Inspector and run again. Make the same cuts. The drawing now includes the old rows, but the latest count and retained length must stay the same. At five cuts there are 63 drawn bars across the history and 32 current intervals. original is still [(0, 6)].

For an independent variation, change the call to replace_intervals(current, 0.25). Predict the two records after one cut before running: (0, 1.5) and (4.5, 1.5). This keeps the outer quarters and removes the middle half. It is a different rule from the middle-third Cantor construction. The small hand model still depicts thirds; resize its three parts before presenting your variant as a matching exhibit. A legal fraction here is greater than zero and less than one half.

The carried point file

This is the same point_body.gd as in Recursive Trees, included so the two-file example is complete. Its XR pickup and desktop hooks are existing knowledge; they are not new steps in the interval algorithm.

extends XRToolsPickable
## Point Lines' frozen point construction, made smaller for the hand model.
var tint := Color("25212a")
var desktop_pointer: WeakRef

func _init() -> void:
    freeze = true
    freeze_mode = RigidBody3D.FREEZE_MODE_KINEMATIC
    release_mode = XRToolsPickable.ReleaseMode.FROZEN
    ranged_grab_method = XRToolsPickable.RangedMethod.NONE
    collision_layer = 4
    collision_mask = 0
    var surface := MeshInstance3D.new()
    var sphere := SphereMesh.new()
    sphere.radius = 0.085
    sphere.height = 0.17
    sphere.radial_segments = 24
    sphere.rings = 12
    surface.mesh = sphere
    add_child(surface)
    var boundary := CollisionShape3D.new()
    var shape := SphereShape3D.new()
    shape.radius = 0.085
    boundary.shape = shape
    add_child(boundary)

func _ready() -> void:
    super._ready()
    var finish := StandardMaterial3D.new()
    finish.albedo_color = tint
    finish.roughness = 0.24
    get_child(0).material_override = finish

func held() -> bool:
    return is_picked_up() or (desktop_pointer != null and desktop_pointer.get_ref() != null)

func on_desktop_grab(pointer: Node) -> void:
    desktop_pointer = weakref(pointer)

func on_desktop_drop(_pointer: Node) -> void:
    desktop_pointer = null

Final · encounter and reflection

More pieces, less material

One bar is waiting. Where could it go if we let it become two?

Take the rose point above the small bar. Pull its middle towards you, past the mark, and release. The large bar gives way to two. Their outside ends reach as far as the first bar, but the middle is missing. Pull again. Look for the new gaps before counting the pieces. Each piece has lost its own middle; the first large gap has not been divided or repaired. NEXT beside your hand makes the same cut.

The little bar stays large enough to hold. It represents one interval, enlarged; it is not the whole row. The interface keeps a familiar span between your fingers while the thing it stands for becomes smaller. One movement of your hand is being repeated in places you did not touch.

The trees sent another branch into space. Here another generation leaves less behind. At the fifth cut, thirty-two pieces share less than a metre of the six metres we began with. The desk counts the latest row. Turn HISTORY on. The old bars appear above it. The whole display has become busier while the thing it is recording has become smaller in total length.

Turn HISTORY off. There is much less to look at. The kept length does not change. The earlier rows were a record we added so we could follow the operation. They were never extra members of the latest generation.

GHOST brings back pale marks where this generation cut its middles. They have no collision. The display can remember an absence without filling it with something that supports a body. Turn HISTORY on again and follow the larger absences upwards to the rows where they first appeared.

These two lines make the next pair in the bar's code:

var new_length = bar_length / 3.0
var offset = bar_length / 3.0

The new bars are placed at the old centre minus that offset and the old centre plus it. Their width is new_length. Two thirds remain, separated by the third for which we create no solid bar. Repeating the operation gives us:

pieces      = 2^n
piece length = 6 / 3^n
kept length  = 6 * (2/3)^n

The count rises as the retained length falls. Neither number tells us how much work the renderer is doing. With history visible, it draws every earlier row as well. At five cuts that means sixty-three solid bars, before we count the ghosts, the desk or the rest of the room.

The screen stops at five. Its smallest pieces still have width, height and depth. The mathematical construction asks us to continue without a last cut.1 Its limiting set has zero total length and uncountably many points. We have not displayed that limit. We have made a finite instrument for approaching its rule.

From here the gaps can look generous. Carry that impression up the ramp.

There is a broad opening under the pink beam. Walk through it. The same removal that interrupted a bar now offers a passage.

Return to the desk and press CUT twice. Smaller openings appear beside the first one. Choose one that looks wide enough, go up the ramp and try it. At this setting the gaps include three metres, one metre and a third of a metre. All are gaps. They do not all admit the same body.

The rule supplied intervals. The pagoda gave them height and depth, stacked their history above them, and made their surfaces collide with us. Here is the box shape used by its collision code:

shape.size = Vector3(width, block_height, block_thickness)

The interval's width is only one of those three decisions. Press DEPTH: the passage becomes longer or shorter while its opening stays the same width. LATEST removes the earlier levels overhead. The ground-level intervals remain; the roof was our way of arranging their past.

Try the narrow gap once more. The simulation does not collide with every fold of your clothes. It tests a proxy body. A passage can exclude that body even when the eye can travel through it. The obstruction belongs to a relation between the gap and the body we have implemented. To make a way through, we could widen the opening, change the body, or change which surfaces count as solid. Each choice makes a different world.

More cuts have made more openings, but many are too small for this visitor. Nothing in the operation promises that more detail will make more room for us. And still we want to look inside. That desire can lead us back to the rule, to ask which of its decisions might move.

At the far end of the hall, three trees stand in a row. They are one rule, three times. Each is grown by a call that makes its children and then calls itself on each of them, the self-call of the first hall, with every fork's angle and length drawn by chance; near the trunk each fork makes three, further out two. Once grown, the branches push apart level by level until they have found room. No seed is kept. The hall builds three different trees each time it is built, and none of them can be asked for again. Every desk in this sequence returns the same object when you press RESET; these trees never do, and “the same tree” stops meaning anything you could check.

The smaller Cantor drawing, the cloud and the dark sphere remain around the experiment as well. Their kinds of repetition do not have to resolve into one shape. Further on, Koch will put a detour into a line; Sierpinski will carry removal into a triangle. We have learned to lose length while multiplying pieces. What happens when the next rule makes the boundary grow instead?
