# The exception and the rewrite

One cell can depart from the surrounding colour assignment without becoming unable to support a body. Colour and collision are different parts of this implementation. The visible regularity is not a physical necessity of the floor.

An exception persists while the visitor selects another address. RULE then overwrites it. This gives the reader a specific event to examine: the exception disappears because a routine assigns another value, not because the grid cannot hold difference. Repetition has an author, a trigger and a scope.

The console also distributes unequal permissions. The visitor can edit twenty-five positions using four inks; the rule addresses the interior floor. This asymmetry is visible and changeable in source. A wider edit region, arbitrary colours or protected exceptions would require further implementation. Shared substrate makes such changes thinkable; it does not implement them for us.

Neither the address nor its hexadecimal colour exhausts the encounter. The swatch and the floor receive the same stored value under different lighting and viewing conditions. In the desktop compatibility renderer, requested and retrieved channels can also differ slightly through storage precision. That discrepancy should be measured before being given a metaphor.

The lesson retains a current value, not a history of its replacements. An undo stack or save file would be another design decision. The next room's accumulating painting makes a different decision about what a surface keeps.
