# Tutorial lineage atlas — first whole-spine edition

The author asked for a tutorial lineage tree through the project. The atlas covers all active spine sequences and halls, preserving their current walking order. Its 67 capability targets are editorial proposals, grounded in a source inventory rather than presented as tested lessons.

## Decisions

- Show one main dependency in the tree and all other prerequisites in the selected capability panel. A return can combine several earlier abilities.
- Separate build, borrow, compare and reflect. A strong reflective hall need not acquire a compulsory programming assignment.
- Give every capability an incoming ability, a thing the student can make, a transfer experiment and named supplied machinery.
- Use stable hall IDs for assignments. A new or removed map must fail coverage validation rather than silently shift a positional mapping.
- Retain current sources for every hall. Existing tutorial prose is not rewritten or accepted simply because it is indexed.
- Treat missing tutorial files as editorial decisions, not a quality ranking. Mature encounters may need only a concise making passage or an explicit reflective role.
- Keep Point One pickup, the first measurable Line, then Trace's small ordered record as the immediate construction chain.

## Specific findings

Twelve active halls lack a non-empty tutorial.md: Array; three Ribbon Patterns halls; six Shader halls; LSystems_Shape_Grammars; ISO_RhizomeBody. Some have substantial current technical and manuscript material.

Those are bridges to name, not automatic reasons to change the museum order. ML_Perception's intent explicitly makes its later position a zoom into a unit after the whole network.
