# Sweep: creative-coding curricula and their ORDER

2026-10-01, auto-research for the braid. [V] = checked against a real page in this session (URL given). [mem] = recalled from memory, not checked. [agg] = only a search engine's summary, no primary page opened.

## The short answer

- Creative-coding teaching has settled on **one intro order** for 27 years: DBN (1999), the Processing Handbook (2007), Learning Processing (2008), The Coding Train's Code! and NYU ICM 2025 all run draw, then variables, then conditionals, then loops, then functions, then objects, then arrays. Each step is named by what it makes you see (ICM: "Animation: Variables", "Interaction: Conditionals", "Repetition: Loops", "Organization: Functions").
- **The Nature of Code starts where that order ends** (it assumes "one semester" of variables, conditionals, loops, functions, objects and arrays) and begins at Randomness. Ada's spine is really both of these laid end to end. Spine 1-5 (point, transformation, array, colour, tiling) is the Form+Code / Handbook *form* order. Spine 6-11 and 13-20 is Nature of Code plus the "complex methods" half of Generative Design. Spine 22-25 (graphs, foundations crisis, QFEP, post-crisis) has **no counterpart in any creative-coding curriculum**. That ground belongs to Code Societies and critical code studies.
- The best ordering idea in the sweep: **the Processing Handbook (1st ed., 2007) prints two tables of contents** [V]. One is a *reading order* that weaves categories together (Structure 1, Shape 1, Data 1, Math 1, Control 1, Control 2, Shape 2 ...). The other lists the same chapters *by category* (Color 1-2, Control 1-2, Data 1-4, Shape 1-3 ...). A topic comes back under a number ("Shape 3: Parameters, Recursion" arrives in Part 2). That is "related to the spine but not forced by it", already built into a book. The spine is the category index and the course is the reading order. A departure shows up as a jump in the numbers.
- What creative-coding curricula mostly **lack** is Ada's DEBT layer: what an approximation owes or hides. Only three places point that way: Recreating the Past's last week (Glitch / Deformation: Rosa Menkman, the Vasulkas), Code Societies (Software as Ideology, Critical Simulation, Cybernetics of Sex), and Code as Creative Medium's interview theme "Encouraging a Point of View". Take the order and the exercise formats from creative coding. Take the debt from critical code studies.

What this shows:
- **Transform:** Ada puts it early (spine 2). The 2D traditions put it late. In Godot a node *is* a transform, so here the spine is ahead of the tradition and should be kept.
- **Random:** Ada puts it late (spine 10). Every tradition puts it early, as the *value* random() long before randomness is a *topic*. The middle ground is to meet random() as a value in the loops chapter (a Molnar-style "1% disorder" recreation), then return to randomness as a declared topic, with seeds and pseudo-randomness as the debt, where the spine puts it.
- **Static before continuous:** the Handbook builds still pictures for all of Part 1 and only then opens the draw loop ("Structure 2: Continuous"). In Godot that means building bodies in `_ready()` first and meeting `_process(delta)` after the first synthesis. This matches the spine, where Point_Animatedcube comes late in primitives.

## Course by course

### 1. Design By Numbers - John Maeda, MIT Press, 1999 [V]
- **Units (19):** Begin, Commands, Line, Lines, Variables, Repeat, Calculate, Dot, Dots, Nest, Commands, Time, Paint, React, Touch, Network, Change, Numbers, End. [V, Internet Archive record `designbynumbers0000maed`; Open Library: 255 pp.]
- **Pedagogy:** a language with "very few commands" for "visual people". Maths is kept out of the first half; the second half brings in the algebra "because computation is inherently mathematical" [V, Open Library]. A 100x100 grey canvas [mem].
- **Ada can learn:** (a) **singular then plural** as an ordering move (Line then Lines, Dot then Dots): one body, then many bodies. That is Point_One then Point_Lines, and it is the braid's "many bodies = loops". (b) "Commands" comes **twice**: first you call them, then after Nest you write your own. That is the named return the contract allows. (c) Constraint as pedagogy: Palle's SKETCH helper (point/line/box) is the DBN move in Godot.
- **Caution:** grey only, 2D, a dead language. The constraint that makes it clear also shuts out colour and depth, and it led straight to Processing (Maeda's students Reas and Fry).

### 2. Processing: A Programming Handbook for Visual Designers and Artists - Casey Reas, Ben Fry, MIT Press, 1st ed. 2007 [V], 2nd ed. Dec 2014, 720 pp. [V, processing.org/books]
- **1st-ed reading order** [V, contents PDF at wiring.org.co]. Part 1: Structure 1 (code elements), Shape 1 (coordinates, primitives), Data 1 (variables), Math 1, Control 1 (decisions), Control 2 (repetition), Shape 2 (vertices), Math 2 (curves: norm, lerp, map), Color 1, Image 1, Data 2-3, Typography 1, Math 3 (trigonometry), Math 4 (random), Transform 1-2, Development 1 (sketching), **Synthesis 1: Form and Code**, **Interviews 1: Print**. Part 2: Structure 2 (continuous), Structure 3 (functions), **Shape 3 (parameters, recursion)**, Input 1-5, Development 2 (iteration, debugging), Synthesis 2 (input and response), Interviews 2. Part 3: Motion 1-2 (lines, curves; machine, organism), Data 4 (arrays), Image 2-5, Typography 2-3, Color 2, Output 1, Synthesis 3 (motion and arrays), Interviews 3. Part 4: Structure 4 (objects I), Drawing 2 (kinetic forms), Output 2, Input 6-7, Structure 5, **Simulate 1 (biology), Simulate 2 (physics)**, Synthesis 4, Interviews 4. Then Extensions: 3D, Vision, Network, Sound, Print, Mobile, Electronics.
- **2nd-ed order** [agg, not checked]: Draw, Color, Variables, Flow, Interactivity, Repeat, Synthesis 1, Text, Typography, Image, Transform, Vertices, 3D Drawing, Shapes, Synthesis 2, Calculate, Random, Motion, Time, Functions, Objects, Synthesis 3, Arrays, Animation, Dynamic Drawing, Simulate, Data, Interface, Image Processing, Render Techniques, Synthesis 4. The 2nd edition merged the numbered families into plain chapters and added "data and geometry" chapters [V, processing.org].
- **Pedagogy:** short topic chapters of examples; every quarter ends with a **Synthesis** chapter (worked larger pieces: sketching, modularity, algorithms) and an **Interviews** chapter with practitioners.
- **Ada can learn:** (a) **Two tables of contents**: course order plus a by-spine index, with chapters numbered inside their spine sequence ("Randomness 1" early, "Randomness 2" at spine place 10). (b) Four parts, each closed by a Synthesis (a mini-project checkpoint, like /course's CP1) and a lineage chapter. Four parts line up with the application's four work packages. (c) Static first, continuous second. (d) Debugging gets a whole chapter (Development 2), in the middle of the book rather than at the end.
- **Caution:** it is a handbook, not a course, so the teacher still has to cut it. The numbered-family scheme was dropped in the 2nd edition, perhaps because it confused readers [mem, a guess].

### 3. Learning Processing - Daniel Shiffman, Morgan Kaufmann, 1st ed. 2008, 2nd ed. Aug 2015, 564 pp. [V, processing.org/books]
- **Chapters** [V, learningprocessing.com/examples]: 1 Pixels, 2 Processing, 3 Interaction, 4 Variables, 5 Conditionals, 6 Loops, 7 Functions, 8 Objects, 9 Arrays, 10 Algorithms, (11 Debugging, 12 Libraries [mem]), 13 Mathematics, 14 Transformations and 3D, 15 Images and Pixels, 16 Video, 17 Text, 18 Data, 19 Networking, 20 Sound, 21 Exporting, 22 Advanced OOP, 23 Java.
- **Pedagogy:** chapters grouped into ~10 "Lessons", each ending in a lesson project [mem]. One running character, **Zoog**, a creature drawn from primitives, is rebuilt at every step: variables, then conditionals, then a function, then an object, then an array of Zoogs [mem, confident]. Chapter 10 "Algorithms" breaks a small game into parts [mem]. Online exercises and examples [V, site nav].
- **Ada can learn:** **one student body carried through the whole course and rebuilt as each code idea arrives.** That is the BODY strand as continuity rather than a new object every chapter. Zoog → object → array of Zoogs is exactly "one body → family → many bodies". Algorithms as a synthesis chapter that takes a small game apart fits the contract's "small complete game" requirement.
- **Caution:** 3D waits until chapter 14, which is impossible in Godot. A cartoon mascot also carries a stance: the body is a *character*, never a question.

### 4. NYU ITP Introduction to Computational Media (ICM), Code + Media halves [V]
- **ICM-2025-Code** (7 weeks, 2.5 h/week, 6-8 h homework): 1 Introduction and Drawing, 2 Animation: Variables, 3 Interaction: Conditionals, 4 Repetition: Loops, 5 Organization: Functions, 6 More Repetition: Objects and Arrays, 7 The DOM and Final Project Presentations [V, github.com/ITPNYU/ICM-2025-Code]. **ICM-2024-Media** (7 weeks): Pixels (1-2), Sound (3-4), Text (5), Data (6), Final (7) [V, github.com/ITPNYU/ICM-2024-Media].
- **Pedagogy:** weekly homework documented with "written description, photos, screenshots, screen recording, code, and video". Graded complete / partial / incomplete. One objective: "Seek, identify, read, and understand code examples that can be combined and/or modified" [V].
- **Ada can learn:** (a) **double chapter titles**: what you see, then the idea ("Many bodies: loops"; "A family: @export"). (b) A course split into two 7-week halves shows how the short track can be the first half of the long one. (c) The "read and modify others' examples" objective is the honest core of ai_assist: reading code comes before writing it. (d) Complete/partial/incomplete grading suits art school.
- **Caution:** 2D, web, and the geometry is incidental. Media comes after code, which would push Ada's bodies back.

### 5. The Nature of Code - Daniel Shiffman, 2012 (Processing) and 2024 (p5.js; print 3 Sept 2024) [V, github.com/nature-of-code/noc-book-2]; publisher No Starch Press [mem]
- **Chapters** [V, natureofcode.com]: 0 Randomness, 1 Vectors, 2 Forces, 3 Oscillation, 4 Particle Systems, 5 Autonomous Agents, 6 Physics Libraries, 7 Cellular Automata, 8 Fractals, 9 Evolutionary Computing, 10 Neural Networks, 11 Neuroevolution. Three parts: inanimate objects (0-4), living systems (5-8), intelligence (9-11). "A linear narrative", not a survey [V, natureofcode.com/introduction].
- **Prerequisite:** "one semester of programming instruction"; OOP "fairly critical" [V].
- **Pedagogy:** each chapter ends with the **Ecosystem Project**, one cumulative project: designing creatures for a museum's "Digital Ecosystem" exhibit [V]. The ITP course (Spring 2023, 14 weeks): Introduction, Vectors, Forces, Oscillating Motion, Particle Systems, Autonomous Agents, **Simulation Project (midterm, wk 7)**, Soft Body Physics, Fractals and CA, Genetic Algorithms, Neuroevolution + proposals, individual sessions, workshop, presentations [V, github.com/nature-of-code/noc-syllabus-s23].
- **Ada can learn:** (a) The cumulative chapter-end project is **literally a museum exhibit of creatures**, and Ada has an endless museum. The contract's `project_step` could be "put this chapter's body into your own hall". (b) Inanimate, then living, then intelligence is the application's arc (WP1 to WP4, F to E); the part titles can say so. (c) A midterm Simulation Project halfway through is a model for the long track. (d) Soft bodies get a week of their own in the course but no chapter in the book, which suggests soft bodies (spine 17) can be a lab week rather than a chapter.
- **Caution:** it presupposes the intro semester, which is exactly the gap the braid has to fill. Its stance treats nature as simulable. It is a *how* book: the debt (what the model owes) is mostly left unasked.

### 6. Generative Design - Bohnacker, Gross, Laub, Lazzeroni (Verlag Hermann Schmidt; English: Princeton Architectural Press, 2012 Processing ed., 2018 p5.js ed.) [V, generative-gestaltung.de/2]
- **Units** [V, site + github.com/generative-design/Code-Package-p5.js]: **P Basic Principles**: P.0 intro to p5.js, P.1 Color, P.2 Shape, P.3 Type, P.4 Image. **M Complex Methods**: M.1 Random and noise, M.2 Oscillation figures, M.5 Data trees, M.6 Dynamic data structure. The 1st edition also had M.3 (formula-based surfaces) and M.4 (attractors) [mem]; in the p5.js code package those folders are absent [V]. Code under Apache 2.0 [V].
- **Pedagogy:** every sketch has an address (P_2_1_2_03 = principles, shape, section 1.2, variant 03). Numbered variants of one sketch each change one thing [V, folder listing: P_2_2_6_01..05]. The book opens with a gallery of projects before the code [mem].
- **Ada can learn:** (a) The **variant series** is Ada's ARGUMENT strand without the prediction: one body, _01.._05. Ada adds what Generative Design never asks, a prediction written before the render, then the comparison image. (b) The **P/M split**: principles by visual element (Ada's version: point, line, surface, volume, colour) against methods (the spine's algorithm sequences). That gives a two-part course whose second half can be taken in any order, which is one way to be "related, not forced". (c) A stable address for every exercise suits the two-index idea.
- **Caution:** a design-craft stance with almost no critique. Mostly 2D; the 3D formula surfaces are the part the web edition dropped. Its parameters are for making, not for arguing.

### 7. Form+Code in Design, Art, and Architecture - Casey Reas, Chandler McWilliams, LUST; Princeton Architectural Press, Sept 2010 [V, formandcode.com + search summary]
- **Chapters:** What is Code?, Form and Computers, **Repeat, Transform, Parameterize, Visualize, Simulate** [V/agg]. Code examples, two per theme [V, formandcode.com]: Repeat: Embedded Iteration, Recursive Tree. Transform: Transcoded Landscape, Slit Scan. Parameterize: Chair, Wave. Visualize: Displaying Data, Superformula. Simulate: Particles, DLA.
- **Pedagogy:** not a programming course. Each theme has an essay and history ("over 250 significant works" across 60 years) plus a few code samples.
- **Ada can learn:** (a) **Parts named by what code does to form**, not by language feature. Repeat, Transform, Parameterize, Visualize, Simulate map onto the spine (tiling/array; transformation; the DNA families; colour/data; forces onward). **Parameterize** is the one verb the spine has no sequence for, yet it is how Ada measures its bodies to be made (74% of scripts use @export). The course can add it as a chapter of its own and declare it. (b) An essay plus a precedent gallery per theme gives the `lineage.reference` field a model.
- **Caution:** no exercises and no ordered skill ladder. The verbs overlap (a recursive tree is Repeat *and* Simulate). It is a survey, not a course.

### 8. Code as Creative Medium: A Handbook for Computational Art and Design - Golan Levin, Tega Brain; MIT Press, Feb 2021, 280 pp. [V, penguinrandomhouse.com]
- **Part One, Assignments (23), in book order** [V, search summary of contents, two independent results]: Iterative Pattern, Face Generator, Clock, Generative Landscape, Virtual Creature, Custom Pixel, Drawing Machine, Modular Alphabet, Data Self-Portrait, Augmented Projection, One-Button Game, Bot, Collective Memory, Experimental Chat, Browser Extension, Creative Cryptography, Voice Machine, Measuring Device, Personal Prosthetic, **Parametric Object**, Virtual Public Sculpture, **Extrapolated Body**, Synesthetic Instrument.
- **Part Two, Exercises** [agg]: Computing without a Computer, Graphic Elements, Iteration, Color, Conditional Testing, Unpredictability, Arrays, Time and Interactivity, Typography, Curves, Shapes, Geometry, Image, Visualization, Text and Language (plus later groups not seen).
- **Part Three, Interviews** with educators, by theme [agg]: Teaching Programming to Artists and Designers, The Bimodal Classroom, Encouraging a Point of View, The First Day, Favorite Assignment, When Things Go Wrong, Most Memorable Response, Advice for New Educators, Classroom Techniques, Provenance.
- **Assignment format:** "syllabus modules, each built around an open-ended assignment or prompt", "tested, adapted, or observed by the authors over twenty years" [agg]. Each has a **Brief**, **Learning Objectives** and **Variations** for different skill levels [agg; "Learning Objectives" also on Google Books], plus an annotated gallery of historical and contemporary precedents [V: "annotated examples of both historic and contemporary projects", tegabrain.com] and a "Making It Meaningful" section [mem].
- **Ada can learn:** (a) The **two-kind unit**: short *exercises* train one code idea; open *assignments* ask for a work with a point of view. That is Ada's CODE strand against its BODY+ARGUMENT strands. (b) Several assignment titles **are already Ada bodies**: Virtual Creature, Parametric Object, Extrapolated Body, Personal Prosthetic, Virtual Public Sculpture, Generative Landscape, Face Generator. They are ready-made short-track mini-project prompts, translated to 3D and VR. (c) "Computing without a Computer" as the first exercise group is Day Zero. (d) Variations by skill level serve the "bimodal classroom", and art schools always have one, so both tracks can share a chapter at two depths. (e) "Encouraging a Point of View" is the CLAIM sentence.
- **Caution:** a catalogue, not a sequence; the teacher has to order it, and that is the very problem Palle has. Assignments are language-neutral and mostly 2D, web or physical. Its critical stance is mild (point of view, not debt).

### 9. School for Poetic Computation - Recreating the Past (Zach Lieberman) [V, sfpc.io/recreatingthepast-spring2020]
- **Format:** 10 weeks, one 2 h meeting a week, 1-4 h homework. Each week, recreate one existing artwork "from scratch" using openFrameworks. Prior coding is required.
- **Weekly themes in order:** Chaos and Order (Vera Molnar); Animation and Harmony (John Whitney); Computational Typography (Muriel Cooper / John Maeda); Pattern (Bridget Riley / Anni Albers); Pixels (Ken Knowlton / Lillian F. Schwartz); Images (Nancy Burson / Jason Salavon); Body (Camille Utterback and Romy Achituv / Myron Krueger); **Glitch / Deformation (Rosa Menkman / Steina and Woody Vasulka)** [V].
- **Stance:** "by recreating historic works, we also investigate what modern tools and approaches have to offer". The course is described elsewhere as rewriting the place of women in computational art history (Molnar, Cooper, Schwartz) [agg].
- **Ada can learn:** (a) **Recreate a precedent** as an exercise format. The recreation is a *baseline* for the ARGUMENT: compare yours with the original and say what the approximation owes. That is DEBT made concrete. Ada halls already recreate (Primitives_Melencolia, Randomness_10_PRINT_Algorithm, Symmetry_Seventeen, Wavefunctions_Bernini, WaveFunctions_John_Cage). (b) **Chaos and order first** (Molnar's disorder) backs meeting random() early. (c) The course **ends in Body, then Glitch/Deformation**, the same close as Palle's DEBT and ONTOLOGY (deformation, polycount against smooth deformation, the poor image). (d) One or two artists per theme is how Palle's lineage list (Höch, Bellmer, Kawaguchi, Satterwhite, Perry, Steyerl ...) could attach one precedent to each chapter.
- **Caution:** needs prior coding. It builds a canon. Recreation can slide into pastiche, and Ada's bodies should leave the precedent, not copy it.

### 10. School for Poetic Computation - Code Societies, Winter 2019 [V, sfpc.io/codesocieties-winter-19]
- **Format:** **3 weeks**, Mon-Fri evenings 6:30-9:30 pm, 7-26 Jan 2019. Organised by Melanie Hoff; a different teacher each session. Outcomes are "several small scores or sketch pieces that may exist online, on screens, be performed, or installed" [V].
- **Sessions in order:** Introduction (Hoff & Taeyoon Choi); Computational Methods (Hoff & Nabil Hassein); The Computational Scrawl (Allison Parrish); Building Nets for Floating Data (Everest Pipkin); Distributed Web of Care (Choi); WYFY: Exorcizing Technology (BUFU); Ethicsware (Dan Taeyoung); Networked Terraforming (Ingrid Burrington); **Cybernetics of Sex** (Hoff); we play programmed. (FlucT); **Software as Ideology** (American Artist); **Critical Simulation** (Nora Khan) [V].
- **Stance:** "ideological and corporeal attributes of computation"; critical theory discussion balanced with hands-on coding workshops; how platforms and algorithms "reinforce existing systems of power" [V].
- **Ada can learn:** a proven **three-week critical format** of the same length as Palle's Queer 3D course, with the guest-per-session rhythm Palle already uses (Harriet Davey, Tobias Bernstrup). The "score" as outcome (instructions a body can perform) suits VR's "become it". Critical Simulation and Cybernetics of Sex are the nearest outside examples of the ONTOLOGY and queer layers. It also shows how the spine's end (crisis, QFEP, post-crisis) can be *taught*: as critique sessions set beside code, not as more code.
- **Caution:** no code ladder and no progression; the sessions stand alone, which makes for weak student logic in a beginner course. The lesson for Ada is the *pairing*, not the order.

### 11. The Coding Train - Daniel Shiffman [V, thecodingtrain.com/tracks]
- **Tracks, in site order:** Code! Programming with p5.js (35 videos), Working with Data and APIs, Git and GitHub for Poets, Beginner's Guide to ML with ml5.js, The Nature of Code (67 videos), Learning Processing. Stand-alone Coding Challenges sit outside the tracks [mem].
- **Code! chapters** [V]: Getting Started (editor, Shapes & Drawing, Color, **Errors & Console**, Comments), Variables (mouseX/Y, own variables, increment, **random()**, map(), createGraphics), Conditional Logic (Bouncing Ball, else/and/or, booleans), Loops (while/for, nested), Functions (parameters, return), Objects (classes, constructor arguments), Arrays (arrays of objects, removing, object communication).
- **Pedagogy:** live coding with the mistakes left in; each video is short, with a named idea.
- **Ada can learn:** (a) **Errors on day one**, inside "Getting Started", which is the planted bug in PRIMM. (b) random() is a *variable's value* in chapter 2, not a topic. (c) Tracks against challenges gives Ada a clean vocabulary: halls are challenges (stand alone, visit in any order), the course is a track (ordered), and one hall can sit in several tracks.
- **Caution:** built on a video persona; energetic, not self-critical; web 2D.

## What the braid can take (concrete moves, ranked)

1. **Two indexes (Processing Handbook 2007).** Publish the course reading order *and* a by-spine index. Number chapters inside their spine sequence ("Primitives 3", "Randomness 1 / 2"). A departure shows as a number jump and carries its `departure` note.
2. **Double titles (ICM).** "Many bodies: loops", "A family: @export", "Chance: seeds". The BODY comes first and the CODE idea second, like the braid itself.
3. **One body carried through (Learning Processing's Zoog).** Each student builds one body in week 1 and rebuilds it with every new idea: function, family, many, in time, placed, becoming. In the short track that body *is* the mini project.
4. **Variant series plus prediction (Generative Design + Ada).** Every ARGUMENT is a numbered series _01.._05 of one body. Ada's addition, missing from every course in this sweep: the closest pair is predicted before the render.
5. **Recreate a precedent, then depart (Recreating the Past).** One recreation per part, from Palle's lineage or an existing Ada hall. The comparison between the original and the recreation is where DEBT is written.
6. **Exercises against assignments (Code as Creative Medium).** Short CODE exercises; open BODY assignments named as bodies (Virtual Creature, Parametric Object, Extrapolated Body, Personal Prosthetic, Virtual Public Sculpture). Variations at two depths serve the short and long tracks.
7. **Synthesis plus lineage every quarter (Handbook).** Four parts, each closed by a Synthesis (a mini-project checkpoint) and a lineage/interview chapter. Four parts line up with the application's four work packages; NoC's inanimate / living / intelligence arc can name them.
8. **Cumulative museum project (NoC Ecosystem).** Each `project_step` places this chapter's body in the student's own hall. The NoC exhibit is literally a museum; Ada's is endless.
9. **Random as a value early, as a topic late.** Every tradition in this sweep meets random() early. Keep spine place 10 for randomness-as-debt (seeds, pseudo-randomness, repetition under a seed) and declare it as a return.
10. **Static before continuous (Handbook).** Build in `_ready()` through the first part, open `_process(delta)` after the first synthesis.
11. **Short track equals Code Societies' three weeks.** Guest or critique sessions set beside code sessions. The late spine (crisis, QFEP, post-crisis) enters as critique sessions, not as new code.

## What is foreclosed if Ada copies this tradition
- The canonical intro order is **language-feature order** (variables → conditionals → loops → functions → objects → arrays). Followed strictly, geometry turns into illustration, and "what bodies are possible" is never asked. The braid keeps the order but swaps what drives it: each code idea arrives because a body needs it.
- **Transform and 3D come late** in every 2D tradition. Copying that would be wrong for Godot, and the spine is right to put transformation second.
- **No debt.** None of these courses asks the student to state what an approximation hides. It appears only at the edges (Menkman's glitch week, Code Societies). If Ada borrows creative coding's formats without the DEBT field, it gets their stance along with them.
