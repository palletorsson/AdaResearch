# Model B — hardware on the wall

20 October 2026. A first working service unit for the Void, using the project's established apparatus.

The roof charger is mounted on the existing wall to the left of the frame counter. A cream cabinet sits on a steel backplate and two brackets. Rectangular controls, ventilation slots, flat printed markings and a small health readout give it a restrained industrial character. Rigid trunking rises from the cabinet, crosses above the wall and meets the northwest overhead supply socket.

## Use

- Stand in front of the panel, within 1.5 metres. Hold **HOLD / CHARGE** to replenish the body's existing health at eight health points per second, up to 100.
- Desktop: look at the button and hold the left mouse button.
- VR: aim the controller at the button and hold the trigger. The existing XRTools touch-button behaviour is also retained; physical hand reach still needs headset review.
- Release to stop. **MAINS ON / OFF** isolates or reconnects this unit.
- Moving out of reach stops charging even if the button is held remotely. The readout distinguishes full, charging, isolated and out-of-reach states.
- Existing health recovery also clears the crawler's attack blur.

The player plays Model B's body; the charger services that body's existing health. It does not add intelligence, moral development, a second battery resource or another progression system.

## Existing apparatus reused

`commons/interactables/interactable_demo.tscn` provides the reference control language. The rectangular button conversion comes from `RackTemplates.make_button_rectangular`; the actual controls remain the project's `push_button.tscn`, with its press/release ownership, sound and haptics.

`model_b_charger.gd` extends the existing museum `wall_health_station.gd` and reuses its actual-delivery/clamped health transfer. Its target is specifically `Void.health`; it does not write museum health or save data. Markings are textured flat meshes generated by the existing baked-text utility. The display uses the existing TextScreen.

The five architectural interface mounts also now use cream panels, rectangular live controls and the shared rigid supply helper. Their input adapters still forward to the original artifact operations. This change covers that architectural interface family and the new charger; other museum instruments retain their established controls.

## Editing and connection

Open `/lab-editor?mode=void&floor=0`. The palette entry is **Model B wall charger**, in **Architectural interfaces**. Its position, quarter-turn facing and scale use the same rooms JSON as the desktop and VR game. The roof placement is `model-b-charger`, at `[-8.25, -7.0]`, facing 0.

The cabinet front faces local +Z; put its back against a wall. The native supply route is rebuilt from the saved placement to the nearest quadrant's overhead socket. The editor previews the exported native cabinet and vertical trunk; the final horizontal connection is resolved when Godot builds the floor. Exported bound interface models show their saved connection routes.

This is visible service hardware with a local mains switch. It does not yet simulate network-wide power flow, broken cables or shared outages.

The editor validator accepts the layout. Its generic centred prop footprint adds one expected wall-intersection warning for the mounted cabinet. Existing tower warnings are retained in `layout-validation.json`.

## Evidence

`checks.json` records the charger checks using the actual Void scene, desktop mouse input and synthetic XR controller rays through the museum rig. They cover health ownership, held charging, release, isolation/reconnection, remote reach rejection, blur recovery, full-health clamping and the physical connection endpoint. `interface-checks/checks.json` records regression checks for the original sampling bench and weather controls, all five mounts and restoration of source controls.

The PNGs are native Godot Mobile renderer captures inside the live tower. A documentary camera hides the desktop help for these views; the health shown is from the running charger. The physical headset has not been tested.

The web editor uses exported Godot geometry. Its preview does not run the native healing interaction.
