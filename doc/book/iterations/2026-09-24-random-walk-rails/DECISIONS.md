# Random Walk: somewhere to start

24 September 2026. An added encounter, with the existing chapter and hall preserved.

## Decision

The terrarium already has a strong account of accumulated steps and an incomplete trail. Keep it. Add `random_position_rails` at (13,8), facing into the first chamber, before the hand-carried drawing point in book order. The visitor can slide a prediction marker, pull NEXT and watch two large carriages answer the same draw differently.

One uses that draw to choose a fresh position across a 4.4m rail. The other uses it for a signed step of at most 0.4m from its last position. Both reveal targets for 0.65s and then move for 1s with identical easing. This separates the appearance of continuity from a rule that retains its previous position. At the ends, the step target folds; this is a bounded walk. The animation joins endpoints without an additional wall-contact waypoint.

The same-input coupling is deliberate. These are not independent populations. Nor does the visible motor supply physical entropy. Both are seeded algorithmic choices with inspectable animated consequences.

## Interaction and evidence

NEXT uses the production grab lever and one-pull latch. RUN repeats. HOLD lets an already revealed move finish and prevents the next draw. REPLAY cancels any active movement and restores seed, positions, record and marker. The prediction marker is the existing native horizontal slider with metre-sized limits and collision shapes; its root is not scaled.

Native pointer/state checks test the real controls on a translated, rotated host, the shared draw, target-before-motion timing, matched easing, bounded history, reflection, seeded replay and cancellation during motion. A separate isolated actual-museum run tests placement, retained artifacts, pointer input and walking approaches, and produces the photographs.

Headset grip, reach, comfort and learner understanding remain untested. The native runner reports an unresolved project UID warning and an ObjectDB exit leak warning; the latter has not been diagnosed. No script errors occur in the passing runs. Counts and results are in native-checks.json and museum-runtime.json.

The capture uses a private museum snapshot. The live museum bake/save is not overwritten. Source placement will appear when the hall is rebuilt. No full-book export or commit was made.
