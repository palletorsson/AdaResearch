A memory we can change

Compact instructions, evolving tutorials and parallel evidence in the Endless Museum · 4 October 2026

The counter was already in the room. We had built it, photographed it and written about arriving in front of it. Yet, while developing the opening tutorial, we drifted toward making another beginning: another example, another prepared environment, another explanation of how to get started. The writing was moving while an essential decision slipped out of view. We were working inside the Endless Museum. The student had already arrived.

The counter in Point Zero. An earlier Godot capture, recorded on 3 October. Its presence belongs to the lesson's starting conditions. This still image does not establish how its update code works.

Ada brings a museum, a book and a programming course into the same developing project. A student meets a point, moves it, connects positions into a line, retains movement as a trace, and returns to that trace through a grid. The reflective writing follows other questions through the same material. What have we borrowed? What makes an abstraction visible? Which boundary can a body cross? Other artifacts remain part of the room without becoming exercises or paragraphs.

Keeping those relations alive is difficult. An AI can produce a convincing example very quickly. Palle has described how useful this is after a long time away from programming. The difficulty shifts toward choosing the right example, placing it in a sequence and remembering why it belongs there. A polished lesson can arrive before its place in the project has been understood.

Repeated corrections exposed the problem. The player is already supplied. The counter already exists. The student's own trace should travel into Grid. A visible sphere and a collision boundary are different things. We are making summaries now; do not change the code. Each instruction is simple. Together they govern what counts as useful work. When one disappears from the working context, a locally reasonable answer can pull the project elsewhere.

We began writing a short storyboard before each tutorial. It identifies the encounter, what the student brings, what they do, what is supplied and what travels onward. Palle can correct that teaching choice before it becomes several pages of prose and code. The next step was to compress the storyboard itself for a future AI.

Point Zero: Use existing counter. Teach _ready() initialization and _process(delta) repetition. Supply player, room and display. Carry execution timing. Preserve reflection on arrival and borrowed time.

This little paragraph carries a selection. It does not attempt to contain the implementation of the museum. A shared brief holds the wider agreement; the hall's full summary, source references and unresolved questions remain available. Together they let us recover the reason for a lesson before deciding how to write it.

The purpose of compression became clearer as we worked. Shorter instructions make it practical to consider more halls together. We can ask whether a list has been introduced before an algorithm needs it, whether a supplied function is being mistaken for a learned skill, or whether three successive halls are teaching the same small edit. We retrieve the detailed material where a decision needs it. There is less repeated reconstruction before we can think about the route.

The core also needs to change. Perhaps Trace is the right place to introduce the ordered list and its loop. Perhaps a later artifact makes that choice less convincing. We should be able to revise the teaching intention without first rewriting every full tutorial that depends on it. An explicit dependency tells us which lessons to reconsider. The full drafts then need to catch up with the revised decision.

That makes the status of a sentence important. “The counter already exists” reports a condition of the project. “Teach repeated execution here” proposes a teaching choice. “Leave the wider player system supplied” limits the lesson. “The student should carry their own drawing onward” expresses an intention whose implementation must be inspected. Shortening all four into confident commands would erase useful differences.

We want the memory to retain decisions, proposals, reasons and open questions. Reasons can be brief. “Supply the player so the first lesson can attend to timing” protects the lesson better than an unexplained prohibition. An earlier proposal also needs to yield visibly when Palle corrects it; otherwise old and new instructions can continue competing inside the same project.

There is a risk in making anything compact. The easiest details to remove can be the ones that make the work particular. “Teach vectors” loses the black point, the hand, the supplied hold and the question of which coordinate frame reports the movement. A useful summary keeps the distinctions that guide the next action. Its success is measured by how faithfully we can return to the work, as well as how quickly we can read it.

This is what we mean by “type-safe” writing. It is an analogy for keeping the edges between different kinds of claims legible. A position value is not the sphere used to show it. An available function is not a skill the student has acquired. A mathematical construction, a historical association and an artistic judgement require different support. They can meet in the same room without becoming interchangeable.

The current route gives Day Zero and 204 halls both full summaries and compact alternatives. The shared brief is included once in the short export. This gives us a working way to hold the sequence, but it does not yet demonstrate that the tutorials will teach well. The summaries remain proposals. Their compression is a practical experiment in continuity.

Palle's next wish was to “stamp the truth” about the project through parallel processing. Many small investigations could run at once, each responsible for a bounded claim. One worker could inspect the counter's callbacks. Another could trace where the drawing record is kept. A third could compare what Grid receives with what it displays. Each would return evidence, rather than another broad account of what the project probably does.

For that to be useful, the workers would need to examine the same saved project state. Their records should identify the claim, relevant files and versions, method, observed result and limits. The outcome could be supported, refuted or unknown, always within the check's scope. A source inspection and a runtime observation should remain distinguishable. A conflict between two findings should remain visible until its cause is understood. Agreement among several AI readers would not by itself establish a fact.

Consider the sentence “the student's trace survives the next hall.” Source inspection can follow the session store and the receiving artifact. A runtime check can record what reaches the next hall under a specified interaction. Restarting the project asks a further question. A screenshot of a line in Grid cannot establish all of these claims. A useful evidence record keeps its conclusion as narrow as its check.

Parallel work could make this affordable across a large project, but it also needs restraint. Check the claims on which the current writing depends. Revisit a record when a relevant input changes. Keep workers observing a saved state rather than letting them repair the behavior they are supposed to describe. A proposed lesson must not become true because an investigator quietly changed the artifact to fit it.

“Stamping” here names a proposed record of evidence, tied to a particular claim and version. Ada's existing spatial stamp tools have a different job, recording changes to arrangements. The new proposal is to distribute observation while keeping its findings attributable. A changed project would leave earlier records as history, rather than silently inheriting their conclusions.

Some questions will remain outside that kind of check. A working collision boundary cannot certify a welcoming room. Correct code cannot certify that a beginner understands it. A camera cannot settle whether the encounter produces awe. Those questions need situated judgement, teaching and play. They belong in the project's memory too, with their conditions and disagreements intact.

We can let a small instruction remember what we intend, and let an evidence record show what we have established. Between them there is room to change our minds. When we return to the counter, we should be able to recover why it is there, inspect what it does and choose what to teach from it. The next beginning can happen in the room we already made.
