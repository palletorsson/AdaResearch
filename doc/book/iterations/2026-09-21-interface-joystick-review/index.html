The release is part of the interface.

Each joystick moves the orange point behind it. Move all three the same way, then let go. The first keeps its exact setting. The second keeps a setting rounded to five-degree steps. The third comes back to the centre.

This example represents position settings. If the receiver represented velocity, returning to centre would stop a movement instead. The receiver is part of the meaning.

Make the grasp agree with the object.

The smooth joystick’s visible ball was five centimetres beyond its grab target, and its hand-pose redirects led to missing nodes. The zero variant never enabled return-on-release. The preserved baseline confirms both defects. The repaired scenes align visible and interactive geometry and use the intended release rules.

The matched close-ups use the same camera. All lettering is flat on surfaces; the shafts and grips remain physical 3D objects.

A reusable vocabulary

ControlWhile movingWhen released
ContinuousBoth angles vary continuouslyStays where set
DetentedBoth angles use 5° incrementsStays at the selected steps
ReturningBoth angles vary continuouslyReturns to (0°, 0°)

Both axes retain their original −45° to +45° limits. Grabbing and pointing share the same movement logic. A pointer cannot steal another pointer’s control, and losing a pointer releases a returning joystick.

The focused scene is commons/interactables/interactable_joystick_demo.tscn, built by the existing interactable demo’s new joystick_reference option. It is a reference station, not a new museum hall.

Keep the existing instrument working.

The three existing joystick scene paths remain in use. The shared ControlPanel, component demo and other source consumers can receive the improvements on reload. The Body / Transform console passes its existing tests in both visual skins; all dependent halls have not yet been reviewed.
