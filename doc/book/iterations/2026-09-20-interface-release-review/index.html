What happens
when you let go?

A choice stays selected. A command returns to zero. A signed setting can stay where you left it. The interface should make that difference visible.

Hold, then release

The orange marker stays at choice five. The purple setting stays at −0.50. The blue command is +1 while held and returns to zero when released. These captures show two states of the same working Godot reference, from the same camera.

The control tells you what will persist

The stepped slider now changes the stored value in discrete steps. Its receiver gets the same value that the handle shows. The bipolar slider supports both return and retention: having negative and positive values does not, by itself, decide what release should do.

The returning control resets immediately. This demonstrates the input contract; it does not simulate spring dynamics. A force or velocity receiver can use the same contract later, but these markers only show the current value.

Repair the route, not only the appearance

The census found that these two rack controls drew a handle but inherited empty pointer handlers. They now handle pressing and dragging. A separate layout defect was also found: entering the scene tree discarded the larger cell dimensions allocated by the panel. Those dimensions now survive.

The existing module panel converts a 3D hit into a 2D GUI event. We tested that whole route and the resulting marker movement. An active drag now belongs to its initiating pointer: another pointer cannot move or release it. Leaving the panel releases a returning command.

A reusable reference

Open commons/interactables/interactable_release_demo.tscn in Godot, or set release_reference = true on InteractableDemo. The full sampler remains available. The reference uses the existing shared module panel and canonical rack controls.

# Control entries supplied to ModuleFaceTexture.build():
{"type": "sls", "step_count": 5}  # Discrete choice; persists
{"type": "slz", "return_to_center": true}  # Command; returns
{"type": "slz", "return_to_center": false} # Setting; persists

The signal remains normalized from 0 to 1. For the bipolar control, 0.5 is signed zero; get_signed_value() returns −1 to +1. Consumers retain control of their own units and effects.

Evidence and what remains

All 43 automated checks pass: endpoints, between-notch input, programmatic assignment, step-count changes, release, exit, competing pointers, receiver agreement, rotated/scaled placement and continuous-slider regression. The renderer is Godot Mobile on the desktop GPU. Pointer events use generated hit coordinates and actual viewport GUI dispatch.

Headset reach, tracked hands and Quest performance still need testing. No museum hall was moved or replaced in this pass.

The standalone VRRackControl wrapper is the next integration gap. It renders a screen and case but has no pointer forwarding of its own. Repairing its inner slider does not yet make that wrapper interactive. Audio and artifact consumers also need their intended release behaviour checked before wider adoption.
