The knob must stay on its plane

The old pad inherited a one-axis constraint script. Its face and movement used different planes, and its grab target missed the visible knob. A larger custom bezel in the vector console tried to compensate. The shared component now supplies the complete working pad.

A reusable control, a specific encounter

The existing slider_plane.tscn path now supplies the repaired physical pad. Its child keeps the historical Vector2-in-metres contract; the wrapper adds explicit signed normalized positions and display scaling. Grabs and pointers agree, including after rotating the console.

interactable_xy_demo.tscn is a focused InteractableDemo configuration using the actual vector console. The same code serves the registry’s vector_add and vector_sub scenes. The room_gap variant substitutes another encounter and remains outside this verification.

These are position settings. A control that commands velocity or force needs a different receiver and a different release explanation; that distinction remains part of the next pass.

Evidence and limits

71 checks cover real XR Tools pickup and release, ray-hit pointer dispatch, tilted and rotated axes, limits, optional detents and spring return, input ownership, operand synchronization, visible arithmetic and four sibling-console construction regressions. The successful run has no script errors.

Still to try in the headset: hand comfort, shorter and seated positions, Quest text legibility and frame time. These captures show the actual artifacts in a desktop fixture, not a complete museum walk. Receiver geometry still rebuilds after edits; this pass makes no Quest performance claim.
