# Closing Primitives: two making studies

3 October 2026. Following the discussion of Plato, finite construction and Melencolia.

The critical lineage concerns the relation between an intelligible form, its material representation and the desires invested in making it. A finite representation is not the same as failed knowledge. A satisfactory tolerance is not mathematical exactness, and exact construction does not settle meaning or aesthetic value. This is Ada's interpretive passage; it is not presented as a documented shared intention of Plato and Dürer.

The tutorials give the learner operations with which to investigate those distinctions. They do not paraphrase the historical argument into technical instructions. No final.md, live map, artifact registry or sequence order changed.

## One column

Ignorance's existing function lesson stays intact with one continuation link. Its companion is canonical `tutorial-column.md`. The shared starter contains `primitive_column.tscn` and both the learner's position rule and the supplied surface builder. A radius list, an equally divided height and sampled circular positions produce seven rings. The learner changes a waist, then height, then radial resolution. Complete lesson geometry is generated in code without scene-child references.

The profile is deliberately piecewise linear. The larger Rings of Ash gallery has curved sections; its separate profile sampling control cannot truthfully be carried into this reduced exercise. Extra evenly spaced radii change the profile and the heights of existing entries. Do not describe that as an automatic smoothness setting. A supplied sampler provides the trigonometry before Portals reuses the same helper. This is an explicitly borrowed operation, not a claim that sine and cosine have been taught here.

ColumnSurface supplies seam closure, two caps, flat normals and SurfaceTool. The learner owns the position data and the loop that makes it. The accepted working bounds are named in the lesson. Assertions guard the example, but the assertions are not the new teaching subject. The completed mesh has no collider.

## Portals

The existing lesson remains unchanged. It measures the polygon's boundary length against TAU times radius and changes a declared tolerance independently of the geometry. That already supplies the missing middle distinction. Its earlier pilot and verification remain linked, not rerun or rewritten without cause.

## Melencolia

The earlier production implementation walkthrough is preserved byte for byte in `tutorial-museum.md`. The canonical `tutorial.md` now uses a small executable study: three identical pyramids, one placement list. Polyhedra's position/face separation and Cube's split square return in the supplied construction. Moving the centre body changes its projected size; closing the outer spacing changes overlaps without changing any local vertex. No new interaction system or unrelated programming concept is introduced.

This follows the geometric court already in the museum. It does not label the court as Dürer's composition or rebuild the historical tableau in the starter. That fuller encounter and its source notes remain available. The practical handover is to Transformation: the positions can next change over time. A two-column arrangement can be a later extension after this whole-body placement operation has been learned.

## Verification

`run_checks.py` packages the starter, extracts it into a fresh temporary project, imports it with Godot 4.6 and runs `verify.gd` against that copy. The printed edits are applied to actual learner scripts. Checks include an independently known volume, closed triangle seams and caps, outward lighting normals, locality of profile edits, unchanged widths under height edits, supported resolution settings, projected size under translation, unchanged local mesh data under placement, fresh instances without authored children and the prepared solid floor. Native captures show the running student room.

The verification harness's first attempts exposed its own untyped-array argument and inferred-type errors; both were corrected before the clean run. These were in the harness, not the learner examples. A physical headset, Quest performance and beginner comprehension have not been tested. `verification.json` and `package-verification.json` record the completed run.

The builder follows Godot's documented clockwise front-face convention and sets lighting normals before submitting vertices. See [SurfaceTool, Godot 4.6](https://docs.godotengine.org/en/4.6/classes/class_surfacetool.html). This dependency remains supplied rather than silently counted as student knowledge.
