Continue with the solid point from Point One. Its surface and collision shape already exist. Keep their size, material and position. We will change what your hand can do with this point.

The prepared museum supplies the XR hand and its pickup function. Your code makes the point available to that hand.

For this pilot, edit incoming.gd, attached to a Node3D station in a working copy with the museum's configured XR player. It collects Point One's small solid-point construction into one file. body refers to its visible mesh; solid refers to its physics body. Both are local variables inside _ready(). Keep these changes in that function.

Give the existing boundary pickup behaviour

Replace this line:

var solid := StaticBody3D.new()

with:

var solid := XRToolsPickable.new()

XRToolsPickable is the toolkit's physics body with pickup behaviour. The existing collision shape still belongs to solid. You do not make another sphere or write a hand-tracking loop.

Immediately after its position assignment, add the settings below:

solid.position = centre
solid.freeze = true
solid.freeze_mode = RigidBody3D.FREEZE_MODE_KINEMATIC
solid.release_mode = XRToolsPickable.ReleaseMode.FROZEN
solid.ranged_grab_method = XRToolsPickable.RangedMethod.NONE
solid.collision_layer = 4
solid.collision_mask = 196615

The first three added lines keep the point still while waiting and after release. Kinematic freezing lets the grab driver move it. RangedMethod.NONE requires the hand to come close. The last two lines use the museum's supplied collision settings: layer 3 for pickable objects, with the existing mask for their collisions.

These assignments must run before add_child(solid). When the body enters the scene tree, XR Tools remembers its collision settings for release.

Make the surface travel with the boundary

At the end of the construction, add one line after the existing add_child(solid):

add_child(solid)
body.reparent(solid)

Point One placed the surface and physics body separately. reparent moves the existing surface under solid in the scene tree. Both nodes are already in the tree, so this call keeps the surface's world position. It does not jump or make a copy. When the hand moves solid, its surface and collider move together.

Run the working copy. Bring your hand close, grab, move and release. The sphere follows your hand and stays where you leave it.

Check what changed

Predict what would happen without the reparent line. Try it, then restore it. Which part moves, and which part stays?

Choose a different value for RADIUS, using what Point One taught. Predict what will change. Check that the surface and boundary still agree while held. No second sphere-construction example is needed here: you are extending the same one.

Carry this changed code forward. The next part of Coordinates can use the same moving point to examine local and world positions. This pilot ends at pickup and release; it has not connected the museum's coordinate readouts to this fixture.

# incoming.gd
# Source-bound fixture ASSEMBLED from Point One's small solid-point construction.
# Assumed incoming learner state, not a recovered learner portfolio or museum file.
extends Node3D

const RADIUS := 0.14
const CENTRE := Vector3(0, 1.12, 0)

func _ready() -> void:
	var radius := RADIUS
	var centre := CENTRE
	var body := MeshInstance3D.new()
	body.name = "VisiblePoint"
	var sphere := SphereMesh.new()
	sphere.radius = radius
	sphere.height = radius * 2.0
	sphere.radial_segments = 48
	sphere.rings = 24
	body.mesh = sphere
	body.material_override = material(Color(0.97, 0.97, 0.95))
	body.position = centre
	add_child(body)
	var solid := StaticBody3D.new()
	solid.name = "PointCollision"
	solid.position = centre
	var collider := CollisionShape3D.new()
	var sphere_shape := SphereShape3D.new()
	sphere_shape.radius = radius
	collider.shape = sphere_shape
	solid.add_child(collider)
	add_child(solid)

func material(colour: Color) -> StandardMaterial3D:
	var mat := StandardMaterial3D.new()
	mat.albedo_color = colour
	mat.roughness = 0.32
	return mat

Method, provenance and reproduction

5 October 2026. One continuation pilot: Point One → Point Coordinates, pickup and release only.

The student continues the same point. Its sphere, material and matching collider are inherited. The new lesson prints three edits: change the physics body class; add its pickup settings; reparent the existing visible surface. Full files remain available outside the lesson's reading flow.

What the test establishes

  1. incoming.gd records the assumed student state and pins its source evidence.
  2. contract.json contains exact edits printed in tutorial.md.
  3. prepare_lesson.py mechanically applies those edits. A missing or ambiguous anchor fails; no solution is filled in behind the lesson.
  4. Godot runs assembled.gd with a private copy of the actual XR Tools library.
  5. The generated output is available as the next lesson's incoming code, with an exact hash in next-input.json.

The native checks cover radii 0.14 and 0.30, a translated and rotated station, preserved geometry/material/world placement, real near-grab overlap, disabled pickup, movement of both surface and boundary, retained node/resource identity, and stationary release. They bypass hardware input with a synthetic controller. Runtime code and addon files were unchanged.

The useful failure

Point One makes the visible mesh and static collision body siblings. Merely replacing StaticBody3D with XRToolsPickable can move the boundary without its visible sphere. Omitting body.reparent(solid) compiles but fails the same behaviour contract: the body and collider move while the surface stays. This tests a causal step, not just whether code parses.

What remains an assumption

The incoming ghost is an explicit reconstruction of what Point One assumes the learner has built. Point One currently provides edits to an existing museum script, so this pilot does not yet prove that its incoming source can be produced from that lesson alone. Source material supplies the names, subdivision settings and material helper; their presence is not evidence that the student has mastered them.

An exact patch assembler cannot judge ambiguous prose. A fresh reader still needs to apply the instructions, and a learner needs to predict, explain and make a variation. The files are reproducible evidence of this bounded transition, not a certificate for the entire Coordinates tutorial or the book.
