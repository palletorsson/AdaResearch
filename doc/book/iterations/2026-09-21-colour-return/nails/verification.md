# Color_Nails: the player's own hands

Verified 2026-09-21 against the working tree. Read `commons/maps/Color_Nails/final.md` before the primary agent's editorial changes. No production files, live museum, visitor state, savegame, or bake were changed by this verification.

## Decision

**Yes: the museum's standard VR controller-hand meshes have a working nail/skin colour path.** This is not limited to the preview or the giant/petite salon hands. Both production meshes have independent receivers. A bounded isolated Godot 4.6 probe passed **35 checks, 0 failures**, including hands appearing after a colour selection and whole-hand scene replacement.

This establishes source and material/signal wiring. It does **not** establish physical headset visibility, finger tracking, controller reach, comfort, or on-device rendering. No headset was attached or tested.

## Prioritized findings

1. **The default museum rig already supplies the receivers; no receiver repair is needed for controller hands.** `commons/scenes/main_menu/MainMenu3D.gd:128` names `endless_museum_staged.tscn`. That scene inherits `base.tscn` at line 18 and contains the museum at line 26. Base mounts the production left/right hand scenes under `XROrigin3D/LeftHand/XRToolsCollisionHand/LeftHand` and its right counterpart at `base.tscn:89` and `:132`. Each hand scene contains a `PresistNailColor` child at lines 371–372. The right scene's unusual root receiver script is replaced by the actual `XRToolsHand` script in `base.tscn:133`; the child receiver remains. The hidden low-poly GhostHands (`base.tscn:92`, `:142`) are not the nail-bearing player meshes.

2. **“Tracked hands” is imprecise here.** The actual parents are `XRController3D` nodes with `left_hand` / `right_hand` trackers (`addons/godot-xr-tools/staging/scene_base.tscn:15`, `:20`). `addons/godot-xr-tools/hands/hand.gd:9` describes grip/trigger animation, and `base.tscn:137–138` sets those actions on the right hand. The traced scene chain contains no `XRHandModifier3D` or `XRHandTracker` skeleton implementation. A runtime might emulate controller actions from bare hands, but that runtime behaviour is untested. Do not present a verified bare-hand skeletal-tracking feature. An invitation to look at **your own virtual hand in the museum's standard VR controller setup** is supported.

3. **A failed station hand search does not prevent colour reaching the player.** `nail_color_controller.gd:109–147` searches one shallow relative path, then the `xr_origin` group, only once after one frame (`:43–49`). A normal stamped exhibit is below Museum/Segment; its `../../XROrigin3D` is not the staged Base's sibling origin. No group registration was found in the relevant base/staging chain. However, `_on_color_values_changed` always calls the GameManager setter before testing any hand reference (`:272–282`). Each hand receiver independently resolves its own child mesh, gets both current colours, and subscribes to GameManager (`left_hand_nails.gd:15–28`; right uses the same sequence). The probe specifically proved correct player materials while the station's direct hand references remained null. Do not treat the station's “Could not find XROrigin3D” warning alone as proof that nail colouring is broken.

4. **Whole-hand scenes added late recover current state.** Receivers wait one frame, discover named surfaces, apply the current values, then subscribe. Both hands added after selection received the chosen values. Both responded to later edits. Both received the stored values after their whole scenes were replaced. Left surfaces were nails 0 / skin 1; right surfaces were nails 1 / skin 0. Receiver selection is semantic (`Hand`, `Nails…`; `left_hand_nails.gd:30–43`, same on right), unlike the station's name-based index shortcut. Their signal callbacks explicitly reapply the active surface override (`left:121–134`, `right:121–132`). The probe also tested coexistence with the station's direct-discovery path. A mesh added **inside an already-ready receiver** is a different case: discovery is one-shot and has no retry. That hypothetical mode is not used by the packed default scenes and was not tested.

5. **Desktop has a pointer surrogate, not the player's own nail-bearing hand.** `endless_museum.gd:3596–3605` creates `DesktopHand` with `em_desktop_pointer.gd`; this is the crosshair/drag adapter, not either production hand mesh. The desktop walker and optional doll do not provide corresponding nail/skin materials. No-XR operation can change GameManager and the preview; the salon's two display hands subscribe separately (`nail_salon.gd:12–17`, `:132–138`). The existing desktop/display-hand comparison remains appropriate. A dormant base rig in a staged desktop load is not a hand the visitor visibly acts through.

6. **Persistence needs a narrow claim.** `GameManager.gd:903–919` stores colours in its autoload and emits signals, so they survive scene changes within the process. The setters do not write disk. `save_game()` includes both colours at `:932–933` and writes `user://savegame.save` at `:937`; `load_game()` restores/emits them at `:973–983`, and startup calls it at `:192–194`. Across-launch persistence therefore depends on a separate save event; selecting a colour alone does not guarantee an immediate disk save. The probe used only the literal colour fields/signals/getters/setters, with no save/load methods and no production GameManager startup.

## Probe and limitations

Run evidence: `probe_results.json`, `godot_probe.log`. Reproduction builder: `build_probe.py`; runnable script: `probe_project/receiver_probe.gd`; source fingerprints: `source_hashes.json`.

The isolated project contains unchanged production receiver and colour-controller scripts, unchanged embedded mesh/surface data from the two hand scenes, and a literal GameManager colour-only slice. To avoid production dependencies or startup writes, copied hand scenes omit XR animation roots/AnimationPlayers and use the original receiver child. The probe creates real XROrigin3D/XRController3D containers but supplies no hardware trackers; the mapper is an explicitly labelled signal fixture. It tests active material values, not visual appearance. The only two Godot warnings were the expected station discovery failures before any origin existed. No production scene importer or editor was started.

No production repair is required for the proven controller-hand path. If a separate tracked skeletal hand mode is intended, the smallest meaningful addition would attach a receiver with explicit mesh/surface references to that real tracked mesh, hydrate from GameManager on readiness, and subscribe to the same two signals; keep the salon display receivers unchanged. That future mode must be tested on the target headset before it is described as available.
