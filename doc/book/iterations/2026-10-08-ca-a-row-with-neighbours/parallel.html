A row with neighbours

Learning elements

  • Binary cell state: bool.
  • An ordered neighbourhood: left, self, right.
  • A rule as eight stored answers.
  • A synchronous update: read the old row, then replace it.
  • A wrapped boundary.
  • Current state and retained history.

At the board

We are in Endless Museum. The explorer already works. Hold its small black point and move your hand sideways: three marks follow the selected address. The point reads the row; it does not turn a cell on. Press the trigger to advance one generation. The overhead ring receives the same stored rows.

Choose Rule 90 and a single seed. Pause before stepping. Pick a cell, read its left neighbour, itself and its right neighbour, and predict its next state from the table below. The museum's side plate can check your answer. Our smaller reconstruction leaves that prediction to you.

What we carry

Trace gave us an array of positions; Grid gave those positions addresses. Arrays let us read and replace stored entries. Here each address holds a Boolean: false or true. The address stays; its state changes. We reuse the pickable sphere from the point lessons as a reader. Its hand position selects an address in the study's local frame.

Three inputs, eight answers

4 * int(left) + 2 * int(self_cell) + int(right) turns the ordered inputs into an address. int(false) is zero; int(true) is one. Compare 100 with 010: both contain one active cell, but use different entries. A count alone would lose information.

The installed explorer packs these eight answers into the number 90. We keep them as a readable list. They give the same answers; bit operations can wait.

Give every cell the same present

evolve allocates a separate next array. Its loop reads only old. The result replaces current after all addresses have received an answer. Writing directly into old would allow a freshly changed neighbour to affect a later calculation.

posmod supplies our boundary choice. With 32 cells, the left neighbour of cell 0 is cell 31; the right neighbour of 31 is 0. The calculation joins the ends even when we draw a straight row.

remember puts a copy of the current row at the front of history. This copy is an observation, not another neighbourhood. Twenty-four observations fit on the board. Older ones leave the display while the generation count continues. The newest row is at the far edge; earlier rows extend towards you. History's second dimension describes time, not a second spatial direction in the rule.

Complete row.gd

The first half defines the state and its update. make_display supplies the repeated boxes, marks and label; redraw gives those boxes the stored states. Both are included so the experiment can be reconstructed. MultiMesh is display plumbing here, not another lesson to master before understanding the rule.

extends Node3D

const PointBody = preload("point_body.gd")
const WIDTH := 32
const ROWS := 24
const SPAN := 1.6
# Inputs:                  000    001   010    011   100   101    110   111
var answers: Array[bool] = [false, true, false, true, true, false, true, false]
var seeds: Array[int] = [16]
var current: Array[bool] = []
var history: Array[Array] = []
var generation := 0
var selected := 16
var point: XRToolsPickable
var tiles := MultiMesh.new()
var reading := Label3D.new()
var marks: Array[MeshInstance3D] = []

func _ready() -> void:
    make_display()
    point = PointBody.new()
    add_child(point)
    point.action_pressed.connect(func(_body): step())
    reset()
    park_point()

func reset() -> void:
    current = []
    current.resize(WIDTH)
    current.fill(false)
    for address in seeds:
        assert(address >= 0 and address < WIDTH)
        current[address] = true
    generation = 0
    history.clear()
    remember()
    redraw()

func answer(left: bool, self_cell: bool, right: bool) -> bool:
    var index := 4 * int(left) + 2 * int(self_cell) + int(right)
    return answers[index]

func evolve(old: Array[bool]) -> Array[bool]:
    var next: Array[bool] = []
    next.resize(old.size())
    for i in range(old.size()):
        var left := old[posmod(i - 1, old.size())]
        var right := old[posmod(i + 1, old.size())]
        next[i] = answer(left, old[i], right)
    return next

func step() -> void:
    current = evolve(current)
    generation += 1
    remember()
    redraw()

func remember() -> void:
    history.push_front(current.duplicate())
    if history.size() > ROWS:
        history.pop_back()

func _physics_process(_delta: float) -> void:
    if point.held():
        var x := to_local(point.global_position).x
        selected = clampi(int(floor((x / SPAN + 0.5) * WIDTH)), 0, WIDTH - 1)
    else:
        park_point()
    show_reading()

func park_point() -> void:
    point.position = Vector3(cell_x(selected), 1.15, 0.90)

func _unhandled_key_input(event: InputEvent) -> void:
    if event is InputEventKey and event.pressed and not event.echo and event.keycode == KEY_ENTER:
        step()
        get_viewport().set_input_as_handled()

func cell_x(i: int) -> float:
    return ((i + 0.5) / WIDTH - 0.5) * SPAN

func make_display() -> void:
    tiles.transform_format = MultiMesh.TRANSFORM_3D
    tiles.use_colors = true
    tiles.instance_count = WIDTH * ROWS
    var cell := BoxMesh.new()
    cell.size = Vector3(SPAN / WIDTH * 0.94, 0.014, 1.2 / ROWS * 0.94)
    tiles.mesh = cell
    var board := MultiMeshInstance3D.new()
    board.multimesh = tiles
    var finish := StandardMaterial3D.new()
    finish.vertex_color_use_as_albedo = true
    finish.shading_mode = BaseMaterial3D.SHADING_MODE_UNSHADED
    board.material_override = finish
    add_child(board)
    for row in range(ROWS):
        for col in range(WIDTH):
            var at := Vector3(cell_x(col), 0.95, -0.6 + (row + 0.5) * 1.2 / ROWS)
            tiles.set_instance_transform(row * WIDTH + col, Transform3D(Basis.IDENTITY, at))
    reading.position = Vector3(0, 1.42, -0.66)
    reading.font_size = 30
    reading.pixel_size = 0.0017
    reading.outline_size = 4
    add_child(reading)
    for j in range(3):
        var mark := MeshInstance3D.new()
        var edge := BoxMesh.new()
        edge.size = Vector3(SPAN / WIDTH * 0.94, 0.006, 0.006)
        mark.mesh = edge
        var ink := StandardMaterial3D.new()
        ink.shading_mode = BaseMaterial3D.SHADING_MODE_UNSHADED
        ink.albedo_color = Color("ff80b4") if j == 1 else Color("ffd77d")
        mark.material_override = ink
        add_child(mark)
        marks.append(mark)

func redraw() -> void:
    tiles.visible_instance_count = history.size() * WIDTH
    for row in range(history.size()):
        for col in range(WIDTH):
            var ink := Color("87dca5") if history[row][col] else Color("243238")
            tiles.set_instance_color(row * WIDTH + col, ink)
    show_reading()

func show_reading() -> void:
    var left := posmod(selected - 1, WIDTH)
    var right := posmod(selected + 1, WIDTH)
    reading.text = "GEN %d / CELL %d\nLEFT %d   SELF %d   RIGHT %d\nMove point: inspect / trigger or Enter: STEP" % [generation, selected, int(current[left]), int(current[selected]), int(current[right])]
    for j in range(3):
        marks[j].position = Vector3(cell_x(posmod(selected + j - 1, WIDTH)), 0.963, -0.597)

Carried point_body.gd

This is the earlier pickable sphere construction, reduced to an 8.5 cm radius for this desk. The finish and desktop hooks are supplied adapters. held() accepts an XR pickup or the museum's desktop grab; release leaves the reader parked at its selected cell. The point does not collide with or edit the automaton. The complete helper is here so no prior file is silently missing.

extends XRToolsPickable
## Point Lines' frozen point construction, made smaller for the hand model.
var tint := Color("25212a")
var desktop_pointer: WeakRef

func _init() -> void:
    freeze = true
    freeze_mode = RigidBody3D.FREEZE_MODE_KINEMATIC
    release_mode = XRToolsPickable.ReleaseMode.FROZEN
    ranged_grab_method = XRToolsPickable.RangedMethod.NONE
    collision_layer = 4
    collision_mask = 0
    var surface := MeshInstance3D.new()
    var sphere := SphereMesh.new()
    sphere.radius = 0.085
    sphere.height = 0.17
    sphere.radial_segments = 24
    sphere.rings = 12
    surface.mesh = sphere
    add_child(surface)
    var boundary := CollisionShape3D.new()
    var shape := SphereShape3D.new()
    shape.radius = 0.085
    boundary.shape = shape
    add_child(boundary)

func _ready() -> void:
    super._ready()
    var finish := StandardMaterial3D.new()
    finish.albedo_color = tint
    finish.roughness = 0.24
    get_child(0).material_override = finish

func held() -> bool:
    return is_picked_up() or (desktop_pointer != null and desktop_pointer.get_ref() != null)

func on_desktop_grab(pointer: Node) -> void:
    desktop_pointer = weakref(pointer)

func on_desktop_drop(_pointer: Node) -> void:
    desktop_pointer = null

What will the next row do?

The rug is already changing. On the other side of the dividing wall, a board holds one green cell and waits. Two ways of making a pattern occupy the same hall. Begin with the one that has left you time to answer.

The board waits in the left-hand corridor near the entrance. The newest row sits along its far edge; the rest of the board is room for a past. The black point has become a reader. Hold it and move your hand sideways: three small marks pick out a cell and its two neighbours. You change which address we inspect; the row keeps its state until you ask it to step. Press STEP. One generation arrives, and the previous row moves towards you. The pink mark stays at the same address. Its state may change. The plate now reads this new generation and predicts the one that could follow it. We have advanced the local machine; the rug has kept its own time.

On the smaller CA RULES panel, between the study buttons and the board, press 90. Keep the single seed.1 STEP once, then again. Follow one of the diagonal edges. Choose CELL to move the witness along the current row, and check a neighbourhood inside the pattern as well as one at its edge. Counting the green cells is tempting. Keep their order too: left, self, right.

Three on/off states make eight possible arrangements. The rule number stores eight answers, one bit for each arrangement. Reading the selected bit gives this cell's next state.

For Rule 90, compare 100 with 010. Each contains one occupied cell. The first makes the next cell occupied; the second leaves it empty. A count would have discarded a relation that this rule uses. A neighbourhood is already a decision about what information may matter.

Press 30 on that rule panel and keep the single seed. Its rows quickly become harder to anticipate by eye. The board still asks the same small question at every position. A more tangled picture has not made the instruction longer. RUN lets the generations arrive automatically; pressing it again holds them, and STEP always leaves this study held after one update.

The update writes a separate row before making it current.

All the questions go to the old row. An answer written at the left cannot slip into the question being asked at the right. This installation builds that separation into its update step, the same under every rule number. A different update order would be another experiment to specify.

Press SEED. Two adjacent cells now occupy the starting row. The rule has stayed where you left it. Advance again and compare what happens where their consequences meet. Changing the beginning explores something that changing the rule alone could leave unseen. RST returns to the selected beginning and clears the visible history.

Keep stepping until a pattern reaches the boundary. The witness can cross it too: after cell 31 comes cell 0. The boundary rule joins the two ends. What looks like a line on the desk is a ring to the calculation. Twenty-four rows fit on this board; older rows leave the display while their consequences remain in the current state. Once again, the visible past is smaller than the past that brought us here.

Just beyond the desk, the same row hangs overhead in a ring. Step underneath and find cells 31 and 0. They stand beside each other, as close as any other pair. The end of the line was where we had cut the picture. The calculation had already joined it.

STEP changes the lowest band as well as the board. Older rows rise above it. Let RUN continue while you walk underneath: the history gathers around an opening you can look through. Height marks how many updates ago a row was current. We have given time a direction in the room; the cells still belong to a one-dimensional neighbourhood. RST leaves only the starting ring again.

The board and ring show the same held Rule 90 history. The lowest band is current; the bands above retain earlier rows.

The ring does not ask where you stand. You can feel enclosed by a neighbourhood without belonging to it. Our body receives the rule’s consequences as light; the cells still consult only other cells. That distance is also something we have built.

Across the entrance, an opening in the dividing wall leads to the rug. A detail in one quarter has partners across the cloth. Find them before naming the symmetry. The pink border and golden interior are another division to follow. Both can change, but they do not consult identical conditions.

This work has a two-dimensional grid, several states and two sets of local rules. The border and interior decide differently when activity begins, continues or fades. After calculating a generation, the program also mirrors one quarter into the others. One value is copied into three reflected positions.

The ornament has several makers: local updates, a chosen boundary, a palette, and this repeated act of copying. The mirror remains at work after the first seed. Knowing that can give us another way to enjoy the rug. We can follow a changing detail while noticing the procedure that makes its companions answer together.

The title invites an association with a textile tradition. These few operations do not account for that tradition, its materials or its makers. They produce this particular computational cloth. Its source offers other stencils and divisions to investigate later; the rug in this hall uses the mirrored quarters and frame.

Return to the board's corridor and follow it past the turmites painting a shared surface: Langton's ants, agents that move, each turning by the colour it stands on, flipping that colour and stepping off it.2 Further along, a small tangle of coloured lines waits above the floor. Approach it. Another set of lines arrives, then another. The figure unfolds over a few seconds, with time to keep an older connection in sight while new ones appear.

You are watching a saved growth history. The same fixed frame holds its twenty stages, so a line already present stays where it was. Move around it and let one apparent knot separate into lines at different depths. Some space that looked full can open when your viewpoint changes.

Its growth begins with a random walk. During a bounded burst of updates, occupied frontier positions may add a nearby cell. The drawing then connects each newly encountered position to one of its neighbours, if any neighbour has already been recorded. There is a detail worth keeping: the parent in the drawing is selected during the scan. The line does not prove which earlier cell caused the birth.

Chance proposes an addition; stored occupancy constrains where it can occur; the drawing supplies connections and colour. After twenty updates, the history stops and the whole network remains. REPLAY lets the same stages return. It repeats what was kept, rather than asking chance for another growth.

The stillness has a limit written into it. Twenty updates were allowed; the shape did not announce that every possibility was exhausted. We can enjoy its resemblance to an organic body while learning to ask what brought this particular body to rest.

We can begin to distinguish forms by the relations that sustain them. The board keeps a row and repeatedly rewrites it. The rug combines local activity with an imposed symmetry. The network retains occupied positions and draws a selected account of their connections. Their resemblance to living things can invite us closer; the code gives us further differences to explore.

Other works remain in the hall. The orb rests on the rug's edge, another is held on a low stand, and a showcase waits at the end of the passage that runs on beyond the rug's room. Past the network, a Rule 110 display stands near the corridor's far end. Let them offer further directions without asking this first encounter to explain them all.

For now, carry four choices: what a cell can hold, which neighbours it can consult, when its answer becomes available to others, and whether that answer is settled by the rule or by a draw. These choices will help us follow the variations ahead. Sometimes the rule changes; sometimes we give the same record another body. Our next comparison, the structure-growth specimen, makes the neighbourhood three-dimensional and gives disappearance more than one state. What forms need a little longer to go away?
