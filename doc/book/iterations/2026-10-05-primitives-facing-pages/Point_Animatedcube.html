Eight corners, twelve triangles

Learning elements

  • A reusable CubeBody class
  • Shared corner data
  • Two triangles per square side
  • Connectivity versus object position

In the museum

The cube appears simple enough to arrive ready-made. The diagonal study in this hall exposes a decision hidden by that familiar outline: a square surface is represented here by two triangles. Build one cube, then a second with the other diagonal on its front side.

We keep FaceBody from the preceding halls. CubeBody adds a particular set of eight positions and twelve index triples. It is the cube we can carry into Transformation and Arrays.

Make this study

Put the four printed files in one lesson folder and attach lesson.gd to an empty unit-scale Node3D named CubeStudy in the museum hall. CubeBody constructs its visible mesh itself. The placements in lesson.gd leave room between two one-metre cubes; they do not alter their local vertex data.

Create the following files together. The complete main program appears once; the remaining listings name every local code dependency. Earlier files return unchanged unless this lesson explicitly identifies a later edition.

The program

extends Node3D
const CubeBody = preload("cube_body.gd")
var first := CubeBody.new()
var second := CubeBody.new()

func _ready() -> void:
    first.position = Vector3(-0.7, 0.7, 0)
    second.position = Vector3(0.7, 0.7, 0)
    add_child(first)
    add_child(second)
    second.other_diagonal()

Dependency: cube_body.gd

extends "face_body.gd"
# Eight shared positions; each triple addresses three entries.
var points: Array[Vector3] = [
    Vector3(-0.5, 0, -0.5), Vector3(0.5, 0, -0.5),
    Vector3(0.5, 1, -0.5), Vector3(-0.5, 1, -0.5),
    Vector3(-0.5, 0, 0.5), Vector3(0.5, 0, 0.5),
    Vector3(0.5, 1, 0.5), Vector3(-0.5, 1, 0.5)]
var faces: Array[Vector3i] = [
    Vector3i(4, 7, 5), Vector3i(5, 7, 6),
    Vector3i(0, 4, 1), Vector3i(1, 4, 5),
    Vector3i(2, 6, 3), Vector3i(3, 6, 7),
    Vector3i(1, 2, 0), Vector3i(0, 2, 3),
    Vector3i(0, 3, 4), Vector3i(4, 3, 7),
    Vector3i(5, 6, 1), Vector3i(1, 6, 2)]

func _init() -> void:
    super()
    show_faces(points, faces)

func other_diagonal() -> void:
    faces[0] = Vector3i(4, 6, 5)
    faces[1] = Vector3i(4, 7, 6)
    show_faces(points, faces)

Dependency: face_body.gd

extends Node3D
## Visible triangular faces and their edges. This class adds no collision.
const LineSkin = preload("line_skin.gd")
var surface := MeshInstance3D.new()
var edges := Node3D.new()

func _init() -> void:
    add_child(surface)
    add_child(edges)
    var paper := StandardMaterial3D.new()
    paper.albedo_color = Color(0.92, 0.91, 0.87)
    paper.roughness = 0.75
    surface.material_override = paper

func show_faces(points: Array[Vector3], faces: Array[Vector3i]) -> bool:
    surface.mesh = null
    for edge in edges.get_children():
        edge.free()
    if faces.is_empty():
        return false
    for face in faces:
        for index in [face.x, face.y, face.z]:
            if index < 0 or index >= points.size():
                return false
        var a := points[face.x]
        var b := points[face.y]
        var c := points[face.z]
        if (c - a).cross(b - a).length() < 0.00001:
            return false
    var builder := SurfaceTool.new()
    builder.begin(Mesh.PRIMITIVE_TRIANGLES)
    for face in faces:
        var a := points[face.x]
        var b := points[face.y]
        var c := points[face.z]
        # Godot's front faces use clockwise winding.
        var normal := (c - a).cross(b - a).normalized()
        for point in [a, b, c]:
            builder.set_normal(normal)
            builder.add_vertex(point)
        for pair in [[a, b], [b, c], [c, a]]:
            var edge := LineSkin.new()
            edge.material_override.albedo_color = Color(0.04, 0.04, 0.045)
            edges.add_child(edge)
            var difference: Vector3 = pair[1] - pair[0]
            edge.show_segment(pair[0], difference, difference.length())
    surface.mesh = builder.commit()
    return true

Dependency: line_skin.gd

# Supplied renderer, adapted from commons/primitives/line/line.gd.
# This finite cylinder gives the segment a visible thickness. It is not a collider.
# Inputs share the parent station's local frame; that station has unit scale.
extends MeshInstance3D

func _init() -> void:
    var cylinder := CylinderMesh.new()
    cylinder.top_radius = 0.012
    cylinder.bottom_radius = 0.012
    cylinder.radial_segments = 16
    cylinder.rings = 0
    mesh = cylinder
    var finish := StandardMaterial3D.new()
    finish.albedo_color = Color(0.98, 0.70, 0.82)
    finish.roughness = 0.3
    material_override = finish
    visible = false

func show_segment(start: Vector3, displacement: Vector3, distance: float) -> void:
    # A zero-length segment has no direction. Do not normalize it.
    visible = distance > 0.0001
    if not visible:
        return
    (mesh as CylinderMesh).height = distance
    position = start + displacement * 0.5
    # CylinderMesh runs along local Y. This borrowed basis aligns it to the ends.
    var direction := displacement / distance
    var right := direction.cross(Vector3.UP).normalized()
    if right.length() < 0.001:
        right = Vector3.RIGHT
    var depth := right.cross(direction).normalized()
    basis = Basis(right, direction, depth)

Read the construction

CubeBody extends FaceBody, so it inherits the face renderer. Its _init() first calls super() to attach the parent's surface and edge container, then calls the renderer with this cube's recipe. Each call to CubeBody.new() creates a new object with its own position array, face array and mesh.

The corners use x and z values of −0.5 or 0.5 and y values of zero or one. The first two triples cover the positive-z side. other_diagonal() changes those two triples, keeping the four corner positions fixed. The black internal line moves to the other diagonal; the square's boundary and area stay the same.

Node position and vertex position do different jobs. second.position places the whole cube in the study. second.points[6] += Vector3(0, 0, 0.35) changes one local corner; call second.show_faces(second.points, second.faces) afterward to redraw it. Every face using entry six changes. A formerly square side can become two angled planes, making the diagonal matter to the surface itself.

These cubes have visible edges and faces, without colliders. The wider prefab collection in the museum remains available for reflection; it is not another construction dependency.

Make it your own

Make a third CubeBody and place it somewhere else. Change one corner on that instance and redraw it. Verify that the first two cubes keep their shapes. Then explain the difference between moving a body and editing the data from which it is made.

Keep CubeBody. The next hall asks whether a short rule can generate a position list that we have so far written out.

Source and scope

The runnable study is a small reconstruction in the existing Endless Museum. The hall contains additional artifacts; this lesson does not reproduce their complete runtime. Camera, light, player and XR Tools are declared museum infrastructure. Local geometry is generated by the printed files.

Godot documents clockwise front faces and ordered vertex submission in SurfaceTool.

Cube Assembly from Primitives

You have been inside boxes since the first room. Now one of them lets you take hold of a corner. What must stay in place for it to remain a cube?

Begin with the outline. Follow the three edges leaving one corner. Look through to the far side. You can recognise a cube before any faces have appeared, although nothing has yet closed the gaps between these lines.

The previous room gave us forms that could support a foot or interrupt a route. Here we return to their construction. What happens when the parts remain connected but their positions change?

The builder may have finished before you arrive. Press REPLAY on its front instrument. Corners appear, then edges, then triangular patches. Press PAUSE at the moment you recognise the shape. How much did you need to see?

Only this assembly pauses. The folding net and the rest of the room continue. We have borrowed a little attention from a world already running.

The source has prepared the geometry before this presentation begins. The animation reveals pieces that were hidden. What looks like construction is also an arrangement of when we are allowed to see.

Resume. Once the assembly finishes, the numbered corner handles become available. Keep the second builder unchanged as a reference. On the one you will alter, find v6. Follow the square face containing v4, v5, v6 and v7. Predict what will happen if you pull v6 out of that face's plane, leaving its other corners where they are.

Move it a little. Look along the face. Where did the crease appear?

Try to locate the seam before pressing DIAGONALS. The yellow lines show the six diagonals that divide the cube's square faces into triangle pairs. Your hand has made one of those divisions matter.1

That face is stored as two triples:

[4, 5, 7]
[5, 6, 7]

Each number names a vertex. Both triples contain 5 and 7: their shared edge. Only the second contains 6. When you move that corner, the second triangle tilts while the first stays in place. A face that appeared to be one flat square can now bend along a choice made in its construction.

The diagonal was already there. Corners 4, 5 and 7 stay still. Moving corner 6 makes the shared edge into a crease.

The builder reads a moved handle back into its position list:

vertices[i] = handle_nodes[i].position / cube_size

The edge and triangle lists still refer to the same vertex numbers. The neighbours remain; equal lengths, right angles and flat square faces need not.2 The display measures the largest corner shift in local metres. It cannot tell us what the changed form is worth.

Release the handle and press REPLAY. The layers return around your altered shape. Then try RESTORE CUBE. This time the initial corner positions return too. Repeating a presentation and undoing a change are different ways of beginning again.

Compare the two builders. Name one property your alteration preserved and one it lost. You can keep a crease you like without claiming the result is still a cube.

Further on, six squares wait in the air. Follow the pink one as the net folds. Predict which faces will meet. The last flap closes. The cube shrinks, then drops to the floor.

It stays there for a moment, as though it needs to think. Above it, another net opens. The first cube remains. Each return leaves something behind; the floor begins to hold a collection.

Here each square stays rigid. The hinges turn. In the builder, you moved a corner and bent a square into two differently tilted triangles. Similar-looking movement can come from different operations. Knowing which data changes helps you predict what a form can do.

Now look down at the floor, then along a wall. Find the box form again in the crates. The museum builds its floor slabs and wall blocks from scaled box meshes. The primitive on display has also been carrying us from room to room.

The initial cube pairs twelve triangle patches into six square faces.3 The crates add geometry for planks and reinforcing strips. We can recognise the box across these different meshes.

You can move a corner on the instrument while the museum's boxes support and redirect your body. What we are learning to inspect is also the place from which we inspect it.

The shelf holds twenty-four pickable copies: cardboard boxes, crates, cargo boxes and printed cartons, followed by variations. Take two copies from one family to the worktable. Moving one leaves the other where it was. Give them a neighbour, leave a gap, or begin a stack. A scene can supply the same made object again; the relation between its copies is yours to arrange. Across the aisle, the conveyor will ask you to follow a matching rule.

A net folds above a conveyor belt. The closed cube drops onto the moving surface. Passing under the printer, it receives one of two editions: cream and red AGAIN, or mint and teal YET. The shape stays the same. Its surface now asks for a choice.

These are prefabs: reusable objects stored as scenes. A placed copy is an instance. The printed carton supplies the basket's sample. Each moving delivery has the same cube geometry and pickup behaviour; two shared textures give it the familiar carton editions. The lettering and stripes arrive together, carrying decisions someone has already made. We can begin with a furnished object before knowing how to build each of its parts.

Take an AGAIN cube from the belt and release it into the AGAIN basket. It shrinks inside. The YET basket receives the other edition. Moving one copy leaves the others carrying on along the belt.

There is pleasure in finding it again: a familiar shape, an interval kept, a difference small enough to search for. A crate can belong to the scenery of many games before it belongs to this room. Its familiarity travels with it.

Warhol's Brillo Boxes bring another kind of repetition here. His 1964 sculptures were fabricated plywood boxes, painted and screenprinted with commercial packaging imagery. Their exhibition arrangement recalled a warehouse.4 Work had gone into making something whose appearance was already familiar. Our printed carton is an original design, but it borrows that tension between an ordinary package and an object given our attention.

Let one pass. At the end of the conveyor it falls onto the floor. Let more pass and the copies begin to pile up, keeping the angles at which they land. Neither edition gets a side of its own. They remain available to your hands, but the line keeps adding another task. The round ends when the room fills; the controls let you pause production or start again.

Look between the small cubes in the baskets and the growing pile on the floor. The arrangement records what you sorted and what you left.

Read the cartons: A WORLD / WITHOUT / COMPOSITION. The supply pile and the stamped crate add YET.

A world without composition yet. There was already an arrangement around us. Between the table, the belt, the baskets and the floor, another has begun. We have borrowed its parts, and made a relation between them.

Take the crease with you: a small movement exposed a decision inside a familiar shape.

The boxes offered a made object we could use again. The next room offers a rule for making a family of objects: choose how many divisions, and the engine constructs the surface. We have followed a corner through a mesh. Now we can inspect what the engine chooses when we ask it for a sphere.

  1. Godot Engine 4.6, Using the ArrayMesh, rectangle example: four positions are connected by two triangle triples. This builder submits its patches through SurfaceTool in triangle mode. A flat convex quadrilateral admits either diagonal; moving a corner out of its plane can make that choice visible as a different crease. ↩

  2. Connectivity names which vertices, edges and faces are incident; their positions place that structure in space. Compare the separate point and connectivity properties in Botsch, Sieger, Moeller and Fabri's Surface Mesh manual, CGAL 6.2.1, “Connectivity” and “Properties.” Here the index lists preserve the combinatorial structure, but moving vertices may produce crossings or collapsed faces, so a valid geometric embedding is not guaranteed. The builder's patches also lack enclosing collision geometry; its handles have pickup colliders. See the technical chapter. ↩

  3. Euler's Elementa doctrinae solidorum (1758) investigates polyhedral counts. For the initial cube, V - E + F = 8 - 12 + 6 = 2. Splitting its squares adds six diagonals and six faces: 8 - 18 + 12 = 2 again. A proof for the sphere's triangulation appears in Heinz Hopf's Selected Chapters of Geometry, §I.3, from his 1940 lectures reconstructed and translated by Hans Samelson. The equality does not certify cube shape or a valid embedding. The instrument counts twelve patches, excluding reverse rendering copies. ↩

  4. The Andy Warhol Museum, Brillo: Is It Art?, on the fabrication and 1964 Stable Gallery exhibition. These were constructed sculptures carrying packaging imagery. The library’s AGAIN carton is a new design for this encounter. ↩
