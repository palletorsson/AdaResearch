# Machine Learning — what the sphere carries

The eight halls now hold together as a sequence. The first half makes different ways of changing a model visible; the second gives the visitor responsibility for examples, timing, variation and checking. The familiar sphere helps us recognise the continuation, but its role changes. Sometimes it controls a process, sometimes it selects parameters, sometimes it queries a model, and later it responds to our hands. Calling all of these “the sphere learning” would conceal the actual lesson.

## Read the progression

| Hall | One new operation | What the student can demonstrate | Reflective question |
| --- | --- | --- | --- |
| Evolution | Inherit traits under finite or renewing resources | Repeat one opening seed and explain different births, deaths and resource histories | What selects when there is no explicit ranking? |
| Gradient Landscape | Change a line's parameters using the slope of a chosen loss | Predict a step; compare MSE and Huber on the same altered observation | What does our score make consequential? |
| Classification | Alternate assigning points and moving group centres | Move an initial centre, separate ASSIGN from MEANS, and challenge the grouping with rings | When does a computed group acquire a name? |
| Neural Networks | Fit thirteen parameters in a complete small network | Separate forward inference from training; change labels and check the derivatives | What have we placed inside the answer before learning begins? |
| Perception | Teach three labels from six hand coordinates | Collect examples, fit, then try fresh poses before enabling an authored response | What can these coordinates say about a gesture—and what cannot they say? |
| Sequence Memory | Retain the order of both hands through time | Teach ONE and A/B phrases; test reversal, unknown and ambiguous outcomes | What is kept when a movement becomes a recorded phrase? |
| Generative | Fit and sample variation across complete paired takes | Compare SOURCE, MEAN and DRAW; repeat a seed and change the teaching examples | What distinguishes a recording from a possibility made from recordings? |
| Synthesis | Join a declared intention to a fresh result without training on it | Keep agreements, mismatches, refusals and model versions in a local journal | Who gets to say that the response was the intended one? |

This builds on positions, arrays, transformations, randomness and the earlier point class. It does not need more algorithms to become coherent. Evolution is an environmental selection study; the later halls implement several different learning procedures. The route is an inquiry through those differences, not a claim that they are all one universal learner.

## What carries, precisely

The first four halls carry an unchanged PointBody class. Each starts its own model state. Evolution's population does not become Gradient's observations; Gradient's two parameters do not become the network's thirteen weights.

Perception explicitly revises the sphere for the hand study: a larger radius, museum interaction collision mask and a host-supplied finish. It omits the earlier desktop grab adapter. Its six-input, three-output network is also a new model; it does not load the small network's weights. The last four halls inherit that revised sphere and the capture/display code. A live sphere node is not transported between hall loads.

The saved-data route forks at Sequence Memory:

- **ONE → Generative.** Save one family of paired performances. Generative imports the recordings, then FIT constructs the generator. A sample never silently becomes a teaching observation.
- **A/B → Synthesis.** Save the two phrase classes separately before leaving Memory. Synthesis imports that library, not the generator's ONE file. A generated variation can prompt another performance, but the person must choose to record and teach it.

Each take retains timestamps and both hands' six coordinates. These are coordinates in the supplied hand-capture reference frame, not unlabelled world positions. The printed capture function and its timing policy remain shared. The new cross-hall test saves and reloads the actual formats rather than reconstructing equivalent data separately in each lesson.

## Reconstruction evidence

**372 Godot assertions pass across the eight freshly reconstructed printed lessons.** Each extracted file matches the corresponding working study. The first four copies of PointBody match one another; the last four match the explicitly revised Perception class.

**18 additional cross-hall checks pass.** Memory saves real ONE and A/B files; the later printed classes read them, generate a repeatable variation and record a fresh A/B check. The files remain byte-for-byte unchanged by those later operations. Wrong-branch imports are refused without erasing the current model. JSON conversion produces a maximum observed numerical difference of about 4.44 × 10⁻¹⁶; the test requires less than 10⁻¹², with labels and structure exact. Live data after import must remain exactly unchanged during generation and checking.

These handoff tests use private fixture paths. Memory's save and Generative's import are exercised through their printed component APIs; Generative's FIT/DRAW/NEXT and Synthesis's IMPORT/EXPORT use real button signals. No visitor save file is overwritten. The timestamps, hand trajectories and declared intentions in these tests are synthetic.

The report also retains **137 museum checks** from the eight hall probes. Gradient's 17 checks and images were rerun after its position fix. Evolution's 18 and Networks' 25 were rerun after external feedback; five other sets are retained from their individual hall passes, not claimed as new whole-world tests. Museum checks include camera, placement and interaction checks; they are not 137 independent learning outcomes.

This is **author-informed reconstruction**, not a blind independent ghost student. It establishes executable examples and specific behaviour. It does not establish human learning, physical comfort, recognition accuracy on diverse performers or the artistic worth of a generated movement.

## Where density still needs care

Memory now explicitly names two visits within the same hall. It remains the busiest transition: timestamps, interpolation, whole-take validation and two-class comparison meet in one hall. Teach it as two visits within the same space: first one phrase kept and replayed, then two phrases distinguished. Both remain in the complete chapter; neither requires another hall or another rebuilt sphere.

In every chapter, read the new model operation first and the host that connects it to the museum second. The full runnable code remains printed. Later host files deliberately reuse the earlier capture and sphere code; reading them should not become a second lesson about setting up XR.

The existing GAN and large network displays are comparison exhibits, not evidence that the printed learner implements those systems. The neural-network exhibit's answer-bearing inputs remain disclosed. Some legacy exhibits still exceed their room footprint; Fine Tuning was absent from the isolated Networks render. The whole-route pass does not turn those observations into verified spatial repairs.

The next useful review is to walk the route with a headset and let another reader reconstruct it from this bundle. Synthesis now introduces a concrete transition toward the language models used to write Ada, using the Gradient testing defect. That wider discussion still needs development in Foundations Crisis: these small, inspectable learners offer useful distinctions, but they do not by themselves explain that production system.
