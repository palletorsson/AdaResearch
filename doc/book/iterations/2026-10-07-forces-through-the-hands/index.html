Shared interaction language

Hands first. Controls within reach.

  1. Grab, pull, push, swing, aim and release operate the actual object. A button labelled PULL FOOT is a candidate for a removable foot.
  2. Use a constrained grab or bounded force tether for a jointed handle. Ordinary pose-snapping pickup must not drag the hinge anchor through the room.
  3. Put reset, comparison and display controls on the existing off-hand interface, or beside the working hand. Show which experiment they control; never reset unrelated bodies.
  4. Keep triggers for powered actions such as thrust or firing. A held object owns its action so the absorbed catalyst does not fire at the same time.
  5. Offer one readable trial and a way to escalate it with more bodies, a blocked exit or another constraint. Keep one causal question visible.
  6. Let misses, fallen bodies and overflow remain. Explicit reset restores the apparatus; lost-body recovery and finite spawn limits are disclosed.
  7. Use colour from the earlier sequence for consistent roles: source, receiver and trace. Label them as well. Do not communicate force only through colour.
  8. Use vectors sampled from the actual receiver model. Distinguish force, acceleration, velocity, displacement and display length; a trail records where a body went, not the field itself.
  9. Entry events release or remove a physical condition once per trial. Subsequent collisions and collapse come from simulation, not a scripted failure animation.
  10. A headset has no sustained weight feedback. Show mass through response to an equal applied force; do not promise the hand will feel simulated kilograms.

The interface is part of the experiment: holding the gate closed should mean holding the gate. Extra controls should help compare a result, not impersonate the action the player came to perform.

Order of work, not new hall order

Make the target rig work first.

It tests the whole promise in a small space: a familiar point, a hand action, motion transferred to another body, a hinge, a basket and a recoverable consequence.

  1. Target rig: familiar point, hand action, cube pin, hinged plate, basket, physical release and local reset. Establish the reusable interaction contract here.
  2. Spring and support: replace proxy buttons with constrained grabs and a removable support. Add one causal arrival event and retain the aftermath.
  3. Walk-in swirl: share the sampled rule with visible vectors, dynamic points and a declared player adapter; show actual trails.
  4. Flight and launch: make the existing spheres easy to find, reuse the shared hand controls, then replace mortar angle buttons with direct aiming.
  5. Bring the remaining halls onto the same interaction conventions. Write/retest each full tutorial only against the working primary object.
What an upgrade must pass
  • The visitor can discover and perform the main action without walking to a remote control panel.
  • Actual XR pickup/release and action dispatch are tested, including a hand already holding an object. No double firing or competing grab ownership.
  • Each lesson has one independent prediction/change/assertion. The displayed quantity comes from the same code/state as the physical receiver.
