# Subject register: first use, usable introduction and deeper study

3 October 2026. Proposed curriculum through Randomness; teaching locations are not completion claims.

**Current writing process:** first correct the one-paragraph [tutorial storyboards](../TUTORIAL_STORYBOARDS.md) with Palle, then reconcile this register with the agreed learning progression. The register is supporting planning data, not authority to expand an unapproved lesson. Existing museum material does not make every implementation detail a teaching subject.

Authored decisions: [subject_lineage.json](subject_lineage.json). Existing token/word taxonomy: [taxonomy.json](../taxonomy.json). Observed tutorial-code occurrences and a disposition for every existing taxonomy entry: [taxonomy_use_index.json](taxonomy_use_index.json).

## How to read this

- Scope: the first ten sequences, through Randomness, plus named later returns. The rest of the 25-sequence taxonomy remains indexed but is not assigned an invented new map order.
- Encountered, supplied, introduced, reused and deepened are different states. Only an introduction with a named learner action counts as a teaching prerequisite.
- Small introductions are allowed before the sequence named after the subject. Sine in Transformation and bounded random variation in Array are intentional teaching, not forbidden premature vocabulary.
- Every deeper return names the extra capability: a range-and-period introduction to sine is not yet a lesson on phase relationships, waves or audio sampling.
- Planned uses select tutorial operations. Museum-only artifacts and final.md references need not be exhaustively taught or listed as student coding requirements.
- All subject locations are proposed. Current code-token occurrences are recorded separately and never promoted automatically into taught status.
- Exact API tokens, supplied interfaces and numeric lesson locations must be checked when the individual tutorial is written; grouping APIs under a subject does not license unexplained code.
- A subject can recur under a different contract: a Vector3 can hold position, displacement, velocity or force, and those meanings must not be collapsed.
- Lesson objects are created in code and kept through direct variable references. No dollar references or other node-path lookups to named scene children. Day Zero may supply explicitly named viewing and input context.
- One prepared Ada XR world is the shared course context. Portable desktop studies are allowed; each lesson declares its environment and input dependencies. Day Zero owns setup. The compact starter is packaged with desktop and simulated-controller checks; physical headset and Quest export verification remain pending.

A usable introduction is a small contract: what the operation receives, returns or changes, and one variation the learner can deliberately make. Deeper study adds a named capability; it does not invalidate the earlier use. The provided renderer or input device remains distinct from the operation taught.

The register uses stable map names. The existing taxonomy's numeric section locations continue to describe the older functional draft. Promote locations into that checker only as each rewritten lesson, its signature and its runnable example are revised together. The checker has not been changed to enforce this new plan.

## The two immediate examples

**Sine in Trans_Pre:** use elapsed time to obtain a smooth value between -1 and 1; change the extent and duration of a repeating height. With a positive period, `height = centre + amplitude * sin(TAU * elapsed / period)`. Name each input and the output; show one cycle. Circle geometry, phase relationships, sampled waves and sound are later developments. Sine's behaviour is introduced; its implementation is borrowed.

**Random draws in Array:** generate a bounded offset for a copy; keep the address and the copy. Change the range and compare. A small local generator and resettable seed make a repeatable comparison possible. Generator state, request order, distributions, estimation and feedback become the Randomness sequence's work. Do not call random results unique or balanced by guarantee.

## What the taxonomy should enforce

1. A lesson may require only a named capability already introduced, introduced earlier within that lesson, or provided through an explicit supplied interface.
2. An early use must teach enough to make a deliberate change. Merely showing a control or naming sine/randomness is not that introduction.
3. A deeper return states what becomes newly possible. It should not restart the definition or imply that earlier use was illegitimate.
4. The same data type can have different meanings. Vector3 position, displacement, velocity and force have different contracts and units.
5. A lexical token match is evidence to inspect, never proof that a subject is taught. A passing code check cannot certify the student's understanding.
6. The hard teaching dependencies apply to tutorial tasks and executable examples. They do not ban a critical word or museum artifact from appearing before its construction lesson.
7. Unmapped prerequisites remain unresolved until an editor chooses a small introduction, a supplied interface, a later return or a local order change.

Regenerate observations and tables with `python doc/book/course/sketch/build_subject_register.py` after editing the authored JSON or the tutorials. The script validates references, prerequisite order and cycles; it does not invent a curriculum or update the legacy checker.
