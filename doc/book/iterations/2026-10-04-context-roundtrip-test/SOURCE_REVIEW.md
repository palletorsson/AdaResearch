# Frozen-source review

Scope: only `manifest.json` and its thirteen frozen `snapshot/` files; all SHA-256 hashes match. Citations below are relative to `snapshot/`. Functions and placement data were inspected; no runtime, headset traversal, external references or other repository files were inspected. This establishes source mechanisms and proposed teaching, not learner outcomes.

- **Supported — the existing frame counter is selected starting material.** `doc/book/course/storyboards/opening.json:9-29` explicitly supplies the existing counter, player and room. `commons/maps/Point_Zero/map_data.json:568` places it. `_ready()` records an arrival frame; `_process()` updates the count through `_count()` (`commons/visualaid/frame_counter/frame_counter_display.gd:133-137,346-375`). The older creation exercise in `doc/book/course/sketch/SUBJECT_REGISTER.md:42-46` is planning material, not an override: `doc/book/course/storyboards/BRIEF.md:11,37` explicitly qualifies older host instructions.

- **Refuted — release necessarily saves only the latest held stroke.** The drop handler passes the entire `_trail_points` list and clears it only when `auto_clear_on_drop` is enabled; its script default is false (`commons/primitives/point/draw_dot.gd:27,631-642`). `add_trace()` duplicates lists with at least two points (`commons/globals/trace_data.gd:27-33`). Records can therefore span pickups. Accepted samples are shaped, duplicate-filtered and bounded, so “cumulative” does not mean every original hand position (`commons/primitives/point/draw_dot.gd:458-490,752-775`). Trace placements specify different resolutions (`commons/maps/Point_Trace/map_data.json:9`). Scene overrides beyond the snapshot remain unverified.

- **Refuted — Grid rounds original world coordinates before fitting.** `_display_frame()` computes bounds, centre and scale; the pink mesh uses `(p-center)*scale`; the green shadow snaps that transformed value in XYZ (`commons/primitives/line/grid_lines.gd:113-157,165-178`). Its retained source copy is separate (`commons/primitives/line/grid_lines.gd:346-351`). “Source” here means the pen's accepted record, already potentially projected or quantized.

- **Refuted — rounding can recover arbitrary original positions by inversion.** Snapping is many-to-one; adjacent snapped duplicates are also discarded (`commons/primitives/line/grid_lines.gd:169-178`). Multiplying an address by spacing produces a lattice position, not lost within-cell detail. `commons/maps/Point_Line_Grid/final.md:18-24` explicitly describes multiple positions sharing a result. Interpret “reversing the earlier mapping” in `doc/book/course/sketch/SUBJECT_REGISTER.md:64` as constructing positions from indices, not recovering arbitrary inputs.

- **Refuted as a guarantee — all saved traces survive project restart.** The shown store starts with an empty array, appends copies, and exposes clearing; its complete implementation contains no disk serialization or reload (`commons/globals/trace_data.gd:1-65`). The summary explicitly excludes restart persistence (`doc/book/course/storyboards/opening.json:158`). Unseen project-wide persistence is **unknown**.

- **Supported — the selected path contains session trace retention.** `TraceData` is an autoload (`project.godot:44`); release writes it, and Grid subscribes to additions and reads existing traces (`commons/primitives/point/draw_dot.gd:631-634`; `commons/primitives/line/grid_lines.gd:89-111`). Grid's table keeps ten recent records (`commons/primitives/line/grid_lines.gd:354-356`); that does not cap the global store.

**Consequences:** At map level, Grid should distinguish list index, fitted display address and retained source values (`doc/book/course/storyboards/opening.json:139-161`). At sequence level, preserve Lines → Trace → Grid's segment/list/address progression; Array explicitly reuses Trace's list and traversal (`doc/book/course/storyboards/opening.json:85-161`; `doc/book/course/storyboards/early.json:187-193`). At project level, keep proposed prerequisites separate from implemented encounters and revise summaries rather than code (`doc/book/course/storyboards/BRIEF.md:27-33`).

**Unresolved teaching decision:** Where should the learner's reduced construction run within the existing museum? The brief requires this choice; Point One leaves it open (`doc/book/course/storyboards/BRIEF.md:11`; `doc/book/course/storyboards/opening.json:53-55`). Actual VR transfer, legibility, beginner understanding and pedagogical effectiveness remain **unknown**; artifact presence and code vocabulary do not establish taught capability (`doc/book/course/sketch/SUBJECT_REGISTER.md:12-20`).
