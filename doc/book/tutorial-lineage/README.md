# Tutorial lineage atlas

Editable curriculum design lives in curriculum.json. It maps transferable capabilities, not an equal lesson quota per hall. Requires edges mean a capability must be taught or explicitly supplied before the proposed making task. A primary parent draws the tree; further requirements remain visible as cross-connections. Encounter order comes from the active spine, never from old sequence notes.

Run python tools/build_tutorial_lineage.py to refresh the readable atlas, source snapshots and inventory. Output: doc/book/iterations/2026-09-29-tutorial-lineage/index.html.

All 25 active spine sequences and their current halls are included. Auxiliary sequences outside the active spine are listed separately as unmapped extensions. The atlas does not claim a complete catalogue of every project artifact or a verified tutorial for every hall.

Capability descriptions are editorial proposals grounded in current tutorial/technical/intent/manuscript sources. File availability, source excerpts and fingerprints are measured; tutorial adequacy is not inferred from length or code-block count. Missing tutorial.md does not mean the room has no content. Sources can disagree; the selected issue records identify known discrepancies without silently resolving them.

Kinds: build = add a transferable operation; borrow = use a named supplied system; compare = vary an existing operation; reflect = return critically without compulsory new code. These roles may coexist within a hall.
