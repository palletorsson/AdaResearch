# An array becomes a condition of passage

**Proposed home: a return at the end of Array / Tutorial_3D.** It follows the existing distinction between an address and its occupant. The earlier changing floor asks what remains underfoot when occupancy changes. This study keeps the floor and all forty-nine fragments, then changes which heights belong to which addresses.

| Earlier capacity | Used here | New consequence |
|---|---|---|
| Point One | Appearance and collision can differ | Seeing through the field does not establish a walking route |
| Coordinates | Retain each horizontal address | Change height without changing identity |
| Transformation / Body | Translate a part; declare the visitor's extent | Clearance belongs to an object-body relation |
| Array | Two indices select one place | A local yes/no choice affects a continuous route |
| Tiling | A small rule repeats across addresses | Equal counts can arrange very different passages |
| Later: Randomness | Reassign the same retained values | Shuffle a height inventory without calling the result more free |

The first exercise needs coordinates, translation, array indexing and an equality condition. The complete mesh and collision setup is borrowed. The modulo comparison is a second exercise, not a prerequisite for changing the straight passage. Graph search is validation apparatus here; it is not silently added to the learner's workload.

The critical text stays with seeing, passing and what the material reference can carry. The tutorial authors a selection rule. The room lets a declared body try that rule. Their connection is an observable consequence, not a requirement that each repeat the whole explanation.

This is a standalone desktop companion. It adds no active hall, map token, curriculum node or `final.md` passage. A future installation needs its own bay with a usable perimeter and an ordinary route to the next hall; it should not turn an inaccessible artwork into a blocked museum exit.
