# Choice and release: canonical rack input

20 September 2026. A focused reference joins `interactable_demo` through `release_reference = true` or `commons/interactables/interactable_release_demo.tscn`.

## What works

- `RackSliderStepped` now handles press/drag and quantizes the stored and emitted value, not just its drawing. Both endpoints are included. Programmatic assignment, pointer input and changing the step count agree. Releasing or leaving the panel preserves the choice.
- `RackSliderBipolar` now handles press/drag. Its existing normalized 0–1 API remains intact; `get_signed_value()` exposes -1–+1. The default `return_to_center = true` implements its previously advertised centre return. Release/exit resets immediately to normalized 0.5. This is a control contract, not a spring physics simulation. Set `return_to_center = false` for a retained signed setting.
- `ModuleFaceTexture` accepts the return option in control definitions and confines an active drag to its initiating pointer. Another hand cannot move or cancel it.
- `RackControlBase._ready()` preserves larger configured cell dimensions; previously it silently replaced them with the canonical minimum. Unconfigured controls retain their canonical dimensions. Custom dimensions smaller than the minimum are still constrained.
- Both sliders have clear value windows, visible notches/zero and printed release behaviour. The new reference has a case and pedestal. All its text is 2D rendered on its panel. Three aligned coloured receivers show the actual values.

## Evidence

Run `python doc/reports/interfaces-2026-09-20/rack-input-pilot/run.py`.

`checks.json` records 43 passing checks. Unlike the original method-only census probe, this test sends `XRToolsPointerEvent` messages through the panel's collision-body forwarding method, into `SubViewport.push_input`, through GUI hit-testing and `Control._gui_input`, and on to the receiver via `value_changed`. It checks all five choices, between-notch input, release, exit, competing pointers, a translated/rotated/scaled assembly, and continuous-slider regression. Hit coordinates are generated by the test; this is not a headset ray/grab test.

`held.png` and `released.png` are real Godot Mobile renderer captures with the same camera. Choice is 5/5, the retained setting is -0.5, and only the blue command changes from +1 while held to 0 after release. These are two interaction states, not before/after migration images. The original census evidence is left unchanged.

Known startup warnings for the unrelated resource UID and Windows certificate store remain in the log. The completed run exited 0 with no script errors. Headset comfort, tracked hands, visual acuity and Quest performance are not established by these checks.

## Integration boundary and next work

The shared 2D components and `ModuleFaceTexture` route are implemented. The ordinary 3D physical `slider_snap`/`slider_zero` scenes remain separate and unchanged. The standalone `VRRackControl` wrapper currently renders a chassis/screen but has no pointer collision/forwarding of its own; repairing the inner control does not make that wrapper interactive. It is the next integration task, including its `ArtifactControls` consumers and layout/label findings. Review retained versus returning intent per consumer before wider adoption, especially audio settings such as mix/drive.

No museum placement, sequence or manuscript was changed. This adds a reproducible reference to the existing demo, without replacing the larger sampler. The live museum and concurrent review evidence remain untouched.
