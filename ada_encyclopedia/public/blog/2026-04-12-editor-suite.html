The Editor Suite

Seven geometry editors. One base class. Each one is a split-view application: parameter sliders on the left, live 3D preview on the right. Drag to orbit. Scroll to zoom. Move a slider, the mesh rebuilds in 150 milliseconds. Save presets. Load them back. The pattern is always the same. The geometry is always different.

Every procedural generator in the project now has a face. You can see what it does by moving a slider, not by reading code.

A new editor is about 80 lines of code. Define your parameter groups — name, min, max, step, default for each slider. Implement _rebuild() — read the parameters, generate geometry, add it to the viewport. That is the entire contract. The base class handles the viewport, the camera, the sliders, the throttle, the presets, and the auto-rotation.

The Slider as Research Tool

A slider is not a user interface element. A slider is a hypothesis. When you drag the twist parameter from 0 to 360 degrees on a tapered cylinder, you are asking: what happens when rotation accumulates along an axis? The answer is a drill bit. Drag further to 720 and it becomes a spring. The mesh shows you what the math does before you understand why.

The five math surfaces in the sine editor make this explicit. A Möbius strip with 1 twist is a standard topology exercise. With 3 twists it becomes something else entirely — a surface that wraps around itself in ways that have no name in the textbook. The slider lets you find the transition. Where does 1 twist become 2? What happens at 1.5? The continuous parameter reveals what the integer cases hide.

The Architecture Pattern

Every editor follows the same lifecycle:

1. Define — PARAMETER_GROUPS lists every slider with ID, label, range, step, default.

2. Build — Base class creates the UI: sliders, viewport, camera, presets. No code needed.

3. React — Slider moves → base sets _needs_rebuild = true → 150ms throttle → calls _rebuild().

4. Rebuild — Subclass reads p("param_id"), generates mesh, adds to content_root. 80 lines typical.

5. Persist — Save button stores all params as JSON. Load restores. Presets survive sessions.

The scene file for each editor is 9 lines of markup. An HSplitContainer with a script attached. Everything else is built at runtime. This means adding a new editor takes 10 minutes: define parameters, write _rebuild(), create a 9-line .tscn. The base class is 417 lines that never need to change.

What Each Editor Teaches

The editors are not just tools. They are teaching instruments. Each one exposes a different principle of computational geometry:

Mesh Modifier — Composition is not commutative. Taper-then-twist produces a tornado. Twist-then-taper produces a drill. Same operations, different order, different form.

Pipeline — Form is layered. Skeleton before surface. Surface before modifier. Modifier before instancing. The order IS the architecture.

Glass Tubes — Swept surfaces follow Frenet-Serret frames. A tube is a circle moving along a curve, maintaining its perpendicularity through curvature and torsion.

Math Surfaces — Topology is independent of geometry. A Möbius strip has one side regardless of how thick or twisted you make it. The slider changes the geometry but never the topology — until it does (Klein bottle).

Floor Patterns — Tiling is constraint satisfaction. Each pattern solves the same problem (cover a plane without gaps) with different symmetry groups. The transitions between them are discontinuous — you cannot continuously deform a herringbone into a honeycomb.

Sculpture — Implicit surfaces (SDFs) define form as a boundary. The mesh is not stored — it is computed as the zero-crossing of a distance function. Union, subtraction, intersection are just min, max, and negation of real numbers.

Five Mathematical Surfaces

The sine editor deserves special attention. Each shape is a different answer to the question: what happens when you sweep a curve through a space that has unusual connectivity?

Torus Knot
Super­ellipsoid
Sphere Harmonic
Klein Bottle

The Möbius strip is the simplest: one twist makes a one-sided surface. The Klein bottle is the most complex: a surface that passes through itself because three dimensions are not enough to embed it without self-intersection. Between them, the torus knot shows how a curve can be knotted on a torus, the superellipsoid shows how exponents control curvature between circle and square, and the sphere harmonic shows how sinusoidal perturbation creates organic ridges on a sphere.

All five are controlled by the same sliders: major radius, minor radius, twist count, segments, exponent. The slider does not care what surface it controls. It just maps a number to a visual outcome. The learning happens in the gap between the number and the shape.

A slider is a hypothesis. The mesh is the experiment. The eye is the instrument.
