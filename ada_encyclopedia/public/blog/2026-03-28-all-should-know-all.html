All Should Know All

We built three separate systems for Ada Research: interactive web editors, VR infoboards, and a writing tool. Today we wired them into one knowledge system where every part knows about every other part. The key insight was LOD — Level of Detail — applied not to geometry, but to understanding.

The question wasn't "how do we merge the databases." It was "what does each primitive actually teach about the world?" The ontology came first. The integration followed.

The Ontology: Not How, But What

We asked a simple question about each primitive: what lens does it open?

Not "how does a line work" but "what does a line reveal about reality?" The answer surprised us: a line is both the thing measured AND the instrument of measurement. Length and ruler are the same object. You cannot separate the measured from the measurement.

Every primitive opened a similar door:

These aren't metaphors. The dot product literally measures alignment between two directions. The random walk literally returns home in 2D but escapes in 3D. The math is the ontology.

The Line Insight

The deepest surprise came from the simplest primitive. A line connects two points — everyone knows that. But a line is also how we measure the distance between those points. The ruler is made of the thing it measures. This is not a philosophical curiosity. It's the reason non-Euclidean geometry exists: when the ruler curves, measurement itself changes.

The line is both length and measure. The instrument is part of the system it measures. You cannot step outside.

LOD: Level of Detail for Understanding

In 3D graphics, LOD means showing a simpler mesh when the object is far away. We applied the same idea to knowledge:

LOD 0 — Glance

Point → Location → "What system am I in?"

One line. Enough to orient across 14 primitives in a single table. No file reads — served from the index alone.

LOD 1 — Card

+ "A point doesn't exist without a space to exist in."

One sentence that captures the deepest takeaway. Plus QFEP connection, tags, related primitives. Enough to decide what to work on.

LOD 2 — Discussion

+ Euclidean, hyperbolic, spherical, spacetime, topology…

The full ontological text. Open questions. QFEP analysis. Enough to think through the primitive deeply.

LOD 3 — Deep

+ Connections to Line, Coordinate System, Grid…

How this primitive links to others. The raw markdown. Cross-references. The full web of relationships.

The API serves any level: GET /api/ontology?lod=0 returns 14 one-liners. GET /api/ontology?primitive=line&lod=3 returns everything about lines. The same data, four resolutions, zero redundancy.

The ontology MDs mirror this exactly. Same LOD pattern, different scope. The ontology asks "what does a line teach?" The map MDs ask "what does this specific room about lines teach?"

What Changes

For writing

When you open a map in Ada Writer, the ontology is there. Writing about Point_One? The sidebar shows: Lens: Location. "What system am I in?" Insight: A point doesn't exist without a space to exist in. The writing becomes grounded in the question the primitive asks.

For building

When building a web editor, the ontology tells you what to foreground. The Wave editor doesn't just show sine curves — it asks "what's the hidden spectrum?" The tangent mode shows discontinuity not as a bug but as a boundary condition. The Fourier mode shows decomposition as analysis of identity.

For AI

The LOD system is a context window optimizer. At LOD 0, an AI agent can orient across 14 primitives in 14 lines. At LOD 3, it gets the full discussion, open questions, and connections. The right depth for the right moment. No wasted tokens.

For VR

The Filter Screen projects 3D into 2D. The Science Screen renders grid data as pixels. Both are ontology in action — the filter screen asks "what is lost in projection?" and the science screen asks "how do pixels represent reality?" Standing between them in VR, you experience the gap between 2D understanding and 3D embodiment. That gap is the research.

What We Learned

The ontology came from asking the right question. Not "how does a triangle work" but "why does winding order determine visibility?" Not "what is a random walk" but "why does a drunk man in 2D always return home while a drunk bird in 3D escapes?"

The LOD system came from recognizing that the same question needs different depths at different moments. Glancing across 14 primitives needs one line each. Thinking deeply about one needs the full discussion with open questions.

The integration came from refusing to let knowledge live in silos. The writer should know the ontology. The ontology should know the maps. The web editor should know the question it's asking. All should know all.

The primitive is not the visualization. The primitive is the question.

Think flat. Build deep. The loop never ends.
