LOD as Epistemology

How Fractal Context Loading Changes AI-Assisted Research

We built a Level of Detail system for loading AI context. What started as an engineering optimization revealed something deeper: the structure of how you load information determines the structure of what you can think. This essay argues that fractal context loading is not a technique but an epistemological position — one with implications for how AI-assisted research works at every scale.

I. The Problem: Context as Bottleneck

Every AI session begins with the same dilemma. The project is vast. The context window is finite. Something has to give.

Ada Research, the project that prompted this investigation, contains 752 artifacts, 656 maps, 42 sequences, 20 interactive primitives, and a curriculum spine that weaves through all of them. No context window on earth can hold this simultaneously. So what do you do?

752

Artifacts

Interactable 3D objects, each with code, scene, and registry entry

656

Maps

3-layer grid levels with structure, utilities, and interactables

42

Sequences

Curriculum arcs from sorting to cryptography to queer theory

The existing approaches each sacrifice something essential:

The Dump: Load Everything

Concatenate every file into the prompt. This works for small projects. For a project of this scale, it overflows the window and — worse — buries the signal in noise. The AI sees everything and understands nothing. Like reading an entire encyclopedia to answer one question, the abundance of information becomes its own form of ignorance.

The Summary: Compress to Abstraction

Write a summary document. CLAUDE.md, README, onboarding guides. These are necessary but insufficient. They capture the shape of the project but not its texture. An AI that reads only summaries can talk about the project but cannot work in it. It knows that maps have three layers but not what any specific map contains. The abstraction purchases breadth at the cost of depth.

The Fragment: RAG and Embeddings

Retrieve relevant chunks via embedding similarity. This finds pieces but misses structure. If you search for "meander," you get paragraphs about meanders from various files. What you do not get is the context that makes those paragraphs meaningful: that the meander is in the Pompeii sequence, which teaches tessellation, which connects to QFEP through the λ parameter. The fragment is accurate but orphaned.

None of these approaches preserve the hierarchical structure of understanding. You do not understand a project by reading random fragments. You understand it by zooming in from overview to detail along a path of relevance.

The problem is not information retrieval. The problem is information architecture. What we need is not a better search algorithm but a better model of how understanding actually works — one that respects the fact that knowledge has scale, that detail is nested inside context, and that the path from ignorance to comprehension is not a flat list but a tree.

II. Fractal Context: The Metaphor Made Literal

Benoit Mandelbrot showed that many natural structures are self-similar: the coastline looks the same whether measured in kilometers or meters. The branching of a tree recapitulates at every scale, from trunk to twig. A cloud has the same statistical texture whether you photograph it from a plane or a rooftop. He called these structures fractals.

The key insight of fractal geometry is that you never render the whole set. The Mandelbrot set has infinite detail at every point, but your screen has finite pixels. You render exactly the region you are looking at, at exactly the resolution your screen supports. Zoom in, and more detail appears — not because it was generated, but because it was always there.

art1 art2 art3 art4 art5 art6 art7 art8 art9 art10 art11 art12

fn() fn() fn() fn() fn() fn() fn() fn() fn() fn() fn() fn() fn()

Each level: same structure (name, description, children). Different scale. Self-similar.

The LOD tree applies this principle to knowledge. Five levels, each self-similar:

LOD 0 — Project

One sentence. The whole project in a breath.

"Ada Research: a Godot 4 VR/desktop project teaching algorithms through navigable maps and interactable artifacts, organized into 42 curriculum sequences."

LOD 1 — Sequence

One paragraph per sequence. Enough to choose a direction.

The Pompeii sequence: 23 maps exploring tessellation, symmetry, and Roman mosaic craft. Teaches wallpaper groups through physical reconstruction of floor patterns from the MANN museum.

LOD 2 — Map

One page per map. Enough to work.

Grid dimensions, layer contents, artifact placements, connected maps, pathfinding validation status. Everything needed to edit or extend a single map.

LOD 3 — Artifact

One file per artifact. Enough to modify.

The GDScript source, the scene tree, the registry entry, the grid config interface. The complete implementation of a single interactable object.

LOD 4 — Function

One block. Enough to debug.

A specific function body, a shader uniform, a signal connection. The atomic unit of code that either works or does not.

Each level contains the same structural elements: a name, a description, a list of children. The tree is literally self-similar. This is not a metaphor for fractal geometry. It is fractal geometry, applied to the organization of knowledge rather than the organization of space.

The LOD tree is a Mandelbrot set for project understanding. Infinite detail at every point. You render only the region you need, at exactly the resolution your context window supports.

III. Slow Thinking vs. Fast Thinking

Daniel Kahneman distinguished two modes of cognition. System 1 is fast, automatic, pattern-matching. System 2 is slow, deliberate, effortful. Most AI usage today is System 1: load a big context, let the attention mechanisms sort it out, produce output. This works for simple tasks — summarize this document, fix this bug, answer this question. It fails for deep research.

Deep research requires System 2: formulating questions, choosing where to look, evaluating what you found, reformulating, looking again. Each step is a decision about attention. The LOD tree makes these decisions explicit.

Fast Thinking (System 1)

"Here is 100K tokens of context about the project. What should I do next?"

The AI pattern-matches against everything at once. Output is broad, shallow, often accurate but never deep. It sees the forest because you showed it the forest.

Slow Thinking (System 2)

"I am at LOD 1. The meander sequence has 4 maps. Which one is relevant to my question? Let me drill to LOD 2."

The AI navigates the tree deliberately. Each level is a decision point. Output is focused, deep, reasoned. It finds the right tree because it chose the right path through the forest.

The critical difference is not intelligence but process. System 1 thinking in AI produces outputs that feel intelligent — they use the right vocabulary, reference the right concepts, have the right shape. But they lack the depth that comes from having actually traced a problem to its roots. System 2 thinking, enabled by the LOD tree, produces outputs that are intelligent — because the AI has done the cognitive work of deciding what matters at each level before proceeding to the next.

Consider a concrete example. A session needs to fix the meander tile pattern — the border that runs around Pompeii floor mosaics. With flat context loading (System 1), the AI receives everything about every mosaic and produces a plausible-sounding solution. With LOD navigation (System 2):

# Step 1: LOD 0 — Where am I?
query: "meander"
→ Found in: Pompeii sequence (LOD 1), 3 maps, 2 artifacts

# Step 2: LOD 1 — What is the Pompeii sequence about?
load: sequences/pompeii.json (summary level)
→ Tessellation teaching arc. Meander = border motif. Known issue: tile constraints.

# Step 3: LOD 2 — Which map has the problem?
load: maps/Pompeii_Meander_Lab/map_data.json
→ 8x8 grid, 3 meander artifacts placed, pathfinding valid.

# Step 4: LOD 3 — What does the artifact actually do?
load: artifacts/tile_meander_floor.gd
→ Procedural mesh. 3-tile solution. The constraint is in _generate_border().

# Step 5: LOD 4 — The specific function.
read: _generate_border() lines 142-198
→ Found: tile rotation logic assumes 90-degree symmetry. Meander is not 90-symmetric.

Five steps. Each one a deliberate narrowing of attention. The AI did not find the bug by seeing everything at once. It found the bug by knowing where to look, which required knowing what to ignore at each level. This is Kahneman's slow thinking, scaffolded by the LOD tree.

System 1 sees everything and understands nothing. System 2 sees one thing at a time and understands each. The LOD tree is a System 2 scaffold for artificial intelligence.

IV. Progressive Disclosure as Research Method

In user interface design, progressive disclosure is the principle that you show users only what they need at each stage, revealing complexity on demand. It is why good software does not present every option on the first screen. The LOD tree applies progressive disclosure not to interfaces but to research itself.

A research session unfolds in phases, and each phase requires a different resolution of understanding:

Phase 1: Orientation

"What is this project? What are we working on today?"

LOD 0-1. The session reads the project summary and sequence list. It needs breadth, not depth. It needs to know that 42 sequences exist and what they are about, not what any specific map contains.

Phase 2: Selection

"Which sequence or map is relevant to the current task?"

LOD 1-2. The session runs a query, receives a filtered subtree, reads sequence-level summaries. It makes an informed choice about where to focus. The choice is logged.

Phase 3: Investigation

"What exactly is happening in this map or artifact?"

LOD 2-3. The session loads specific files, reads code, examines configurations. It has enough context to form hypotheses and test them.

Phase 4: Modification

"What needs to change, and how?"

LOD 3-4. The session operates on specific functions, specific parameters, specific lines. It makes changes with full understanding of local context and structural context.

Phase 5: Contribution

"What did I learn that the next session should know?"

LOD 0-4. The session writes discoveries back to the tree at the appropriate level. A discovery about the project goes to LOD 0. A discovery about a specific function goes to LOD 4. The tree grows.

This is a hermeneutic circle applied to AI context management. The concept, from Schleiermacher and Gadamer, holds that understanding moves in circles: you understand the parts through the whole, and the whole through the parts. You read a sentence and it changes your understanding of the paragraph; your understanding of the paragraph changes how you read the sentence.

The LOD tree operationalizes this. Each zoom-in refines understanding of the focused region. Each zoom-out revises understanding of the broader structure in light of what was found. The circle is not vicious but productive: each pass through the levels deepens comprehension.

Progressive disclosure is not just a UI pattern. It is a research method. Show only what is needed at each phase. Reveal complexity on demand. Let the researcher's questions, not the data's volume, drive what becomes visible.

V. The Session as Research Unit

An individual AI session is finite. It has a context window, a beginning, and an end. But research is not finite. The project continues across sessions, across days, across collaborators. The fundamental challenge of AI-assisted research is bridging this gap: how does ephemeral cognition contribute to persistent knowledge?

The LOD system offers three components that, together, form a persistent epistemological infrastructure:

TREE

Accumulated Structure

The LOD tree encodes the project's hierarchical organization. It is the skeleton of understanding — stable, regenerable, shared across all sessions.

DISCOVERIES

Session Contributions

Each session writes what it learned to LOD_DISCOVERIES.json, tagged with LOD level and context. These are the flesh that grows on the skeleton.

QUERY

Retrieval Mechanism

The LOD query finds relevant subtrees by keyword, returning context at the right resolution. This is how sessions access what previous sessions learned.

This is Edwin Hutchins' distributed cognition made operational. Hutchins argued, studying navigation teams on naval vessels, that cognition is not confined to individual minds but distributed across people, tools, and representations. The navigation team "thinks" through the coordinated use of charts, instruments, and communication protocols. No single team member holds the complete picture. The knowledge lives in the system.

The LOD infrastructure distributes cognition across AI sessions in exactly this way. No single session holds the complete understanding of the project. But the system — tree plus discoveries plus query — does. Each session is a team member: it arrives, orients itself using the tree, does its work using the query, records its findings in the discoveries, and departs. The next session inherits everything.

The implications are significant. If knowledge lives in the system rather than in any single session, then:

Session failure is not knowledge failure. A session that crashes after making a discovery has still contributed, as long as the discovery was written. The tree persists.

Session specialization becomes possible. One session can focus on code, another on curriculum design, another on art history. Each loads the LOD subtree relevant to its task. They do not need to understand each other's domains — only to write discoveries at the right level.

Knowledge compounds. The hundredth session on a project has access to ninety-nine sessions' worth of discoveries, organized by level and topic. This is not merely accumulated data. It is accumulated understanding, structured in a way that makes it navigable.

The knowledge lives in the system, not in any single session. This is distributed cognition — Hutchins' insight about naval navigation teams, applied to AI research across time.

VI. What This Means for Ada Research Specifically

There is a recursive elegance in the fact that Ada Research — a project about how patterns encode knowledge — has built a system that encodes knowledge as a pattern. The LOD tree mirrors the project's own concerns at every level.

The Grid is an LOD Structure

Ada's map system uses a 3-layer grid: structure (walls, floors, heights), utilities (spawns, teleporters, labels), and interactables (artifacts). Zoom in and you see individual cells with specific contents. Zoom out and you see the pattern — the flow of the map, the placement strategy, the teaching intention. The grid is an LOD structure, discretizing continuous space at a chosen resolution. The LOD tree does the same thing to continuous knowledge.

The Meander is an LOD Problem

We spent 14 iterations trying to tile a Greek key meander border. The fundamental difficulty: a meander looks continuous at a distance but is made of discrete stones up close. The pattern exists at the macro level; the constraints exist at the micro level. Solving it required constantly moving between scales — zooming in to check tile alignment, zooming out to verify visual continuity. This is LOD navigation applied to craft, and it is precisely the cognitive motion the LOD tree supports for research.

QFEP's λ Parameter

The Queer Failure as Epistemological Praxis framework includes a λ parameter that measures the information lost between levels of abstraction. When you summarize a 200-line GDScript file as "procedural floor generator," what is lost? The λ captures this loss. The LOD tree makes λ measurable: the difference between LOD 3 (full file) and LOD 2 (one-paragraph summary) is exactly the information that was compressed away. QFEP asks: what truths are only visible at the level that was discarded?

The Science Screen as LOD Device

The Science Screen artifact places a 2D interactive editor inside a 3D VR environment. It is, literally, a device for switching between levels of representation: the 3D world is one LOD level (experiential, spatial, embodied); the 2D screen is another (analytical, flat, symbolic). The student moves between them. The LOD tree is the Science Screen of the research process — a device for switching between levels of understanding.

The project that studies how patterns encode knowledge has now built a system that encodes knowledge as a pattern. The research methodology has become recursive — studying itself through its own framework.

VII. The Meander: LOD in Action

The meander investigation provides a concrete case study of LOD-structured research across multiple sessions. Fourteen iterations over several days, each session inheriting context from the previous one.

# Session 1: "What is a meander?" (LOD 0-1)
Discovery: Greek key border pattern. Used in Pompeii floors.
             Infinite repeat. Looks simple. Is not.

# Session 3: "Why won't it tile?" (LOD 2-3)
Discovery: Meander has 4-fold rotational structure but tiles
             need 2-fold reflection. Conflict at corners.

# Session 7: "Can we use 3 tiles instead of 1?" (LOD 3-4)
Discovery: Straight + corner + T-junction. Three tiles compose
             the full meander. Constraint: adjacency rules.

# Session 11: "The 3-tile solution works." (LOD 4, writing back to LOD 2)
Discovery: tile_meander_floor.gd implements procedural border.
             Key insight: "tiles repeat, mosaics don't."

# Session 14: "What does this mean for the project?" (LOD 1-0)
Discovery: The meander is the project in miniature.
             Pattern at macro scale, constraint at micro scale.
             The LOD tree itself is a meander — continuous at
             a distance, discrete up close.

Each session loaded exactly the LOD levels it needed. Early sessions worked at LOD 0-1, establishing the domain. Middle sessions drilled to LOD 3-4, solving the technical problem. Late sessions zoomed back out to LOD 0-1, synthesizing meaning. The hermeneutic circle, completed across fourteen sessions, with the LOD tree as the persistent medium of understanding.

Without the LOD system, each session would have started from scratch: re-reading the same files, re-discovering the same constraints, re-learning the same context. With the LOD system, each session started where the previous one ended — not because it loaded the same context, but because it loaded the right context at the right level.

VIII. Optimization: What Could Be Better

The current LOD system is a first implementation. It works, but it has clear limitations that point toward future development.

1. Active LOD

The tree is currently static — regenerated manually by running a script. It should update in real-time as files change. When an artifact is modified, its LOD 3 node should automatically refresh. When a new map is created, a new LOD 2 node should appear. The tree should be a living document, not a periodic snapshot.

2. Relevance Scoring

The current query uses fuzzy string matching to find nodes. This finds matches but does not rank them. A query for "meander" returns every node that mentions meanders, with no distinction between a map dedicated to meanders and a map that mentions them in passing. Future versions should weight by recency, edit frequency, discovery count, and structural centrality.

3. Cross-References

The tree is hierarchical, but knowledge is networked. "Meander" connects to "self-avoiding walk" (combinatorics), "braid group" (topology), "QFEP" (methodology), and "Pompeii" (art history). These lateral connections are invisible in a tree structure. The LOD system needs a graph layer — not replacing the tree but augmenting it with edges between related nodes across branches.

4. Embedding Integration

Each LOD node could carry a vector embedding of its content, enabling semantic similarity search alongside structural navigation. When the tree search fails (the user's query does not match any node names), the embedding layer would find semantically related nodes. The tree provides structure; embeddings provide semantics. Together they cover both axes of retrieval.

5. Attention Budgeting

Given a context window of N tokens, what is the optimal LOD path that maximizes relevance within the budget? This is a knapsack-like optimization problem: each node has a cost (token count) and a value (relevance score). An attention budgeting algorithm would automatically select the deepest, most relevant path through the tree that fits within the available context. The AI would always use its full context window, but never waste it.

6. Multi-Session Memory Compression

LOD_DISCOVERIES.json grows linearly with sessions. After a hundred sessions, it contains hundreds of entries, many redundant or superseded. It needs periodic compression: merge similar discoveries, promote recurring insights into the tree itself, archive resolved investigations. The discoveries file should be a living research journal that self-organizes over time.

Each limitation is also a research question. The LOD system is not finished. It is a framework for understanding how to build the next version of itself — which is, perhaps, the most fractal property of all.

IX. The Deeper Question

If an AI can only think about what it can see, and what it can see is determined by how its context is structured, then the structure of context is the structure of thought.

This is not a philosophical abstraction. It is a design constraint with measurable consequences. Load context flatly, and the AI thinks flatly. Load context hierarchically, and the AI thinks hierarchically. Load context fractally, and the AI thinks fractally — which means it can move between scales of understanding fluidly, attending to both the forest and the individual trees, holding the macro pattern and the micro constraint in productive tension.

This is exactly what deep research requires. The historian who studies a Pompeii mosaic must see both the individual tessera (stone, color, placement) and the overall composition (mythological scene, room function, patron status). The mathematician who studies a tiling must see both the local adjacency rule and the global symmetry group. The programmer who debugs a rendering artifact must see both the shader uniform and the scene graph. In every case, understanding requires the ability to move between levels — and the LOD tree is the mechanism that enables this movement in AI-assisted research.

There is a deeper parallel here, one that connects to Ada Research's core concerns. In the Pompeii wall painting essay, we argued that the grid is a reading protocol — a structure that organizes the viewer's attention, directing the eye through a composition in a specific order. The LOD tree is a thinking protocol. It organizes the AI's attention, directing cognition through a knowledge base in a specific order. Both are structures of attention. Both make the invisible visible. Both are ornament functioning as infrastructure.

Mandelbrot's fractals revealed that the boundary between simple and complex is itself complex — that coastlines are neither one-dimensional lines nor two-dimensional surfaces but something in between. The LOD tree reveals something analogous about knowledge: understanding is neither a single state (you know it or you do not) nor a continuous quantity (you know 47% of it) but a structured traversal — a path through levels of resolution, where each level is complete in itself yet part of a larger whole.

Kahneman showed us that thinking has at least two speeds. Hutchins showed us that cognition can be distributed across systems. Mandelbrot showed us that structure recurs at every scale. The LOD tree is where these three insights converge: a distributed (Hutchins) system for slow thinking (Kahneman) organized fractally (Mandelbrot) to enable deep research across the boundaries of individual AI sessions.

The tree is not a map of the project. The tree is a theory of how to understand it. And that theory, like the project it describes, is fractal — self-similar at every scale, infinitely detailed, never complete.
