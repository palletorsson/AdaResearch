The Geometry Spec

Ada Research has 1,700 artifacts. Each one is a handwritten GDScript file that builds geometry from scratch — parametric surfaces, L-system line networks, CSG boolean tunnels, pixel-computed textures, instanced particle swarms. Every one of them teaches an algorithm through embodied experience in VR.

But the build instructions live inside Godot-specific code. If you wanted to rebuild a Möbius strip in another engine, you'd need to read 200 lines of GDScript and reverse-engineer the parametric equations, the shader properties, the mesh topology. Multiply by 1,700.

What if every artifact carried its own build recipe — engine-agnostic, machine-readable, and complete enough for any system to reconstruct it?

The Portability Stack

Ada Research already had most of the layers. The curriculum, maps, and sequences are pure JSON. Every artifact has an @identity block with a desire field — what it wants to be. The registry carries metadata, tags, and placement rules. The only missing piece was the technical recipe.

@identity.desire What it wants to be exists
@identity.truth What it proves exists
README.md Human explanation (92% coverage) exists
registry.json Metadata, placement, sequences exists
geometry_spec Technical build recipe new

With this layer in place, any engine — or any AI — gets both the soul and the skeleton.

What the Spec Contains

Each geometry_spec is a JSON object inside the existing registry entry. No new files, no new schemas, no migration. The Godot registry loader reads all fields generically, so the entire codebase continued working the moment we wrote the field.

10 Mesh Types

Every artifact in the project falls into one of ten geometry categories. This taxonomy emerged from reading the actual code, not from theory.

The largest category — composed_primitives — is artifacts built from boxes, spheres, and cylinders arranged in space. These are the easiest to port. parametric_surface artifacts carry the most mathematical complexity: they define geometry through equations, which means the equations themselves become the portable specification.

Engine Portability

The geometry spec was designed with a specific question in mind: what would it take to rebuild Ada Research in a different engine?

s&box

C# runtime. Grid system maps directly. Parametric surfaces via mesh API. CSG available natively.

Unreal

Procedural Mesh Component covers parametric + line types. Niagara for particles. Blueprint for composition.

AI Reconstruction

Feed mesh_type + construction + material to an LLM. It generates the target engine code. Desire provides intent.

The JSON data layer — sequences, maps, artifact placement — was already engine-agnostic. Now the geometry layer is too. What remains engine-specific is the VR interaction pattern (grab, trigger, slider) and the runtime managers (death, ecology, grid system). Those are smaller problems.

The Extraction Process

We built a Python tool that reads every artifact's GDScript source and infers the geometry spec through heuristic scoring. The same pattern the project already uses for artifact type classification and metadata enrichment.

python tools/extract_geometry_spec.py                     # dry-run all
python tools/extract_geometry_spec.py --registry parametric  # one registry
python tools/extract_geometry_spec.py --artifact mobius_strip # one artifact
python tools/extract_geometry_spec.py --save                 # write to JSONs

The tool detects mesh construction patterns (SurfaceTool for parametric, CSG nodes for booleans, MultiMesh for particles), infers topology from cull mode and surface type, identifies material and shading from StandardMaterial3D vs ShaderMaterial, and estimates vertex counts from grid dimensions.

1,508 artifacts were enriched in a single run. 202 were skipped because they had no script file (scene-only or external). The remaining ~200 in the total 1,713 count are utility entries or have registry keys but no corresponding scene.

Desire + Recipe

The most interesting consequence is how the geometry spec interacts with the existing @identity system. Every artifact already declares what it wants to be:

Barnsley Fern desire: "Reveal how four simple affine transforms, chosen by weighted randomness, conspire to grow an unmistakably organic shape"

Barnsley Fern geometry_spec: texture_plane, pixel_computation, generated_texture

The desire is the soul. The geometry spec is the skeleton. Together they give any reconstruction system — human, engine, or AI — both the why and the how. The desire tells you what experience to create. The spec tells you how to build the geometry that creates it.

An artifact that knows what it wants to be AND how it's built can be reborn in any engine that's willing to listen.

What This Means

Ada Research is no longer locked to Godot. The curriculum was always engine-agnostic (JSON sequences, JSON maps, JSON registries). The pedagogical intent was always engine-agnostic (@identity blocks in code comments). Now the geometry is engine-agnostic too.

If s&box ships with a good mesh API, the spec tells you exactly what to build. If an AI model gets good enough at code generation, you hand it the desire and the spec and it writes the implementation. If Godot 5 breaks everything, the spec survives because it's just data in a JSON file.

The project carries its own blueprint. Not as documentation that rots, but as structured data that travels with the artifacts themselves.
