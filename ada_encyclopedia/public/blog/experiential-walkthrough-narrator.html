Experiential Walk-Through Narrator

March 16, 2026

The batch narration system we built earlier told us whether a map worked — which artifacts were reachable, where dead ends lived, whether the teleporter was accessible. Structural facts. But it couldn't tell us what it felt like to walk through a map. Where do you look when you arrive? What catches your eye first? How does the space unfold as you move through it?

Today we added an experiential layer: the narrator now walks every map the way a player would, recording what it sees at each stop.

The Problem with BFS

BFS (breadth-first search) radiates outward from spawn like a flood. It visits every reachable tile and computes shortest distances. That's useful for reachability analysis, but it produces a flat view of the map — everything gets a distance number, and the order of exploration is geometric, not experiential.

A player doesn't explore like a flood. They look around, spot the nearest interesting thing, walk to it, look around again. The experience is sequential and perceptual — shaped by what's visible from where you're standing, not by graph distances.

Nearest-Neighbor Touring

We already had a system that understood this: CameraTourManager.gd, the 992-line camera tour controller that generates smooth flythrough paths for map previews. Its core algorithm is a greedy nearest-neighbor walk — from your current position, always go to the closest unvisited artifact.

We adapted its logic for the text narrator. The walkthrough algorithm:

1 Start at spawn. Record facing direction (toward nearest artifact).
2 Scan: which artifacts are visible from here? List them with distance and direction.
3 Walk to the nearest unvisited artifact (Manhattan distance, skip unreachable).
4 At the new position, scan again. Record what's visible from this vantage point.
5 Repeat until all reachable artifacts visited, then walk to teleporter.

The key difference from BFS: this produces a sequence of stops, each with a perspective. You know what the player sees at each moment, what draws them forward, and where the journey has gaps where nothing is visible.

This tells you something the structural analysis never could: the Boids map has good spatial rhythm. Four artifacts arranged in a square, each visible from the others, with a natural circuit that loops you through all of them before the exit. You can almost feel the map working.

Compare that to a walkthrough with long stretches of nothing visible — 15 steps south into emptiness, then an artifact that can't see any of its neighbors. That map needs attention, and the walkthrough makes it obvious in a way that a BFS distance table doesn't.

Others tell a different story: Forces has 110 issues across 9 maps, Wavefunctions has 100 across 12. These are real design debts, now visible.

The Text Board Bug

While testing the narrator we noticed the desktop comment panel — the text board from DesktopMapSwitcherOverlay that players use to type feedback during VR sessions — was staying visible during batch narration. It shouldn't be.

The root cause was simple: the _set_overlay_visible() method toggled the main panel, camera bar, and rating panel, but forgot the comment panel. One line fix:

if _comment_panel:
    _comment_panel.visible = is_visible

The batch runner now hides the full overlay before narrating, so screenshots captured during narration show clean map views without UI clutter.

Each walk stop rendered as a card with spawn position, facing direction, visible artifacts and distances, cumulative step count. Color-coded: green for spawn, blue for artifacts, purple for teleporter. Tabs switch between the experiential walkthrough, spatial analysis grid, issues list, and artifact reachability table.

The viewer loads the narration report JSON, lets you browse by sequence and map, and shows the walkthrough as styled stop cards. Each stop shows where you are, what direction you walked from, and what you can see from that vantage point. Issue badges (red for critical, orange for high, green for clean) surface problems at a glance.

Run controls let you trigger new narration runs directly from the encyclopedia — narrate a single sequence or the full spine, with live progress tracking via API polling.

The API Layer

Two new API routes power the viewer and open narration data to other tools:

Trigger Runs

  • POST /api/game/narrate
  • Spawns Godot headless process
  • Returns run ID for progress polling
  • GET /api/game/narrate?id=... for status

Read Results

  • GET /api/game/narration?sequence=...&map=...
  • Serves per-map narration.json
  • Includes walkthrough, spatial, journey data
  • Path traversal protection via sanitization

What Changes

The structural narrator told us this map has 4 artifacts at distances 6, 10, 10, 14. The experiential narrator tells us you arrive facing southeast, the aquarium catches your eye first, then you spot the flocking demo to the east, and after visiting all four you loop back toward the exit. One is a health check. The other is a design review.

With 163 walkthroughs now generated across the full curriculum, we can read the player experience of every map without loading a headset. Maps where the walkthrough shows long blind stretches — 15 steps with nothing visible — are maps where the spatial design needs work. Maps where every stop has two or three visible neighbors are maps where the space guides the player naturally.

The walkthrough doesn't replace playtesting. But it compresses hours of VR time into seconds of reading, and it turns spatial intuition into something you can grep.
