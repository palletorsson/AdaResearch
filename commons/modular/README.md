# The modular class system — a grammar that grows Ada's objects from a point

Every object in this system is a **recipe**: a short JSON expression built from earlier recipes. A
builder turns the recipe into the thing. Two builders read the same recipes — Godot
(`builder.gd`, this folder) and three.js (in the encyclopedia web app) — so a recipe is the source and
a mesh is only what it unfolds into. The gyroid is 423 bytes here and 2.5 MB as a mesh.

Start at `terms.json`. Everything else explains, builds, orders or checks what is written there.

## Where things are

| what | file |
|---|---|
| the recipes (one entry per term: `chapter`, `label`, `from` = parents, `expr` = the idea in words, `build` = the recipe) | `commons/modular/terms.json` |
| the main track (16 steps) and the chapter order | `terms.json` → `track`, `chapters` |
| the operators (recipe → Godot node tree) | `builder.gd`; primitives `mod_mesh.gd`, `mod_body.gd`, `mod_surface.gd`, `mod_label.gd`, `mod_point.gd`, `mod_grabbable.gd`; engines `mod_behaviour.gd`; fields `mod_field.gd` |
| a term as a placeable artifact (token `mod_<term>`) | `composite.tscn` / `composite.gd`; registry `commons/artifacts/registry/modular.json` (generated by `tools/build_modular_registry.py`) |
| the order everything is shown in (authored by Palle) | `commons/data/construction_path.json` (`order`; generated by `tools/construction_path.py`, which keeps an authored order) |
| capacities, the track gate, every artifact hung off its nearest step | `tools/capacity_track.py` → `commons/data/capacity_track.json`; every saved version of the track in `commons/data/capacity_track_history.jsonl` |
| the history of decisions, faults found, numbers measured | `doc/LIVE_UPDATE_BRIDGE.md`, sections 17 onward |

## The grammar

A recipe is one of:

- `{"t": name}` — another term.
- a primitive `{"p": "point" | "mesh" | "collider" | "body" | "grabbable" | "label" | "light" | "prefab", ...}`
  (`mesh` shapes: box, sphere, cylinder, cone, torus, plane, wedge, tetra, pyramid, triangle, octa, icosa, dodecahedron;
  surfaces for `associate`: tape, stripes, red, rubber, metal, urethane, grip, hazard, wood, concrete, cardboard, warhol,
  plastic, paper, glow, rim, pink_rim).
- an operator `{"op": ..., "of": recipe, ...}`:

| op | what it makes |
|---|---|
| `compose` | one thing from several parts |
| `associate` | the same thing with another surface or story (a variation, not a new form) |
| `transform` | placed: `at`, `rot` (degrees), `scale` |
| `times` | n copies laid out: row, stack, ring, polygon, mirror, circle, phyllotaxis |
| `array` | a grid of copies (1d row, 2d, 3d); `palette` + `palette_by` colour a copy by its address; `profile` (+ `rise`) shape it by a function of its index; `inside` keeps only copies whose centre is inside a field (voxels) |
| `assemblage` | placed parts with ids |
| `connect` | ties between parts (rope, rod, spring); joints under physics |
| `engine` | time: physics, trace, hand, sine, sine_field, noise, random (`keep` removes by a draw), logic, tween (a transform played over time), flock (boids) |
| `recurse` | an iterated function system: a thing made of smaller copies of itself |
| `rewrite` | an L-system: a sentence rewritten, then drawn by a turtle |
| `field` | a surface where a function of space crosses zero: signed distances, gyroids, metaballs, noise; union, intersect, subtract, smooth union |
| `sort` | the parts of a thing in a row by a reading (measure) |
| `exhibit` | staging: a label, a lamp, a sensing area |

The full parameter list is the header of `builder.gd`. The three.js twin is
`ada_encyclopedia/src/lib/modular-terms.ts` and `modular-field.ts` (a separate repository).

Example — the Sierpiński triangle:

```json
{"op": "recurse", "of": {"p": "mesh", "shape": "triangle", "size": [1.6]}, "depth": 5,
 "rules": [{"at": [0.462, 0, 0], "scale": 0.5}, {"at": [-0.231, 0, 0.4], "scale": 0.5}, {"at": [-0.231, 0, -0.4], "scale": 0.5}]}
```

## Two orders, both deliberate

- **The main track** (`terms.json` → `track`) is a gate: each step gives the thing ONE new capacity —
  form (point, line, surface, solid, field), body (seen, collides, falls, graspable), many, kinds of
  part, a tie, a drive, a reaction or decision, a measure. 16 steps, from `point` to `metaballs`, no
  holes. `python tools/capacity_track.py` checks it; a change goes through
  `python tools/capacity_track.py --propose=<file> --note=...`, which writes it only if it passes.
- **The lineage** (`construction_path.json` → `order`) is every new form, each built from earlier ones,
  in the order Palle authored: point → line → triangle → tetrahedron → … → the Platonic solids →
  transformation (in time) → arrays → colour → tiling → change → forces → form finding → waves →
  randomness → noise → shaders → logic (cellular automata) → fractals → L-systems → procedural generation →
  soft bodies → isosurfaces → booleans → swarms → graphs → machine learning → the foundations crisis →
  the QFEP laboratory → after the crisis.
  A term written as `associate(N)` is not a node; it is a variation shown around N.

## Checking that a recipe builds

Godot 4.6, run from the repository root:

```bash
godot --headless --path . --xr-mode off --script res://commons/testing/probe_modular.gd   # every term builds
godot --headless --path . --xr-mode off --script res://commons/testing/probe_field.gd     # every field mesh against its field
godot --headless --path . --xr-mode off --script res://commons/testing/probe_logic.gd     # the logic machines' truth tables
python tools/capacity_track.py                                                         # the track gate
```

`commons/testing/export_terms_gltf.gd` exports every term as Godot builds it to `.glb` (not kept in git:
the meshes are regenerated from the recipes).

## What is still missing

Every sequence has nodes now; 23–25 (the foundations crisis, the QFEP laboratory, after the crisis)
have only a few, because they are arguments more than objects. Not every principle in any sequence is
covered yet. `doc/book/course/MODULAR_COVERAGE.md` lists every spine principle the grammar
does not yet cover. Its match is lexical (two shared word stems), so it over-counts: two generic words
can coincide. Read the term a "covered" row names before believing it.
