# Dice replace clocks across a lattice where deterministic rules learn to stutter, skip, and recover under gravitational pull

CA_6 stretched the neighborhood. Cells that once saw eight neighbors now saw sixteen or twenty-four, and the reach changed everything — branching trees, interference patterns, structural persistence at distances the original Moore neighborhood could never support. But every rule in that sequence fired with certainty. Given an input configuration, the output was fixed. The same initial condition produced the same trajectory every time, every run, every machine. CA_7 breaks that guarantee.

The transition function no longer returns a state. It returns a probability distribution over states. The rule might fire. It might not. Run the same seed twice and get two different histories. Determinism softens into statistics.

This is not degradation. This is generalization. Deterministic automata are a special case of stochastic automata — the case where every probability is 0 or 1. Relaxing that constraint opens a space of dynamics that deterministic rules cannot reach. Patterns that survive noise reveal themselves as structural attractors. Patterns that dissolve were artifacts of perfect synchrony. The noise is a filter. What passes through it is real.

## Stochastic Transition Functions

A deterministic transition function maps a neighborhood configuration to a single next state. A stochastic transition function maps the same configuration to a probability distribution over possible next states. The rule does not say "this cell becomes 1." It says "this cell becomes 1 with probability p and remains 0 with probability 1 - p."

```gdscript
@export var fire_probability: float = 0.8
@export var hold_probability: float = 0.2

func stochastic_transition(current_state: int, neighbor_sum: int,
                           threshold: int) -> int:
    if current_state == 0:
        if neighbor_sum >= threshold:
            # Rule says "fire" — but only with probability p
            if randf() < fire_probability:
                return 1
            return 0
        return 0
    else:
        # Active cell: hold with some probability, decay otherwise
        if randf() < hold_probability:
            return current_state
        return maxi(current_state - 1, 0)
```

The `randf()` call is where determinism breaks. Each cell, each generation, draws an independent random number. The rule consults the neighborhood, decides the deterministic answer, then flips a biased coin to decide whether to follow through. At `fire_probability = 1.0`, the rule is deterministic. At `fire_probability = 0.0`, nothing ever fires. Between those extremes lies a continuum of behaviors where the rule's intention is probabilistically enacted.

The independence matters. Each cell flips its own coin. Two cells with identical neighborhoods in the same generation may produce different outcomes. Spatial correlations in the grid arise not from correlated randomness but from the propagation of stochastic events through deterministic neighborhood coupling. The noise is local. The structure that emerges from it is global.

## Rule 30 Under Noise

Rule 30 is Wolfram's canonical chaotic elementary automaton. Its deterministic output from a single active cell is aperiodic, passes statistical randomness tests, and has been used as a pseudorandom number generator. The left side produces a nested triangular structure. The right side produces apparent disorder. The boundary between order and chaos runs through the pattern like a fracture.

```gdscript
const RULE_30: int = 30

func elementary_rule(left: int, center: int, right: int, rule_number: int) -> int:
    var index: int = (left << 2) | (center << 1) | right
    return (rule_number >> index) & 1
```

The rule table is an 8-bit integer. Each three-cell neighborhood encodes a 3-bit index. The output bit at that index determines the next state. Rule 30 in binary is `00011110`: neighborhoods 1, 2, 3, and 4 produce 1; all others produce 0. The encoding is identical to CA_3's elementary rules.

Adding stochasticity to Rule 30 does not make it "more random." It makes it differently random. The deterministic Rule 30 produces pseudorandomness from structure — the chaos is generated by the rule itself. Stochastic Rule 30 injects external randomness on top of the internal chaos. The two sources of disorder interact.

```gdscript
func stochastic_elementary_step(grid: Array[int], width: int,
                                 rule_number: int, noise: float) -> Array[int]:
    var next: Array[int] = []
    next.resize(width)
    for x in range(width):
        var left: int = grid[posmod(x - 1, width)]
        var center: int = grid[x]
        var right: int = grid[posmod(x + 1, width)]
        var deterministic_result: int = elementary_rule(left, center, right, rule_number)
        # Apply noise: flip the result with probability `noise`
        if randf() < noise:
            next[x] = 1 - deterministic_result
        else:
            next[x] = deterministic_result
    return next
```

At `noise = 0`, the output is pure Rule 30. At `noise = 0.5`, every cell is a fair coin flip regardless of the rule — maximum entropy, zero structure. Between those values, Rule 30's characteristic pattern degrades progressively. The nested triangles on the left side dissolve first — they depend on precise correlations across many generations. The disordered right side is more resilient because it was already close to random. Adding noise to noise changes little. Adding noise to structure destroys it.

The degradation is not uniform. Some features of Rule 30 survive moderate noise: the overall leftward drift of the order-chaos boundary, the average density of active cells, the rough triangular silhouette. These are statistical properties — averages over many cells and many generations. They reflect the rule's macroscopic character rather than its microscopic trajectory. Stochasticity strips away the particular and reveals the typical.

## Rule 110 Under Noise

Rule 110 is computationally universal — capable of simulating any Turing machine. Its deterministic evolution from simple initial conditions produces persistent mobile structures (gliders) that interact in complex ways. Universality depends on the reliability of these structures. A glider that loses a cell to noise is no longer a glider.

```gdscript
const RULE_110: int = 110

func test_rule_110_robustness(grid: Array[int], width: int,
                               noise: float, generations: int) -> Dictionary:
    var glider_count: int = 0
    var structure_frames: int = 0
    for gen in range(generations):
        grid = stochastic_elementary_step(grid, width, RULE_110, noise)
        var structures := detect_persistent_structures(grid, width)
        if structures.size() > 0:
            structure_frames += 1
            glider_count += structures.size()
    return {
        "survival_rate": float(structure_frames) / float(generations),
        "mean_gliders": float(glider_count) / float(generations)
    }
```

At zero noise, Rule 110 produces a rich ecology of gliders, backgrounds, and interactions. At low noise (0.01 to 0.05), gliders occasionally misfire — a cell flips, the structure deforms, the glider may repair itself or disintegrate. Self-repairing structures are robust attractors in the rule's dynamics. Structures that cannot tolerate a single flipped cell are fragile — they exist only in the deterministic limit.

At moderate noise (0.05 to 0.15), glider populations decline sharply. The background texture — a repeating pattern that fills space between gliders — corrupts. Without a stable background, gliders have nothing to propagate through. The computational universality of Rule 110 depends on a stable substrate. Noise erodes the substrate before it destroys the computers running on it.

At high noise (above 0.2), Rule 110 becomes indistinguishable from a random process. The rule's structure is overwhelmed. No persistent patterns survive. The automaton has crossed from the edge of chaos into the chaos itself — not the deterministic chaos of Rule 30, but the statistical chaos of thermal noise.

The threshold where universality breaks is not a sharp transition but a crossover. There is no single noise level at which Rule 110 ceases to compute. There is a range over which its computational capacity degrades — fewer gliders, shorter lifetimes, simpler interactions — until the residual structure cannot support information processing. The crossover is the stochastic analog of a phase transition.

## Gravitational Bias

The `rule_30_110_gravity` artifact adds a directional force to the stochastic framework. Gravity does not change the CA rule. It changes the probability landscape. Downward transitions — active cells in upper rows, inactive cells in lower rows — become more likely. Upward propagation becomes less likely. The bias is asymmetric.

```gdscript
@export var gravity_strength: float = 0.3

func gravity_modified_probability(base_probability: float,
                                   row: int, total_rows: int,
                                   direction: String) -> float:
    var height_factor: float = float(total_rows - row) / float(total_rows)
    match direction:
        "downward":
            # Activating cells below is easier
            return clampf(base_probability + gravity_strength * height_factor, 0.0, 1.0)
        "upward":
            # Activating cells above is harder
            return clampf(base_probability - gravity_strength * height_factor, 0.0, 1.0)
        _:
            return base_probability
```

The `height_factor` normalizes the row position to [0, 1], with 1.0 at the top. Gravity increases the firing probability for cells influenced from above and decreases it for cells influenced from below. The effect is strongest at the top of the lattice (where the "gravitational potential" is highest) and weakest at the bottom.

Under gravity, Rule 30's symmetric triangle distorts. The pattern sags. Active cells accumulate toward the bottom of the lattice. The left-side nested structure, which in the deterministic version builds upward and leftward with precise self-similarity, now droops — the upward component fights gravity and loses cells probabilistically. The rightward chaotic region pools at the base.

Rule 110 under gravity loses its horizontal glider traffic. Gliders that move laterally rely on symmetric propagation — equal probability of activation to the left and right of the wavefront. Gravity breaks this symmetry along the vertical axis. Gliders that travel horizontally with any upward component slow and fragment. Gliders with a downward component accelerate and sometimes merge into incoherent cascades. The computational ecology of Rule 110 is disrupted not by random noise but by directional noise — a systematic bias rather than uniform corruption.

## Lattice Gas Automata

Stochastic CA connect directly to fluid dynamics through lattice gas models. A lattice gas automaton populates a grid with particles that carry velocity vectors. At each time step, particles stream along their velocity to adjacent cells, then collide — redistributing velocities according to conservation rules.

```gdscript
enum Direction { E, NE, NW, W, SW, SE }

const VELOCITY: Array[Vector2] = [
    Vector2(1, 0),    # E
    Vector2(0.5, 1),  # NE (hex offset)
    Vector2(-0.5, 1), # NW
    Vector2(-1, 0),   # W
    Vector2(-0.5, -1),# SW
    Vector2(0.5, -1), # SE
]

func lattice_gas_cell() -> Array[bool]:
    # Each cell holds up to 6 particles, one per direction
    return [false, false, false, false, false, false]
```

Each cell on a hexagonal lattice holds up to six particles — one per lattice direction. A particle in direction E streams to the eastern neighbor. A particle in direction NW streams to the northwestern neighbor. Streaming is deterministic. Collision is where stochasticity enters.

```gdscript
func collide(cell: Array[bool]) -> Array[bool]:
    var count: int = 0
    for occupied in cell:
        if occupied:
            count += 1
    if count == 2:
        # Head-on collision: rotate both particles by 60 degrees
        # Choose rotation direction randomly
        if _is_head_on(cell):
            if randf() < 0.5:
                return _rotate_particles(cell, 1)  # Clockwise
            else:
                return _rotate_particles(cell, -1) # Counter-clockwise
    # All other configurations: no collision, pass through
    return cell
```

Two particles traveling in opposite directions collide head-on. The collision must conserve both particle count and total momentum. On a hexagonal lattice, a head-on pair can rotate 60 degrees clockwise or counter-clockwise — both options conserve momentum. The choice between them is random. This single stochastic decision, repeated across millions of cells over thousands of time steps, produces macroscopic fluid behavior.

The connection to physics is precise. In 1986, Frisch, Hasslacher, and Pomeau proved that lattice gas automata on hexagonal grids recover the Navier-Stokes equations in the macroscopic limit. The hexagonal symmetry is essential — it provides the isotropy that square grids lack (as CA_4 established). The stochasticity is essential — it provides the mixing that drives the system toward thermal equilibrium.

Deterministic collision rules produce artifacts. If a head-on collision always rotates clockwise, the fluid develops a systematic rotational bias. The bias accumulates over time and produces spurious vorticity. Random collision resolution eliminates the bias. The macroscopic flow is symmetric because the microscopic stochasticity is unbiased.

## Robustness as a Diagnostic

Running the same rule deterministically and stochastically, side by side, is a diagnostic tool. Features that appear in both runs are robust — they reflect attractors in the rule's dynamics. Features that appear only in the deterministic run are fragile — they depend on the absence of noise.

```gdscript
func robustness_test(rule_number: int, initial: Array[int],
                     noise_levels: Array[float],
                     generations: int) -> Array[Dictionary]:
    var results: Array[Dictionary] = []
    for noise in noise_levels:
        var grid := initial.duplicate()
        var density_history: Array[float] = []
        for gen in range(generations):
            grid = stochastic_elementary_step(grid, grid.size(), rule_number, noise)
            var density: float = 0.0
            for cell in grid:
                density += cell
            density /= grid.size()
            density_history.append(density)
        results.append({
            "noise": noise,
            "mean_density": _array_mean(density_history),
            "density_variance": _array_variance(density_history)
        })
    return results
```

Mean density across noise levels reveals the rule's statistical character. A rule whose mean density is stable across noise levels has a strong density attractor — the rule drives the system toward a particular fill fraction regardless of perturbation. A rule whose density shifts dramatically with small noise is sensitive — its equilibrium is a knife-edge.

Rule 30's mean density is approximately 0.5 and remains near 0.5 under moderate noise. The rule is statistically robust — it produces roughly equal numbers of 0s and 1s regardless of small perturbations. Rule 110's mean density depends on its initial condition and shifts under noise because the persistent structures (gliders, backgrounds) that maintain specific density regions are fragile.

Density variance tells a complementary story. High variance means the population fluctuates widely — the system oscillates or drifts. Low variance means it has settled into a stable regime. Deterministic Rule 110 has low variance once its glider ecology stabilizes. Stochastic Rule 110 has higher variance because glider creation and destruction events become probabilistic, introducing demographic stochasticity into the population dynamics.

## Statistical Mechanics and Macroscopic Law

Stochastic CA embody the central insight of statistical mechanics: macroscopic laws are robust summaries of microscopic randomness. Temperature is the average kinetic energy of randomly moving molecules. Pressure is the average force of randomly colliding particles. Entropy is the logarithm of the number of microscopic configurations compatible with a macroscopic state.

```gdscript
func compute_block_entropy(grid: Array[int], width: int,
                            block_size: int) -> float:
    var block_counts: Dictionary = {}
    var total_blocks: int = 0
    for x in range(0, width - block_size + 1):
        var block: String = ""
        for dx in range(block_size):
            block += str(grid[posmod(x + dx, width)])
        if block in block_counts:
            block_counts[block] += 1
        else:
            block_counts[block] = 1
        total_blocks += 1
    var entropy: float = 0.0
    for count in block_counts.values():
        var p: float = float(count) / float(total_blocks)
        entropy -= p * log(p) / log(2.0)
    return entropy
```

Block entropy measures the information content of consecutive cell blocks. A perfectly ordered row (all 0s) has entropy 0. A perfectly random row has entropy equal to the block size. Deterministic Rule 30 produces high block entropy — its output is nearly maximally disordered despite arising from a simple rule. Adding stochastic noise to Rule 30 pushes the entropy even higher, toward the theoretical maximum.

Rule 110 under deterministic evolution has lower block entropy than Rule 30 — its periodic background and structured gliders reduce the disorder. Under noise, Rule 110's entropy rises as the structures degrade. The entropy trajectory — starting low, rising toward maximum — charts the destruction of computational structure by thermal noise. It is the information-theoretic signature of the transition from computation to heat death.

The lattice gas automaton inverts this relationship. Individual particle trajectories are random. But the macroscopic averages — density, momentum, energy — obey the Navier-Stokes equations. Microscopic entropy is high. Macroscopic behavior is lawful. The stochastic CA demonstrates that order can emerge from noise just as noise can destroy order. The direction depends on the level of description.

## From Perfect Rules to Physical Rules

Six maps of deterministic CA established what rules can do in isolation — the clean, repeatable, analyzable dynamics of cellular automata as mathematical objects. CA_7 introduces the question that bridges toward physical modeling: what happens when rules operate under uncertainty? The answer is not simply "things get messier." Some things get messier. Some things get clearer. The noise strips away contingent detail and exposes the robust skeleton of the dynamics.

The `rule_30_110_gravity` artifact stages this confrontation. Rule 30 and Rule 110, two of the most studied elementary automata, run under gravitational bias that warps their evolution asymmetrically. The learner sees deterministic patterns sag, fracture, and reform under probabilistic pressure. The structures that survive are the ones that physics would preserve. The structures that dissolve are the ones that existed only in the mathematical idealization.

CA_8 takes the next step. Where CA_7 kept discrete states and added probabilistic transitions, CA_8 replaces discrete states with continuous values. Cells hold real numbers, not integers. The transition from stochastic-discrete to deterministic-continuous completes the bridge from abstract automata to physical simulation — reaction-diffusion systems, continuous fields, the substrate on which partial differential equations live.
