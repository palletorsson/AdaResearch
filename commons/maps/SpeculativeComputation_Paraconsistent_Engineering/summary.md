# Paraconsistent Engineering — Summary

SpeculativeComputation_Paraconsistent_Engineering is the third map in the Post-Foundations Crisis sequence. It stages paraconsistent logic as an engineering practice rather than a philosophical curiosity. Classical logic collapses under contradiction — once a system proves both P and not-P, it proves everything. Paraconsistent systems do not.

A large spherical rig sits at the centre of the room, modelled on Pavel Florensky's sphere as a pedagogical ornament. Inside the sphere, a small database holds a set of statements, some of which contradict each other. The learner can query the database, and a live panel reads out which statements are true, which are false, which are both, and which are neither. The classical inference engine crashes under the contradictions; the paraconsistent engine continues to return useful answers on the non-conflicting parts of the knowledge base.

A second station extends the same mechanism to a tiny production pipeline. Incoming data is inconsistent in realistic ways: one sensor reports a value, another reports the opposite. The paraconsistent stage catches both, annotates the conflict, and passes the surrounding non-contradictory data downstream without loss. The stage does not resolve the contradiction; it contains it.

A wall panel names the stakes. Classical systems must be kept pristine; small contradictions destroy them. Paraconsistent systems are built for the messy world. Within the sequence, this map makes contradiction load-bearing rather than fatal.
